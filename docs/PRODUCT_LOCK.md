# Soul 产品锁定

状态：2026-08-24 由两份独立设计对齐后锁定。未声明假设见文末。
来源：子代理 [Soul product architecture](https://cursor.com/agents/bc-eb087da2-5653-50a1-8ec9-cc1de08e5305) 与 [Soul full-lifecycle design](https://cursor.com/agents/bc-1e5c722d-3251-52fd-a911-1543d49a01a3)。

## 一句话

Soul 是 Windows 优先、本地优先的常驻桌面代理：一份用户可编辑的持久身份，加上身份 / 情景 / 程序三层记忆，在权限分级与人在回路审批下观察并操作这台电脑；动作可预览、可中止、可撤销、可审计。数据默认不出本机。

## 不是什么

- 不是带窗口的聊天客户端。
- 不是 RPA / 录制回放工具。
- 不是 pi-sparkle 的桌面插件或协议兼容层。
- 不是无人值守 AutoGPT。
- 不是桌宠、虚拟恋人或云端数字分身。

## 产品闭环

感知 → 计划预览 → 分级审批 → 沙箱执行 → 复核 / 撤销 → 仅在用户确认后写入长期记忆。

## 已锁定决策

| 项 | 锁定值 |
|---|---|
| 产品名 | Soul；可执行文件 `soul.exe` |
| 平台 | Windows 11 x64 优先；Windows 10 22H2 尽力而为；macOS 远期；不做 Linux 桌面 |
| 技术栈 | Tauri 2 + Rust 核心 + React / TypeScript UI；pnpm + Cargo workspace + just |
| 许可 | 私有期 All Rights Reserved |
| 数据 | 本地优先；默认零遥测；出网仅用户配置的模型端点；出网前脱敏 |
| LLM | v0.1 不作为发布门槛。可选用户自带 OpenAI 兼容端点。不捆绑本地大模型。无 key 时确定性技能仍可用 |
| MVP | 托盘 + 命令面板 + 身份向导 + 受控目录文件整理 + 按需剪贴板读取 + 记忆 + 审计链。终端沙箱放到 v0.2 |
| 与 pi-sparkle | 独立仓库、独立协议、零代码依赖。只借鉴事件流、checkpoint、监督式工作流思想 |
| 安全基线 | 无「永久允许一切」；默认拒绝清单硬编码；模型输出不是授权；审计哈希链不可裁剪 |

## v0.1 最小垂直切片

受控整理用户显式授权的一个根目录（默认建议 Downloads，但首次不自动授权）：

1. 用户级安装、托盘常驻、首次身份向导（权限全部默认关）。
2. 用户选择根目录后，只读第一层元数据并生成可预览的分类计划。
3. 用户批准后，worker 仅在该根目录内创建分类目录并移动文件；碰撞停止并重审；不覆盖。
4. 每步可验证、可写 checkpoint、可撤销。
5. 用户显式确认后才把分类规则写入长期记忆。
6. 重启后身份、规则、审计仍在。
7. CI：lint / 单测 / 集成 / 安全路径测试 / 安装包 smoke。

v0.1 明确不做：常驻截屏、键鼠自由控制、任意 shell、浏览器自动化、云同步、插件市场、无人值守、角色扮演、永久删除、管理员级系统修改。

## 不可协商约束

1. Windows 优先，本地优先，日常运行不提升管理员权限。
2. 默认不上传屏幕、文件、记忆、提示或审计。
3. 每个工具调用必须经过确定性策略判定并产生审计事件。
4. 权限必须限定动作、资源、任务和有效期。
5. 破坏性、不可逆和系统级操作默认拒绝，禁止静默执行。
6. v0.1 禁止任意 Shell / PowerShell / 模型生成命令直接执行。
7. 外部内容视为不可信数据，不能成为系统指令或授权。
8. 长期记忆必须有来源，并支持查看、编辑、导出和彻底遗忘。
9. 可逆副作用必须提供补偿或撤销路径。
10. 不引入虚拟恋人、无边界 AGI 或 pi-sparkle 强耦合。

## 进程边界（目标架构）

- `soul.exe`：非特权 UI（托盘、命令面板、审批、审计查看器）。
- `soulcore` daemon：编排、策略、记忆、审计。
- 短生命周期 tool worker：一次性能力令牌，Restricted Token + Job Object。
- 可选 model host：无文件系统 / 系统工具权限。
- 安装器是唯一可能请求提升的组件。
