## 3. 三个目标如何共同发展

| 方向 | 要实现的价值 | 独立证据 | 不能混用的结论 |
|---|---|---|---|
| 个人数字分身 | 少重复解释；纠正持久有效；能够回顾经历、理解情境并辅助行动 | 作者持续使用记录、任务结果、失败案例 | 作者喜欢不等于适合其他人 |
| 商业产品 | 其他人能够建立自己的 Soul，并愿意持续使用和承担成本 | 上手完成、重复使用、实际付费试验与支持成本 | 使用意愿不等于已付费；试用数量不等于留存 |
| 研究平台 | 明确什么资料、表示和算法改善了什么判断 | 可重复实验、简单基线、时间外测试及不确定性 | 合成测试通过不等于真实世界有效；相关性不等于人格解释 |

规划采用的起步用户假设：愿意主动维护个人资料、重视本地控制、经常需要中文表达与经历回顾的个人用户。先检验这个人群，不同时扩展企业协作、团队管理、医疗或未成年人产品。该假设由 VAL-03 的结果决定保留还是修订。

首个核心场景组合：
1. 设置或纠正语气 → 起草 → 用户修改与采用；验证个性化是否值得维护。
2. 导入允许的数据 → 查看关系与证据 → 纠正；验证“理解来自哪里”是否可用。
3. 记录经历 → 修改 → 遗忘并查看影响；验证长期信任所依赖的数据控制。

三者都使用已存在的 v0.1 路径。记忆自动参与任务、主动建议和跨设备连续性是下一阶段能力。

## 4. 长期架构的演进边界

| 能力边界 | 当前落点 | 后续契约必须回答的问题 |
|---|---|---|
| 数据获取与规范化 | soul-import、soul-collect、soul-schema | 身份归属、事件时间、来源、用途许可、重复导入与增量导入 |
| 事实、记忆与密钥 | soul-store-api、soul-store、soul-memory | 导出迁移、版本兼容、数据损坏恢复、派生索引与缓存的遗忘传播 |
| 个人理解 | soul-profile、soul-graph、算法 crate | 稳定偏好、情境偏好、当前状态如何并存；事实/自述/推测如何区分 |
| 任务上下文 | 现有 ProfileBrief 与 draft；检索部分尚未实现 | 只取获准且相关的材料，附来源与有效期；无法确定时明确缺信息 |
| 行动与结果 | soul-policy、soul-egress、soul-fileplan、soulcore | 哪些动作可预览、需审批、可撤销；如何验证真实结果 |
| 研究 | store 的 research_preview、现有 schema/fixture | 允许字段支持什么问题、哪些数据不能使用、研究结果如何独立验证 |
| 多端 | KeyProvider、ForegroundSource、核心/壳分离 | 身份、配对、设备撤销、密钥恢复、冲突、离线和遗忘传播 |

实现原则：
- 沿用 store 唯一持久化业务数据、policy 签发许可、egress 唯一 HTTP client、soulcore 编排、UI 不复制业务规则的边界。
- 不为长远愿景立即拆微服务或新建大量空 crate。接口扩展与独立测试确有需要时再拆。
- 长期个人模型拟采用“稳定信息 + 情境信息 + 有时间范围的当前状态”，但必须由 MODEL-01 单独定义契约；不改变目前冻结的轴算法。
- 多模型一致性优先验证纠正、来源、许可和遗忘保持；不承诺不同模型逐字回答一致。
- 数据默认继续本地；研究只使用用途获准的 derived/aggregate。原始个人或第三人内容不因为商业与研究目标而自动获得新许可。

### 当前数据可用性判定（RES-01 起点）

- 事件候选逐行读取 `privacy_subject` 与 `privacy.egress.research_export`：只有 owner/self 且 `bucket` 的小时聚合可进入预览；third_party/mixed、deny/hash/allow、缺失或不可读 disposition 均被排除并计数。规划不能把这些排除改写成许可。
- 档案轴是另一条有意存在的派生路径：有 weak/moderate/strong `evidence_band` 的轴被构造成 owner/bucket，只输出 `self_trait_axis` 与 `self_trait_band`；产生轴的问卷/纠正 evidence 仍是 `exportable_to_research:false`，原证据和正文不随预览输出。现有 Session、IPC 与 store 测试都把这条非空轴行当作契约，因此不能误报成偶发泄漏。
- 当前可出现的字段是事件类别、UTC 小时或退化日期桶、聚合计数、轴 ID 与证据档位。`duration_bucket` 虽在 schema/API 中允许，现有构造没有赋值；预览默认只取前 50 行，也没有采集覆盖、设备在线或可用时段字段。
- `ConsentTopic::ResearchPreview` 已定义，但 `Session::research()` 当前只打开 store 并生成预览，没有在该入口读取或授予这项 consent。这里不据此新增缺陷或改变 v0.1 本机预览边界，但不得把枚举存在、合成测试通过或页面可打开解释为“独立研究同意已经记录”。
- 现有数据不能直接支持“预测下一次打开哪个应用”，也不足以严谨区分下一小时“真实无活动”和“未采集/离线”；带时区偏移的时间戳还会退化成日期桶。因此 RES-03 当前结论是数据不足，候选仍限“下一小时是否出现获准采集的活动事件”，不启动建模，不推断心理/人格或他人行为。扩充覆盖字段须经 DATA-01 的数据最小化与许可决议。

### 7.2 首轮个性化试验

- A 为无个性化基线：现有 ProfileBrief::neutral()；B 为现有 ProfileBrief::from_view()；C 为用户手工提供的简要偏好参考。C 用于检验自动整理档案的额外价值，必须固定相同输入/上下文预算，不允许临时给某组追加信息。
- 模板路径和模型路径分别评估。自动回归使用合成 fixture / 本地 mock；真实模型调用只有用户已配置端点且逐次授权时发生。新增对照不进入产品 UI，也不新增 IPC；需要新评测适配代码时作为 Q2 测试目录的任务，不作为产品能力偷偷发布。
- 同一配对固定模型标识、版本（若端点提供）、参数、输入、脱敏策略和预算；记录条件不可控的部分。候选显示顺序按预先固定种子平衡，评估人不知道来源标签。
- 作者：14 个自然日、至少 30 个配对任务。其他自愿用户：5–8 人，每人 10–15 对，只作探索。所有数字均为 ASSUMPTION；预先确定开始与截止时间，不通过无限补样本追求好结果。
- 到期未满样本量，或效果受模型/任务变化混淆，结论为“不确定”；未达到候选阈值则先检查场景、资料维护负担和失败类型，不能直接以更多采集或更大模型掩盖问题。
- v0.1 不自动把实验反馈写成研究导出，不新增遥测。真实反馈由本人手工记录和主动提供；仓库只保存经检查的汇总。未完成任务、拒绝、隐私问题和严重错误全部进入分母或单列说明。
- 对照试验与代理的安全不变量分开：出现越权、原始内容泄漏、纠正被静默覆盖或遗忘后仍可读取时，立即暂停相关试验，先走现有缺陷修复。

### 7.3 预测研究的首个可检验问题

RES-03 拟检验：在有有效采集覆盖的小时内，仅用过去获准的自我聚合事件，预测下一小时是否有活动事件。这是待 DATA-01 确认的候选，不等于已经获得足够数据。

设计输出必须包含：
1. 输入字段与用途许可、覆盖判断、预测时点和 horizon；禁止使用预测时点之后才产生的数据。
2. 按时间先后划分训练/验证/测试；跨用户时同时报告留出用户表现。不能随机打散同一人的相邻时间桶。
3. 众数、最近值、个人周期规则三类简单基线；报告样本分布、balanced accuracy、概率输出时的 Brier score，以及相对最强基线的差值与不确定区间。
4. 训练期拟合的变换不得读取测试集；开发期可反复看验证集，最终测试集只在冻结候选后评估。
5. 未优于简单基线、覆盖不够或发生明显漂移时，保留描述统计，停止产品化。该结论不能被表述成对人格或心理状态的准确理解。
6. 研究模型不得直接覆盖用户锁定的档案、关系或行动权限；进入助手前另设受控集成任务。

## 11. 商业化的默认实验顺序

1. 先验证个人用户是否愿意持续维护自己的资料，以及维护是否换来可感知的帮助。
2. 小范围自愿试用先做三类任务，观察安装成本、解释成本和实际重复使用，不开发账户、支付、增长或遥测系统。
3. 若 VAL-03 出现稳定需求，再比较一次性本地授权与可选持续服务两种交付假设。前者需要验证升级与支持成本；后者需要验证持续价值与服务成本。本文不指定价格。
4. 自带模型端点继续作为已有路径；托管推理、订阅验证、自动更新等项目方出网只能进入明确版本的产品决议。
5. 无明确价值时收窄场景并改进数据维护与任务体验；不通过扩大采集范围来代替价值验证。
6. 正式外部发布前，补齐实际适用的发行、许可、隐私说明、支持与反馈安排；需要外部事实的具体事项届时另行核查。本文不作法规或市场规模结论。

## 12. 主要风险、处理与收敛规则

| 风险 | 观察信号 | 处理 |
|---|---|---|
| 门禁完善但没有日常价值 | 作者也不愿连续使用核心场景 | M1 到期形成负结果，优先解决前三个真实障碍；不无限扩功能 |
| 数据越多却理解越差 | 过期/冲突资料导致更差回复 | MODEL 契约优先解决来源、有效期、检索与纠正；不先扩采集 |
| 自用成功无法推广 | 其他人需要大量解释或不愿导入 | VAL-03 定位冷启动与维护成本；缩小用户/场景并复测 |
| 多端放大密钥/遗忘问题 | 恢复旧备份重生已遗忘数据、离线设备重新传播 | PORT/DATA 独立定义删除与恢复语义；未验证不承诺连续分身 |
| 研究得出虚假增益 | 时间泄漏、只挑成功样本、对照预算不等 | 冻结实验条件和分母；保留失败/不确定；独立分析 |
| 并行写入破坏一致性 | 多 agent 改 Session、schema、lock、同一计划 | 文件单 owner；共享契约先行；冲突回 A0；完整候选复验 |
| 大范围重构拖延成果 | 为未来平台重写所有模块 | 只在当前工作包涉及边界做必要拆分，保持可独立交付 |
| 商业/云成本失控 | 使用增加但费用与支持增长更快 | BIZ/CLOUD 分别核算；设置预算与降级，不损坏本地能力 |
