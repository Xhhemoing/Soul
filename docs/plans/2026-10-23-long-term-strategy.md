## 0.2 每次开工

在 AGENTS.md 原有开工步骤之后：

1. 读 STATUS 与本文 §6，确认当前获准的周期目标、实际候选和任务卡；周期日期不代表工作已启动。
2. 确认任务属于哪个职责区（§8），只改允许的路径；涉及共享语义（授权、事务、来源失效、提议归属、取消结算）时先回报主线程排队。
3. 任务卡写清：**场景 × 层 × 想验证或修复的问题**；纯工程项写优化编号 O?。
4. 实现 → 独立只读评审 → 主线程集成。失败处理与记录沿用 AGENTS 与 `operations/repository-workflow.md`。
5. 收尾：摘要尽量一页，完整证据照常持久保存（§9）；实际创建 PR 时使用四栏模板，文档更新不自动创建 PR。

# 1. 北极星与长期方向

## 1.1 北极星（作者原话，2026-10-22）

> 复刻一个电子版的自己：整合多来源信息，理解本人、记忆与环境，辅助处理琐事，分析并给出建议，与本人讨论选择。

与 `PRODUCT_LOCK`“作者原意 1–10”一致。三条长期目标（数字分身 / 商业产品 / 行为建模研究）继续并存，本文只调整**近期**先验证哪一个。

## 1.2 五个长期场景（方向，不预排月份）

| 场景 | 一条完整通路的含义 |
|---|---|
| S1 回复消息 | 导入 → 理解待回消息与人物 → 起草 → 作者修改 → 纠正被记住 |
| S2 整理琐事 | 识别承诺与待办 → 整理提议 → 确认 → 提醒 |
| S3 分析人与事 | 选人物或事件 → 证据化汇总 → 带来源的分析 → 纠正 |
| S4 推敲选择 | 描述选择 → 召回相关偏好、价值、经历 → 列选项与理由 → 讨论 |
| S5 回顾记忆 | 按时间、人物、主题回看 → 修正、合并、遗忘 |

近期只细化 S1；其他场景在 §7 的决策点按真实问题选择，不预先承诺顺序。

## 1.3 能力证据标签（不作为门槛）

| 标签 | 含义 | 证据 |
|---|---|---|
| 证据级 0 | 未实现 | — |
| 证据级 1 | 合成数据下端到端可用 | 本地合成检查；远端 CI 有结果后注明目标 SHA |
| 证据级 2 | 作者在获准范围内实际用过 | 使用观察记录 |
| 证据级 3 | 真实使用中有可解释的改善 | 同口径的前后对比，附样本量与限制 |
| 证据级 4 | 其他人可安装使用 | 外部用户上手记录 |

规则：标签只描述**已有证据**，不限制任何能力的推进；某能力长期未动时，重新判断继续后置是否合理，不自动生成实现任务。原方案记载的证据级 1 来自本地合成检查；远端是否已运行以目标候选的实际结果为准，不能沿用该快照。

小样本（例如 20 次）是一批**探索性观察**，可以发现问题和方向，不能单凭数量证明效果显著、具有普遍性或已经“复刻人格”。

# 2. 近期战略转向（D-S0 的内容）

## 2.1 为什么转向

- 现有底座（加密、遗忘、出网边界、审计、导入、起草、D109 范围偏好）提供了准备 S1 使用验证的基础；能否进入真实观察仍须完成拟用原生路径的实际核验与具体授权，不能由附件诊断代签。
- 现有合成证据能证明所覆盖路径的行为，不能回答真实使用中“哪里最不像作者、最没用”。缺少这类信号，下一步选择容易落到单个算法或模块上。

## 2.2 D107 实验版工作的处置

| 处置 | 内容 |
|---|---|
| 保留（继续维护） | 持久化与事务、CK 遗忘传播、来源失效、D108 时间规则、已有研究留存实现的安全维护；针对已授权实现的缺陷复现、最小修复与必要合成回归继续按原范围执行 |
| 后置 | 研究系列（数据与模型）的新实验、研究留存范围扩展、新的算法架构实验、行为预测 |
| 结束 | 不强制结束任何工作；D107 计划中未完成项在 STATUS 标“后置”，保留原记录与失败 |

本次按此方向调整近期排序；D107 原实施记录与失败仍有效地描述其原版本，当前暂停和后置状态见 STATUS。

# 4. S1 拆分与运行模式

## 4.1 三类工作分开

| 部分 | 内容 | 依据 | 状态 |
|---|---|---|---|
| S1-a 使用现有能力 | 导入、起草、作者修改、明确选择人物/场合语域并确认 | 现有功能＋D109 | 可列入已授权合成/原生验证；真实使用另依具体许可 |
| S1-b 编辑差异推断偏好 | 从作者修改推出偏好提议 | **新能力**，与 D109“不从编辑推断”冲突 | 只在 S1-a 的真实失败显示必要时，经新决定再做 |
| S1-c 反馈记录 | 记录每次任务的结果、耗时、错误类型 | **新用途**，不属于 D107 | 先按 §4.3 定义并获批准 |

## 4.2 运行模式（D-S4）

| 模式 | 能证明 | 不能证明 | D109 是否生效 |
|---|---|---|---|
| T1 本机模板 | 语气个性化、补全成本、范围偏好是否有用 | 是否理解待回消息 | 是 |
| T2 占位端点 | 不看正文时档案的通用效果（隐私对照） | 消息特定正确性 | 否 |
| T3 一次性原文端点 | 内容相关性、事实保留、边界是否正确 | 本地无出网下的表现 | 否（如需生效，另行决定 D-S7） |

**建议**：第一批真实观察同时使用 **T1 与 T3，结果分表报告**，不合并统计；T2 不作为主要使用模式。T3 每次仍按现有二次确认与单次批准，导入授权不自动包含出网授权。

- **T1 只评**：语气骨架是否可接受、补全耗时、范围偏好是否被正确应用。不进入内容相关性、事实错误、承诺反转等分母。
- **T3 只评**：当前端点路径的内容相关性、事实保留、边界与新增承诺，以及作者实际编辑负担。**不据此判断 D109 范围偏好的端点效果**：T1 与 T3 同时在模板/模型、正文可见性等多个条件上不同，“T3 内容对但语气不像”只能支持把 D-S7 列为候选，不能确定原因。D-S7 若被采纳，再在同一端点、同一任务、其他条件一致时比较有无范围偏好。
- **请求模式 ≠ 实际来源**：请求 T3 后，端点回复不可读、为空等情况会回退为本地模板。这种任务按实际来源记录，作者补完模板后接受也**不计为 T3 内容理解成功**（沿用 [ROADMAP §7.2.2](../ROADMAP.md#722-abc-条件与盲评规则) 的降级处理）。

## 4.3 S1-c 反馈记录的最小定义（D-S6）

- **用途**：仅用于作者本人评估 Soul 的产品效果，不用于研究留存、不出网、不进仓库。
- **形式（近期）**：沿用 ROADMAP §7.2.3 的“手工评测记录”模式，写在作者选定的本机目录，不改产品 schema；仓库只保存汇总数字。是否改为库内加密表（受 CK 与遗忘约束）留到周期 2 后决定。
- **不记录**：消息正文、草稿正文、编辑后正文、人物或来源的 UUID/ID、姓名、账号，以及任何可反推对象的自由文本备注。
- **标识说明**：`task_id` 是随机任务编号，用于去重和统计；它不使记录“匿名”，只是不含对象关联键。
- **遗忘**：记录不存对象关联，因此**不承诺按联系人自动同步删除**。作者遗忘某联系人或来源时，若该批观察期间涉及过该对象，删除该批次的全部记录行（保留已发布的汇总数字，因其不含对象信息）；每批次记录开始与结束日期，便于整批定位。
- **正文处理**：`edit_ratio` 由本机工具在内存中计算——周期 1 采用独立本机脚本（作者粘贴草稿与终稿，脚本只输出数值并立即丢弃文本），不改产品；是否在原生界面定稿时自动计算，留作后续候选。

**最小字段**（每次开始的任务一行）：

| 字段 | 取值 |
|---|---|
| task_id、batch_id、时间（含时区） | 随机编号 |
| requested_mode | T1 / T3 |
| actual_source | template / endpoint / none |
| fallback_reason | 无 / 端点未配置 / 审批不匹配 / 网络拒绝 / 回复不可读 / 回复为空 / 其他 |
| origin | requested（为验证而做）/ organic（主动使用） |
| scope_used | 是否使用了范围偏好 |
| outcome | not_generated / abandoned / rejected / heavy_edit / light_edit / accepted / no_feedback |
| content_acceptable | 是 / 否 / 未评 / 不适用（T1 记不适用） |
| severe_error | 无 / 事实错误 / 承诺或边界反转 / 关系误判 / 隐私问题 / 未评（未评不得记成无） |
| edit_ratio | 0–1 实测值；无草稿或未测时为空（缺测） |
| task_seconds | 从选定待回消息到定稿的业务耗时（含审批、等待、修改；不含填写评测与分类）；未测时为空，不计为零 |
| correction_status | none / d109_covered_new / d109_covered_repeated / unmemorable（当前系统没有机制记住这类纠正） |
| correction_opportunity | 是 / 否 / 未评：是否属于 D109 偏好已设后的再次适用机会；无复发的机会也记“是”，不能仅凭出现纠正推定适用 |
| failure_layer / failure_type / severity | 见附录 B；满意的任务留空 |

## 4.4 指标口径

总原则：**完整保留任务漏斗**（开始 → 生成 → 实际来源 → 反馈 → 结果）；每项指标只用**适用且已测**的分母，同时报告被排除的数量。T1 与 T3 按 `actual_source` 分表。

| 指标 | 分子 | 分母 | 同时报告 |
|---|---|---|---|
| 可接受率 | outcome ∈ {accepted, light_edit} 且 content_acceptable=是（T1 只看 outcome） | 已生成且有反馈、已评的任务 | not_generated、abandoned、no_feedback、未评各自数量 |
| 编辑比例 | `edit_ratio` 的中位数与分布；公式 = 字符编辑距离(草稿, 终稿) / max(草稿长, 终稿长) | 有草稿且实测的任务 | 未生成与缺测数量 |
| 首稿严重错误率（仅 T3） | severe_error 为具体类型 | actual_source=endpoint 且已评的任务 | 按类型分列；未评数量 |
| 业务耗时 | `task_seconds` 中位数 | 实测的任务 | 缺测数量；可选：作者估计的“自己直接写”耗时 |
| 纠正复发率 | 已评适用机会中 correction_status=d109_covered_repeated 的任务数 | correction_opportunity=是的已评任务数，含 correction_status=none 的无复发任务 | 未评机会单列，不进分母；无已评适用机会记 N/A；例如 10 次机会中 1 次复发为 1/10，不是 1/1 |
| 无法记住的纠正 | unmemorable 次数与类型 | — | 作为 §7 选择 S1-b 或 Claim 的证据 |
| 使用情况 | requested 与 organic 分开计数 | — | 完成与放弃分开 |
| 召回（启用后） | 必要信息被提供 | 有必要信息的任务 | 遗漏数、无关候选数、勾选负担 |

反例提醒：20 次任务中 10 次未生成、10 次编辑 0.1，编辑比例报告为“0.1（n=10），另 10 次未生成”，不能报告为 0.05。编辑量小不代表内容正确，删掉“我同意”只改几个字也是严重错误，由 severe_error 捕捉。

# 5. 战略原则

1. **安全边界不让步**：出网、遗忘、审计、只起草不发送全部保留。
2. **证据驱动**：下一步由真实观察和合成反例决定；严重问题出现一次即可处理，不需要重复三次。
3. **先通后深**：场景先跑通一条，再按问题加深某一层。
4. **需求拉动基础设施**：基础设施和重构由当前任务的实际阻塞或安全需求触发。
5. **小步交付**：短分支、小 PR；远端 CI 恢复后以目标 SHA 结果为准。
6. **共享语义集中设计**：DTO 和 trait 可以减少编译依赖，但授权、事务、来源失效、提议归属、取消结算需要共同设计，不承诺“接口合并后互不等待”。
7. **摘要短、证据全**：摘要尽量一页；失败、原始日志和复现输入照常持久保存。

## 5.1 控制验证与单点投入

- **验证围绕一个可回答的问题。** 冒烟只用于必要的启动/接线确认；已有覆盖且候选、环境和问题均未变化时，不重复冒烟或同范围扫描。优先实际执行主路径、复现失败和必要的消费者回归，复杂改动仍执行已有独立评审与适用检查。
- **不增加哈希与冻结流程。** 使用 Git、现有版本、任务输入与实际结果定位候选，不额外生成文件摘要、哈希台账、冻结 contract、baseline 或 gate。确需新增时必须满足 AGENTS 的具体失败场景及逐项不足说明；既有安全机制保留。
- **每项工作有时间盒和停止条件。** 写清要解决的问题、允许投入、预期产物和退出条件；不是必须耗满预算。同一失败在没有新假设、输入或环境变化时不原样重试；相同候选与覆盖面无新发现就结束检查。
- **到期收口并继续可做部分。** 问题已回答即交付；没有增量证据、收益不足或超出时间盒时，保留失败、未决与恢复所需条件，缩小切片、后置该问题或转向无依赖的已授权工作。安全阻塞保持阻断相应路径，不能因时间到而跳过，也不必让无关工作一并停滞。
- **周期只选一个主要切片。** 按严重错误、放弃原因、作者投入时间排序；不为凑样本、过线或优化单个数字延长周期。下一个切片由 §7 的观察决定，50/30/20 只是估算。
