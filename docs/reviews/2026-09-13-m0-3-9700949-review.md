## F1 · P1：用 stdout 的 ok 替代真实退出码，错误进程被报成成功

**位置：** `scripts/install-smoke.ps1:448–453`；影响调用方 `:637–645`。

`Process.ExitCode` 为空时，新增逻辑根据 `$report.ok` 生成 0/1，导致“进程退出成功”和“报告声称成功”两个独立检查合并成同一个自述。进程打印成功报告后再异常退出、清理失败或显式非零退出，都不应该被转换为退出 0。

### 实证 `[V-runtime]`

本机 Windows PowerShell `5.1.26100.9444`，编译真实子进程：

```rust
fn main() {
    println!("{{\"ok\":true}}");
    std::process::exit(23);
}
```

使用 PowerShell AST 只加载**当前脚本原有的 `Invoke-HeadlessSmoke` 函数**，没有执行安装/卸载 main；子进程在临时目录运行，无 mock 进程。先以 `System.Diagnostics.Process` 直接启动，获取 Handle 并等待，确认控制组真实退出码，再调用被审查函数。实际输出：

```text
CONTROL_EXIT=23
CONTROL_BODY={"ok":true}
REPORTED_EXIT=0
REPORT_OK=True
PS_VERSION=5.1.26100.9444
BUG_REPRODUCED: exit 23 became exit 0 based on stdout
```

这证明**退出码验收项被错误放行**。没有跑完整安装门禁；极简 JSON 不含其他门禁字段，不声称这份 JSON 已使所有门禁通过。

**修复要求：** 可靠保留并读取真实进程退出状态；拿不到时 fail closed，报可定位错误，不能从 JSON、stderr 或其他自述推导零退出码。保留网络观察和输出捕获，不靠重跑整次 smoke 掩盖一次真实失败。

**必要回归：** `ok:true + exit23` 必须失败；`ok:true + exit0` 才可通过相应检查；`ok:false + exit0` 必须报告流程失败；快速退出和重定向输出均覆盖。必须运行真实子进程，不能只检查脚本文本中是否有某个字符串。

## F2 · P2：MSVC 专用 linker 参数无目标平台条件

**位置：** `apps/desktop/src-tauri/build.rs:12–14`。

`cargo:rustc-link-arg-tests=/MANIFEST:EMBED` 与 `/MANIFESTINPUT:...` 无条件输出，传给所有目标的集成测试链接器。它们是 MSVC 风格参数，不适用于 GNU 风格驱动。现有 MSVC 测试加载问题不应通过破坏其他目标的链接来解决。

### 证据

- `[V-source]` 新增输出不检查 target OS/env；不是 `tauri-build` 内部会自动过滤的 WindowsAttributes 参数。
- `[V-runtime]` 本机 LLVM-MinGW/clang 对同一个最小 C 程序：不带这些参数成功；加入原样参数失败：

```text
GNU_STYLE_CONTROL_EXIT=0
GNU_STYLE_MANIFEST_ARGS_EXIT=1
clang-22: error: no such file or directory: '/MANIFEST:EMBED'
clang-22: error: no such file or directory: '/MANIFESTINPUT:E:/Project/Soul/apps/desktop/src-tauri/windows/soul.exe.manifest'
```

这只是原生 GNU 风格驱动的参数验证；**没有运行完整 Linux/macOS Tauri 构建**。本机只安装 Rust `x86_64-pc-windows-msvc` target。

**修复要求：** 根据 Cargo **目标**配置（如 `CARGO_CFG_TARGET_OS` / `CARGO_CFG_TARGET_ENV`）仅对 Windows MSVC 输出相应参数。不要只用宿主机 `cfg!(windows)`，以免交叉编译错误。保留产品 `app_manifest` 路径；非 MSVC 支持若不实现，应不输出无效参数，而不是伪装已验证其 manifest。

**必要回归：** Windows/MSVC 输出参数；Linux、macOS、Windows/GNU 不输出 MSVC 参数；真实 Windows integration-test EXE 仍嵌入 Common-Controls manifest 并能启动。配置分支测试不等于完整跨平台构建，分开报告。
