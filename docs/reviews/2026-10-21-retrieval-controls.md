## 预测前方案审查

已核对五种方法、三条件与固定指令。明确条目、来源、事实三个口径；compact14 隐藏来源只复验，不自动进入请求；普通 BM25 与分组 BM25 的统计范围明确。跨条件数量、长度、IDF 与干扰内容变化是混杂，不宣称独立因果分解。语义指令含多样性提示，结果代表完整策略，不能把优势全部归因于语义理解。精确正文分组只在本轮同分类合成材料成立，不授权生产跨分类、版本或来源状态合并。

## 预测前 fixture 发现

1. 初版 distinct32 的十八条新增摘要仅修改附件编号与版本号，内容均为往年登记表列宽／页码，并主动声明不提供新事实。字符串不同不足以支持“不同内容干扰”的研究目标，且可能偏向语义近重复识别。要求改为多类实质不同的对象、阶段、事项或许可主体干扰，逐条给出排除理由；原必要事实不变。
2. 包装事实写成“干纸隔开”，来源只说用纸隔开、标组名、不要湿布，不能额外推断干纸要求。要求事实描述直接对应原文。

其余已审 any-of 支持关系可辩护；最后任务的钥匙缺失与钱包找回被明确分开。旧约定和一般背景列为辅助；ID 和排列没有读取 gold。明显注入与普通引用只覆盖当前合成反例，不证明隐蔽注入鲁棒性。

上述反馈发生在任何语义预测之前。新增干扰已改为多类实质内容；复核又发现儿童班负例中的成人班登记句、会员卡补办费用负例中的当前钱包状态句，均已在预测前删除。原必要事实不变。

## 实现审查与复现

`/root/framework_generality` 独立核对 BM25 的 tf/df/长度/字段权重、组统计量、代表次序、MMR 与并列行为，未发现数学实现偏差。设计补明 Jaccard 包含标题与摘要、跨空白边界形成 bigram、长度为出现总数，以及全零相关性后仍按多样性选择。

主评审核对隐藏 aliases 的初始化正文匹配、独立快照及全部复验，实际 Owner 许可和 retained IDs 限于可见选中来源；动态排列与 any-of 计分未发现具体问题。主线程发现重放最初在读入全部文件后才检查字节限制，已补 `Read::take(limit+1)` 有限读取；非法 response 仅使该 case 不可用。

评审发现旧 adapter 要求预览数据逐字包含原摘要，新邮箱来源会被正常脱敏。主线程新增定向真实准备测试，实际在该旧断言失败（EXIT 101）；原始日志见设计回执。修复只调整测试对完整脱敏结果的核验，未删除来源、豁免邮箱或修改生产 redactor。独立复审确认 ID、来源、Owner 许可、预算、默认拒绝与零请求检查保持；直接单来源测试另外手写检查邮箱已占位、许可和未承诺事实仍在，修后运行通过。

## 最终原始结果重算

评审先读取十八份原始 input / response 与 replay 日志，再从 fixture 的 ID 映射、事实 any-of 规则和类别重建全部 90 个方法条件。原始语义排序与重放一致；实际 selected 均为前八条，retained 与 selected 相同。全部来源映射、首支持排名、Top-3、辅助／不适用及重复占位均与日志一致；派生 `results.json` 恰好对应 90 条观察，未把完成汇总混入样本数。

每格顺序为“事实覆盖 / 13；Top-3 / 13；完全覆盖任务 / 6；重复占位；不适用条目”。每条件共选 48 条。

核对结论为：90 次真实准备，720 个选中引用全部保留，零批准、零执行、零生成请求。每 case 均保存并复验 32 来源；compact14 的十八个隐藏来源仅进入映射与复验。紧凑 InputCase 为 2,942–5,930 字节，实际请求为 2,271–3,323 字节，均符合对应预算，不混作 token 或费用。

评审确认更强词面明显缩小差距；但分组把 duplicate32 的重复占位 18→0 时，不适用条目反而 19→30，不能只凭去重指标宣称整体质量改善。MMR 的 `q11` 必要截止条件排第十而漏选；语义的六个重复条件分别有 4、3、2、3、3、3 个重复占位，钱包任务 Top-3 缺一项。多样性提示没有保证去重，完整召回也没有证明应该填满八条。

实际日志复核：新 7 + 旧 8 普通测试通过、5 ignored；相关五目标 12 + 10 + 11 + 10 + 4 = 47 通过，普通测试合计 62 项。显式 export / replay 各一项通过，限定严格 Clippy 与根格式退出码均为 0。邮箱修复已有实际绿色支持，不仅是静态判断；完整命令与日志名见设计回执。
