## F1 P1 缺少适用条件和有效期不能解释为永久适用

位置：§3.2/B056，“旧记录缺字段（视为无条件、无期限并在界面标注）”。

`[V]` [selection.rs](../../crates/soul-memory/src/selection.rs):22–25 明确记录存在不等于事实仍有效；:374–381 对限定事实时间的查询返回澄清。[MemoryDraft](../../crates/soul-memory/src/draft.rs):43–54 可以保存用户自己的 Preference，但没有结构化 scope/valid。[事项类型](../../crates/soul-store-api/src/assistance.rs):17–20、:39–64 还存在与 Memory 关联的截止、取消和已解决状态。

`[H]` 合成反例：旧记录正文为“这周与 A 沟通先用正式语气”。把没有结构化字段解释为“全对象、永久有效”，会扩大原意；界面标注无法修复这个推理。这个反例是当前接口可表达的静态构造，本轮未运行，也没有读取任何真实记忆。

建议替换为：

> 旧记录缺字段时，保留“适用范围未知／有效期未知”；兼容读取不等于确认其无条件、无期限。维持现有本次明确候选参考及时间澄清语义；来源对象已有截止、状态等信息时按既有语义投影。只有显式声明不限范围或期限的记录，才标记为不限。

这不要求迁移时拒绝全部旧记忆，也不新增 hash 或迁移框架；修正的是不能把未知伪装成肯定。

## F2 P1 三值分离需要按对象语义投影，不能编造机器值

位置：§3.2/B051–055，“每条论断同时给出三样”“无锁取机器值”“authority 只能从用户锁/纠正证据推导”。

`[V]` 用户可直接保存 Preference，既没有机器原值，也不一定有纠正证据。问卷轴同样来自用户自述，未锁定不改变其来源：[profile service](../../crates/soul-profile/src/service.rs):223–239、:299–305；values/boundaries 的自述指针见 :544–558。不能把这些无锁对象统一归为机器判断。新增未确认 LLM 提案若也遵循“无锁就生效”，还会与本文件规则 8 冲突。

此外，[correct.rs](../../crates/soul-graph/src/correct.rs):90–118 允许用户把与机器相同的档位锁定，并不要求两者不同。因此 Corrected 不宜被定义成一律“否定机器判断”；准确含义是发生过用户纠正/覆盖，但不能据此推定原机器 statement 已被接受。

建议替换为：

> Claim 按源对象的既有语义给出生效值及真实来源；机器判断和纠正证据在存在时分别提供，不存在时标记无。“锁定取用户值，否则取机器值”仅适用于已有该语义的对象，如 T4D。直接保存、问卷自述、导入与推断保持来源区别；新增未确认提案无生效值。authority 不从 Corrected 推定，也不只根据是否发生纠正判定来源。

共享 CK 或独立 CK 加遗忘依赖均可继续作为候选，不据静态设计判定不可行；实际实现须保证依赖文本不可再解密，而非仅从召回中屏蔽。闭集枚举和联系人 UUID 未密封也不一概构成缺陷，它们仍须服从现有主体、用途及遗忘约束。

## F3 P2 首个偏好切片需要包含归属和下一次应用

位置：§5.7/B115、§8.1/B160–161。选择反馈→偏好提案可以成立，但“只存 Preference + scope”尚不是完整闭环，“不新增授权面”也应限定为读取本次草稿与编辑的阶段。

`[V]` 普通 [DraftRequest](../../crates/soul-draft/src/draft.rs):137–156 只有 brief 和 turns，普通 [Draft UI](../../apps/desktop/src/routes/Draft.tsx):212–213 没有稳定 person/occasion 绑定。把“您”改成“你”，不能自行判断是本人对 X 的长期表达偏好、一次性措辞还是全局偏好，更不能据此写成 X 本人的偏好。

`[V]` [ProfileBrief](../../crates/soul-draft/src/brief.rs):42–44、:68–80 只读取 voice 与 axes；[Session memory](../../crates/soulcore/src/commands/session_memory.rs):119–132 仍按明确 candidate_ids 取材。保存一条 Preference 不会自动改变下一次普通起草。即使手选进 W2，[本地模板路径](../../crates/soulcore/src/commands/draft.rs):794–805 也不会自动把记忆内容转成语域规则。直接修改全局 `set_voice` 又会影响其他联系人，违反“仅对 X”的 scope。

不必因此把整个 Claim 或自动召回前置。首版只需写清一条有限闭环：

1. 用户确认这是**本人的表达偏好**，明确一个已有语域选项、目标联系人或全局范围，以及有限场合；提案绑定本次草稿/编辑版本。
2. 保留 scoped 方案时，下次任务显式选择相同 scope，只加载已确认的有限偏好，应用到本次 brief，不修改全局 voice。确认时说明这项未来使用；无需为此强制另造 gate。
3. 同 scope 下一任务可见应用；不同对象/场合或缺标识时不应用。拒绝/取消不生效；经现有遗忘入口销毁后不再应用，旧准备也失效。

若想进一步缩小，也可明确只做**全局 voice 提案**并复用现有路径，但需相应删去“只对 X”的承诺。两种方式择一即可。本轮没有作出该产品选择，也没有实现或验证新反馈流程。

## F4 P2 VAL-lite 已能作障碍日志，但 UUID 不等于可重放样本

位置：§7/B150–153。

`[V]` 新版的失败记录、全部发起任务分母、缺测不填零和事实错误数是有效修正，不必为记障碍复制整套 VAL-01。剩余问题在于宣称材料 UUID 就是 T2 金标来源、纠正 UUID 就能判断是否复发。

`[H]` 相同 UUID 的材料可能已经更新、过期或遗忘，仅 ID 不能还原当时任务、时间参照和适用语义；一周没有再次遇到同类任务，也不能把“没有再次出错”解释为纠正有效。计时若混入离开页面的时间，周中位数仍不可比。

最轻修文：

> 所用、必需及禁用材料 UUID 提供 T2 标注线索；T2 另行在获准范围内整理成有明确任务、相关材料和预期结果的合成/脱敏 fixture，未形成可执行 fixture 时不称完成 T2。纠正关联用于调查；未定义同类任务和观察机会时，复发效果记为未测。编辑耗时为净编辑时间，无法区分中断时记 missing；明确缺信息统计的是任务数还是缺项条数。

“不保存正文”继续保持；不能为补金标自动保存真实聊天或建立绕过遗忘的历史副本。可先只记障碍，不计算尚无依据的效果指标。

## F5 P2 暂停来源与 S1 路线的生效条件仍需区分
