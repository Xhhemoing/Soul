## 发现、修正及验证

| 发现 | 处理与验证 |
| --- | --- |
| 计分读取合法 JSON 但坏 needs/status 形状时会崩溃 | 加局部容错，结构失败仍保留分母；status 先查字符串再集合比较。修复前公式反例可复现，修后当前函数反例通过。 |
| 需求拆分后逐项强制包含完整 gold AND 组会误判，部分映射又可能误算召回 | 增加事后 `gold_coverage` 完整组合标注，按预测各 OR 路径的组合联合检查 AND 证据；不向运行流程回填答案。 |
| 同 case 重复方法行可能被字典覆盖，费用条数相同也可能实际错配 | 先查方法行数与精确集合，计量检查唯一 case 集合与数量。 |
| 初候选 predicted 排名来源标签疑似不符 | 定向复读最终源码确认统一从原文投影排名，已消除，不列为剩余缺陷。 |
| 元数据可能同源子串各自成立、联合语义错误 | 不修改本轮模型输出；按预定语义口径保留为结果失败，见方案全部失败表。 |
