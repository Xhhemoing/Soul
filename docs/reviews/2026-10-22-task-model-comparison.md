## 发现与处理

| 具体发现 | 影响 | 实际处理与证据 |
| --- | --- | --- |
| 原 `all_options` 对未评估项补 unknown | 对照会因构造方式而过度阻断，不能归因于“全部当必需” | 改为一次真实模型评估四项，再分别采用全部项/预测必需项；定向测试覆盖可选项不阻断必要项策略 |

| `c50634f84007` 的 gold 缺少有效替代关联来源 | 两款 GPT 同时失去一个完整诊断分，不能视为模型错误 | 保留主评分，单列敏感性解释；未回改 gold/提示词或重跑求分 |

上述实现修正已经过对应普通回归及最终结果核验。后两项是保留在交付中的材料/评分限制，不通过事后调整主分数消除。明确模型反例 `a90c00c21ed7` 中，Luna 忽略当前 P6 的 175°C/190°C 冲突而判充分；该失败没有被标注争议掩盖。

## 最终实际核验

- 两款 GPT 各 96 个唯一 case 均为 completed；逐项核对 input 与 fixture.input、raw 与 measurement 的型号/状态/usage、prediction 与 raw 文本提取，一致。中转返回的名称未被当作底层模型身份的独立证明。
- 每笔 GPT 正式请求的计费请求数增量为 1，费用为正有限值，与费用 ledger 一一对应。Luna $0.028633499998250045、Sol $0.5543940000006842；整个 ledger 194 条、未结算 0、合计 $0.6927989279999713。Jev 使用返回用量乘官方单价，与 GPT 的接口消费增量明确分列；不声称已核对供应商账单或有服务端硬限额。
- 四个最终结果目录各 384 条唯一 case/方法条件；独立重算必要项、动作、AND 支持、OR 冲突、额外来源与错误充分，和报告相符。Jev 的结构失败保留在分母；固定四/八条没有诊断评分分母，不将其当作语义诊断模型。
- 原始主评分：Luna 全批动作 89/96、完整诊断 88/96、错误充分 1，留出动作/诊断均 31/32；Sol 分别 96/96、95/96、0，留出均 32/32。接受 f13 替代路径的敏感性诊断为 89/96、96/96，与原始主评分分开。
- 同一留出 8 个 complete case 中，Luna/Sol 均覆盖 16/16 必需事实，最终请求为 11273/11026 bytes，引用 20/19 条；固定八条同覆盖为 21390 bytes、64 条，固定四条只覆盖 9/16。47.30%/48.45% 字节减少只适用于这个配对子集，不包括诊断调用成本。
- `sol-replay.log` 支持 1 项显式重放通过及 384 条条件完成；`python-tests-final.log` 支持 5 项通过。主会话退出码摘录明确其工具返回来源，没有伪装成历史 stdout。16 项 Rust 普通测试、严格 Clippy、根格式与其余模型重放的命令和范围列在设计回执。
- 未运行本地模型分支已移出仓库 runner；任务专用下载尝试和草稿保留在仓库外。未把依赖下载或静态实现当作推理证据。离线 Session 的零出站只描述重放阶段，不覆盖实际 API 实验。

最终定向核验未发现新的运行、输入隔离或费用记录阻塞。评审到此停止；没有对相同候选反复扫描或扩大模型测试范围。

## 结论的适用范围

本回执支持本轮合成研究切片交作者验收，保留两项评分/材料限制。24 个相关任务 family、其中 8 个留出 family，不能等价为 96 个独立真实用户任务；未验证图片、音频、真实聊天导入或真人效用。语义模型尚未接入生产默认，既有加密、来源、许可和真实数据边界未因本轮研究扩大。

不签发 G-L/G-W/G-M、Goal 关闭、合并批准或生产模型正确性结论。当前候选未提交、推送或发布。

## GPT-6.1 Sol 跟进：增量静态核验

作者随后要求用 GPT-6.1 Sol 替代 GPT-6 Sol 做同批测试，并比较各类算法的场景、速度与成本。仍由原独立评审者 `/root/pipeline_review` 只读核验；本节是后续增量，不把首轮模型结果自动转签给新候选。

- runner 仅新增 `gpt-6.1-sol` 白名单和 docstring；共享提示词、768 输出 token、low reasoning、`store:false`、费用差值核对、未结算停止与累计预算控制保持。
- 新增 `measure_local_stages` 显式 ignored 入口与 `timing.rs`，复用现有函数。10 次总秒数乘 100000 等于单次平均微秒，首次秒数乘 1000000 等于首次微秒，单位正确。create_new 防止覆盖此前结果。
- 文件读取、fixture/gold 加载与预测读取在计时闭包外，闭包仅使用 input/case/prediction/rank，没有用 gold 决定选择。`first_us` 是该 case/阶段第一次调用，不代表进程冷启动；`warm_mean_us` 是十次算术均值，不是 p95。
- BM25 的 rank 函数内部也计算分组，分组与各排名路径不能相加。支持组阶段含输入、预测与完整排序校验，只测既有 Sol 判断 ready 的 24 case；其他阶段各 96 case。此微测量不代表真实 Session 的端到端准备。
- 当前配对复测沿用已见的 96 份输入与旧 holdout，模型输入不含 gold，提示词没有调参；但不能称一批新的盲测任务。前述 gold 替代路径遗漏和不可读元数据不足的限制继续保留。

增量静态核验未见阻塞。主会话实际运行 local-stage 测量 1 项通过、504 行；16 项普通 Rust 测试通过、3 项默认 ignored，限定严格 Clippy 通过。首次格式检查发现 timing.rs 单个调用需要换行，原失败日志保留；仅修正该换行后格式检查通过。Python 5 项边界回归通过。模型完整结果的独立核验在后续回执单列。
