# ADR-002：统一运行时与本地 API

日期：2026-10-23（America/Los_Angeles）。状态：采纳；N2 共享 runtime/types 与受限 API 已扩展为 N3 写操作、主体归属及事件候选，实际验证状态见实施回执。旧决定索引：D111。具体结构、实现边界和验证链接见 [local-api](../architecture/local-api.md)。

## 背景

`soulcore::Session` 不依赖 Tauri；桌面以 `Arc<Mutex<Session>>` 共享核心。API 可复用业务，但现有 `core.ts` 来源通知只覆盖本 WebView，经 HTTP 的写入不会自动使 UI 旧结果失效。接口抽取与 API 第一片应在同一实现中完成。

## 决定

1. 保留 `soulcore` 和既有领域 crate。新增 `soul-runtime` 负责传输无关的 Session 所有权、统一操作协调、后台任务结算及变更通知；Session 迁移按被接入操作逐项进行，不复制业务规则。
2. 新增 `soul-types` 放共享边界 DTO 与稳定拒绝码，作为 Rust/TypeScript/OpenAPI 输出的唯一来源。按首片真实接口抽取，避免把全部内部类型强行公开。生成器必须先在两个锁文件和 Rust 1.83 下证明兼容，再接常规检查。
3. 新增 `soul-api` 实现 `/v1` HTTP/JSON 传输，依赖 runtime/types；Tauri commands 也转调同一 runtime。初片接状态和必要查询，保持前端现有 Tauri 传输，不并行维护两套业务实现。
4. 首片由桌面同一进程持有唯一 Session。后续 headless host 复用 runtime/API，并遵守同库 lease；不让两个 host 各自维护同库批准状态。
5. API 默认关闭、只监听 `127.0.0.1`、运行期随机凭据、接口白名单、有界输入及队列。当前只开放明确合成目录和输入范围；真实采集、外部模型、任意目录和研究保存不因 API 化获得授权。
6. 若使用运行期令牌文件，其 ACL 限当前用户、令牌不进参数/URL/日志、退出失效。该方式不能抵御同账户恶意进程读取令牌，不能描述成满足全部同机攻击防御；生产敏感接口开放前须解决凭据交付与既有威胁模型的差距。第一片的合成受限模式不降低原真实数据入口保护。
7. 服务端区分 UI 与已认证驱动主体，prepare/confirm/cancel 绑定主体和原核心提案。确认采用现有一次消费和明确状态码；只在原业务已经支持结果回读时复用幂等回执，不将所有动作改成盲目重试。
8. 变更协调覆盖开始、结算和来源变化，保留已发生写入与失败结果。成功后发事件之外，还必须防止进行中旧读取交付；UI 订阅 runtime 事件，并处理重复/丢失/重连和明确重读。现有 JS 自身写入通知不能与新事件机械叠加。
9. API 认证不等于用户已批准每个敏感动作。核心预览、确认、单次 capability、审计、CK 遗忘和事务不变量继续有效；审计不含正文。所有业务写操作经过原审计语义，新增动作按既有 schema 白名单评审，不直接记录整个请求。

## 取舍

共同运行时能避免两个入口的行为分叉；代价是要清晰处理 Session 锁、长任务和 UI 同步。先接只读端点降低首片风险，后续写入必须同时交付双入口时序测试。HTTP 断连不是取消或回滚，worker 必须保留结算所有权。

不采用把全部 Tauri command 动态映射到 HTTP、直接暴露数据库、一次搬空全部 crate 或为便利绕开单实例/lease 的方案。MCP/远程多用户/公网服务不在当前切片。

## 验证

真实 HTTP → 同一 runtime → 合成 Session，与 Tauri 路径对照结果。鉴权/Host/Origin/越界输入拒绝不产生业务副作用；跨主体不能消费提案；写入使 UI 在途旧结果失效；重启读取正确；锁文件不被删除以“解除占用”。生成 TS/OpenAPI 的普通可重复输出检查不引入第二份冻结 contract 或 hash。
