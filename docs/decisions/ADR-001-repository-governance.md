# ADR-001：仓库规范与交付证据

日期：2026-10-23（America/Los_Angeles）。状态：采纳作者本次规范化方向；本地文件实施情况见 [STATUS](../STATUS.md)，远端设置和 CI 结果须另行核验。旧决定索引：D110。

## 背景

STATUS 已混入长篇执行历史，API 方案埋在实施回执中。D61/D64 的禁止 hosted CI 与作者本次恢复 CI 的方案冲突，需要显式记载政策变更，同时保留原安全和平台验收边界。

## 决定

- AGENTS 放结构、日常命令路由、不变量、协作和交付要求；操作及记录细则在 operations。README 只说明原则、启动、验证入口、实际结构和许可，不堆测试数量/历史 SHA。
- STATUS 不超过 40 行，每项仅 1–2 句；只维护当前进展、阻塞、下一步与记录整理日期。完整历史放 archive，已有 history 保留。每个结论只在所属文档维护；PR 发布后引用原记录与该候选的检查结果。
- product / architecture / decisions / operations / plans / archive 按职责分层。现有产品、算法、安全和验收权威不为目录整洁集中搬家；product 导航指向原文件。新增 ADR 从 001 起编号，旧 D 编号保留为历史及索引，不重新编号。
- 一文件一写者，最多两个实现者、三个子 Agent、三个活跃 worktree。复用适合的 checkout，不自动建立或清理 worktree。模型使用用户明确指定的 gpt-6.1-sol/high。
- 日常先跑最贴近改动的检查；公共类型、事务、授权和跨入口行为变化扩大覆盖。失败按“保存失败 → 定位原因 → 最小修复 → 重跑原命令”处理，不靠豁免或更换分母报绿。
- Conventional Commits；后续交付以 main 为集成目标，短分支、小 PR。现有长期分支/dirty 工作不因此被重置、重写历史或代为提交。
- 恢复仓库内 hosted CI 配置；普通工程 PR 的合并检查以目标候选 SHA 的远端运行结果为准。PR head 与 GitHub merge ref 必须分清，旧 SHA 绿色不转签。本地检查仍是有效开发证据，不能代替远端 CI 或人工平台验收。
- D61/D64 的 hosted CI 禁令由本决定取代；D63“每个工程合并 SHA 必须先有 G-L 文档”的常规合并规则改由上述远端检查承接。原 G-L/G-W/G-M 定义、正式 Goal 关闭条件及历史失败保留；G-L 暂缓不改为通过。删除的旧 prompt、扫描轮次、`.agent_workspace/` 不恢复。
- GitHub Actions 开关、required checks 和分支保护只按实际远端状态记录。在候选尚未提交/同步、检查尚未产生时，不声称恢复成功。当前无自动提交/推送/合并授权；先形成可审阅候选，再安排远端交付。

## 不采纳机械照搬的部分

- 保留现有 `soulcore` 和领域 crate；runtime/types/API 按 [ADR-002](ADR-002-local-api-runtime.md) 提取，不把未来目录写作现状。
- 使用 pnpm 与两个 Rust workspace；保持 Rust 1.83。只使用合成数据，保留三项真实采集测试排除；fixture 的来源与用途是边界，不以改目录名替代检查。
- 不创建宽泛告警 baseline。已有严格检查继续执行，具体旧告警如确需例外必须逐项附原因、范围和撤销条件；新规则先诊断，不弱化原规则。
- 现有 Win32/DPAPI 窄 unsafe 模块保留。业务/core 新代码优先禁止 unsafe、避免非测试 unwrap；规则实际覆盖以编译配置为准，不声称全仓已启用。格式默认足够时不额外创建 rustfmt 配置；TS strict/ESLint 已存在，Prettier/nextest/生成器按兼容性与实际收益接入，不做全仓格式重写。
- 错误与日志使用既有类型与边缘约定。日志仅批准的安全元数据；ID 也受白名单约束，不默认所有 ID 都可记录。响应 `details` 不透传底层错误、正文、路径或凭据。
- 迁移沿现有顺序版本，说明升级及失败回滚/不可逆边界；遗忘后的数据不能靠旧备份或降级恢复。不能把“附回滚说明”写成承诺每次迁移都可逆。

## 影响与验证

新 CI 是合成工程自动检查，不是安装、原生交互或作者 G-M。剪贴板、文件选择器、托盘由作者人工验收；Agent 不代勾。数据/授权安全检查不删，研究暂停保持。

实施记录、首次失败、归档内容保留核验和独立审查见 [规范化计划](../plans/2026-10-23-repository-normalization.md)。本 ADR 不把未来 API、DTO 生成、CI 远端成功或分支保护记成已实现。
