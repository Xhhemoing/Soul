## 1 本轮选择与理由

近期主线是：**保留现有加密与来源体系；先把任务需要、适用范围和必要证据组表达清楚，再按预算选材；语义模型按实际增益加入。** 不将所有数据都摘要化，不要求所有请求走模型，也不在 32 条明确候选上先建设向量库。

具体保留三条研究路线，不能将表中“候选”理解为已接入：

| 路线 | 具体配置 | 用来回答的问题 |
| --- | --- | --- |
| 轻量本地对照 | 现有显式字段核对；研究中的中文 bigram BM25、精确分组、必要支持组优先选材；固定四/八条作为对照 | 已有结构足够时，纯计算能否选全而少带无关材料 |
| 本地相关性增强 | 相同输入和预算，分别只加 `BAAI/bge-reranker-v2-m3` 或 `Qwen/Qwen3-Reranker-0.6B`；两者不默认叠加 | 同义改写、专名和任务相关性是否值得一次本地模型推理 |
| 语义判断增强 | 单次通用 LLM 输出需求/适用关系/支持组及出处；Jev 原子判断作为替代或选择性升级候选 | 复杂否定、条件、改口和跨条依赖能否可靠解释，额外调用是否真正省钱 |

重排器解决相关性，语义判断器解决材料之间和任务之间的关系，确定性选择器解决预算和完整保留。它们不是互相替代的万能模块，也不应为了“更智能”全部常驻、全部调用。若一次联合语义判断已能覆盖整池并给出支持组，额外 embedding/reranker 必须单独证明增益。

本机只读检查得到 Ryzen 7 H 260、8 核/16 线程、约 15.26 GiB RAM；`nvidia-smi` 得到 RTX 5060 Laptop GPU、8151 MiB 显存、驱动 610.88。此配置支持把小型本地模型列入测试，但不能据此承诺延迟、同时常驻数量或 Windows 打包可用。PATH 未找到 ollama/llama-server；这不证明机器其他位置没有运行环境。

## 2 按数据类型处理，保留原有信息边界

| 数据 | 近期处理方式 | 当前仍缺什么 |
| --- | --- | --- |
| 聊天导入 | 复用 Telegram/v1 解析、来源自然键、事务和密封正文；保留原文、说话人、事件时刻与来源引用。原始时刻缺失/非法按已有规则拒绝，不用导入时间冒充 | 任意对话里的指代、承诺撤回、有效时间和适用条件尚非通用已实现能力 |

实现依据：`soul-import/src/indexed.rs`、`telegram.rs`；`soul-collect/src/collector.rs`、`session.rs`；`soulcore/src/commands/session.rs` 的问卷路径；`soul-memory/src/service.rs`；`soul-fileplan/src/scan.rs`。此前时间完整性、导入和停止实验只支持其各自列明的范围，见[实验版回执](2026-10-20-research-experiment.md)。

文本规范化采用可逆、保留原文的方式：统一换行/明确等价空白用于查询；数字、日期在主体和时区/参照时刻已明确时转成类型化值，用代码比较。简繁、昵称、近义词、相对时间不能直接覆盖原文。检索中的归一化不能自动成为事实相等的判据；“九点”和“09:00”的等价还需要日期、时段、时区上下文。

## 3 存储取舍：复用主库，先用请求内派生结构

现有 SQLCipher 保护整个库，内容另按 CK 密封，遗忘销毁内容密钥。**直接向普通 SQLCipher 表加入正文词项、事实摘要或 embedding，并不能保证原 CK 遗忘时这些内容副本也不可读。** 多来源摘要也不能随意只挂到其中一条来源的 CK。依据见[安全规范](../SECURITY.md)、`soul-store/src/forget.rs` 和 `soul-schema/src/event.rs`。

因此近期选用：

1. 原始证据继续使用已有密封存储、自然键和事务。自然键处理导入身份，不宣称全历史语义去重。
2. 请求内构建词项、类型化值、排序和支持组；保留每个实际依赖来源 ID，结束或失效即清除。已有标题/摘要和正文的用途许可不互相替代。
3. 同一次请求内复用已读取的同 ID 元数据；仍保留完整候选检查，不通过提前截断避开坏数据、来源变更或预算检查。此前查询优化的回归和限制继续保留。
4. 同正文的多个来源只作选材分组，保留全部来源映射；主体、事项、有效时间或来源资格不同的材料不能仅因文本相同合成一个事实。语义相近、相反说法和改口不作破坏性去重。
5. 持久化内容索引/事实缓存后置到规模测量显示有必要时；届时必须复用或扩展既有事务与来源依赖，覆盖更新、遗忘、重启和派生失效，不另建第二份可复活的正文库。

当前不增加 FTS5 或独立向量库。FTS5 trigram 对少于三个 Unicode 字符的全文查询有局限，LIKE 回退也不等于短词检索高效；不能用“换 FTS 就解决中文检索”代替测试。[SQLite 官方说明](https://sqlite.org/fts5.html#the_trigram_tokenizer)

## 4 任务到最终材料的流程

1. **确定任务。** 用户目标、明确必需项、主体、事项和允许范围优先；机器只提出候选需求，区分完成任务必需与可选背景。不能从候选里恰好有什么反推任务还必须知道什么。
2. **检查读取资格。** 复用现有候选上限、来源/CK 存活、精确快照及用途检查。来源无权访问、解析失败、未检索范围都记清原因，不能转成“事实不存在”。
3. **取得候选。** 当前继续用户明确给定的最多 32 条池；未来面向库级召回时，先测词法，再按漏召回类型加入 dense。未来召回不能自动扩大当前授权池或绕过全池检查。
4. **解释关系。** 能可靠解析的显式结构交给代码；自由文本需语义判断时，输出主体、时间范围、条件、例外、支持/反驳关系和精确来源。只保留本次任务需要的字段；解析不了就未确定。
5. **选择支持组。** 把一个结论需要共同出现的来源视作 AND 组，不同完整证明路径视作 OR 替代；先确保必需支持，剩余预算才用于可选背景与多样性。
6. **判断下一动作。** 本次池中有支持但未选入则补选；只有确认任务必需、且在已检查范围内确实缺少材料时才提出针对性澄清。模型犹豫、格式失败、预算不足、无权限不是同一种缺口。
7. **复验最终输入。** 通过现有 ContextSelection、TaskGuard 与 Session 完成准备/派发/完成复验，检查实际序列化后仍保留必要组；再走原有脱敏预览、origin 与单次批准。算法输出不自行成为授权事实，不自动写回长期记忆。

建议语义输出使用已有来源 ID 加请求内片段位置，例如 `need_id / supporting_groups / contradicting_ids / scope / unresolved_reason`。语义模型产生的主体、条件、时间和改口关系也要有可解引用片段。代码校验 ID、边界和引用一致只能证明引用合法，不能证明解释正确。

处理“新说法替代旧说法”时，要先确定同主体、同事项/命题、适用时间和明确修改关系。导入更晚或创建更晚本身不能自动获胜。冲突未解时保留双方出处并澄清，不以相关性分数选一个事实。

## 5 具体算法及候选位置

### 5.1 词法、融合与重排

本仓库研究对照已有字符 bigram BM25，`k1=1.2, b=0.75`；任务 scope/intent/constraints 权重为 1/2/1；精确分组后 MMR 使用 `0.75 relevance - 0.25 Jaccard`。这些是既有研究配置，不是本轮新生产常量，也不声称已调到最优。

中文先保留相邻汉字 bigram、孤字回退 unigram 的路线，英文词和数字/标识符单独保留。需要词级分词时再与 bigram 作配对比较；不默认把所有长度 n-gram 混成等权词袋。Lucene 的 CJKBigramFilter 可作为实现行为参考，无需在 Rust 项目引入 Java。[官方 CJK 分析器](https://lucene.apache.org/core/10_3_0/analysis/common/org/apache/lucene/analysis/cjk/CJKBigramFilter.html)

RRF 只在两个通道确有互补时采用：`score(d) = Σ 1/(k + rank_i(d))`，避免将 BM25、向量余弦和模型概率直接相加。论文中的 60 是其 pilot 选择，不是 Soul 的永久阈值。32 条下它使第一与末位贡献只相差约 1.51 倍，可能稀释很强的第一名；当前先保留，未运行此次 RRF 对照。[RRF 原论文](https://plg.uwaterloo.ca/~gvcormac/cormacksigir09-rrf.pdf)

MMR 用来减少冗余，不能识别真假和适用性。保留规则与例外之后再处理多样性，不能因例外与规则措辞相近而丢弃它。有限候选用普通循环即可，当前没有引入 ANN 的本地证据。[MMR 原论文](https://www.cs.cmu.edu/~jgc/publication/The_Use_MMR_Diversity_Based_LTMIR_1998.pdf)

### 5.2 本轮可执行的支持组选择

在已有机器需求和机器支持映射上，固定以下启发式进行比较；不读取人工真值做选择，不看结果后调权重：

- 按机器需求原顺序，给每个需求选一个完整替代组。优先最少新增来源，其次该组在原排序中的最晚位置，再按组内 ID 排序确定并列。
- 选中组的并集作为 `support_only`；另一候选 `support_plus_initial4` 再并入原排序前四条中尚未入选的来源。其余候选按原顺序追加，保留完整排列。
- 没有支持组记 `mapping_unsatisfied`；超过现有 8 条或真实序列化预算记不可用。不能截断 AND 组、悄悄回退，或把机器没有找到支持当成事实缺失。
- 与相同候选、相同排序上的固定四条、固定八条及已有前缀停止配对比较，分别使用 MMR 与留存语义排序。

这是局部贪心，不保证全局最小集合或最小字节。需求顺序和 OR 组选择可能影响结果；“启发式超预算”不证明不存在可行组合。只有观察到这类具体失败后，再比较有限回溯/一组替换，暂不引入整数规划器。后续可比较按新增实际上下文字节选择，但真实最终序列化才是预算依据。

其价值是把“找不到证据”和“证据在排名第十、被窗口挡住”分开，也能揭露需求过细或映射错误。支持组正确性仍依赖语义解释，不能用代码选择成功代替自然语言准确率。

### 5.4 Jev 保留为有条件的低成本判断候选

Jev 不是无用，也不应默认成为每条材料的必经步骤。适合比较的窄任务是目标主体归属、明确撤回、给定命题的支持/反驳/材料不足，证据从预先列出的片段 ID 中选取。涉及原主张与改口时提供两者上下文，不能为压 token 删掉条件。

2026-10-22 官方资料：`jev-1.13.0` 与 `jev-1.14.0` 均为每百万输入 token 0.042 美元，输出免费；`jev-latest` 当前指 1.13，preview 指 1.14。单请求 64k、单问题 state+question 32k；英文优先，中文需自测。当前确认的是托管接口，本轮没有本地部署证据。[模型文档](https://docs.typesafe.ai/models)

直连接口批量问题共享 state、文档输入计一次，不能将这点误写成每个问题重复收费；拆成多次请求则各自计入。官方示例基于历史 1.12，其速度和倍数不转作 Soul 结果。代理商计价、包装开销以实际 usage/账单为准。[官方并行问题示例](https://docs.typesafe.ai/cookbooks/parallel_questions)

1.13 已公开的短板包括数字、时间比较、多步指代和干扰长上下文。因此明确日期抽取后用代码比较，计数/预算用代码；1.14 是否改善要独立测试，不能继承也不能抹去旧版本结果。[官方能力边界](https://docs.typesafe.ai/model-jaggedness/jev-1.13)

比较三种配置即可：单次通用 LLM、Jev 原子判断、Jev 后仅未可靠解决者升级 LLM。若 Jev 单次成本为 `cJ`，升级率为 `r`，升级子集的实际平均成本为 `cL_upgrade`，则总成本为 `cJ + r*cL_upgrade`。只有同等质量下低于直接 LLM，且延迟/复杂度可接受，才值得级联；升级子集更难，不能用全量平均成本替代。

“模型不确定”与“材料不足”分别记录。原始 confidence、重排分数、RRF 分数不是同一种量，更不是事实正确概率。先报告接受比例与接受样本错误率，再决定是否需要校准；样本少时不拟合复杂校准器。[选择性预测研究](https://jmlr.csail.mit.edu/papers/v11/el-yaniv10a.html)、[置信校准研究](https://proceedings.mlr.press/v70/guo17a.html)

## 6 怎样测试并停止无效尝试

第一步为本轮零新推理重放：复用六任务 × 三种候选条件的原始机器预测，比较取材策略。该组已经用于研究，属于后验机制分析，不能再称盲测，更不能代表中文泛化准确率。旧 q13 结构失败不修复；每种方法分别保留不可用和共同有效分母。

下一有意义的验证点是新中文合成任务，而非继续在这十八例上反复调参。建议构造 24 个独立场景族，每族四种材料状态：完整、必需事实缺失、相互冲突、来源或解释不可用，共 96 例。按场景族拆成开发/校准/留出各 8 族；同义改写、名字替换和时间替换不能跨分区冒充独立样本。覆盖主体错配、明确时间/相对时间、条件例外、改口、跨条 AND 依赖、冗余重复、指令性干扰和预算裁剪。此规模是下一批工程筛选建议，不是生产统计保证。

运行模型前先完成人工可解释标注：任务真必需项、每项可接受来源、不可用理由、正确下一动作。算法输入不得带真值、排除标签或人工优先序。需要模型时统一输出出处与关系，同一输入和最终预算配对；错误 JSON、超时、重试、拒答及预算失效都保留在总分母中。需求生成本身错误、候选召回错误、语义判断错误、选材错误和序列化丢失分别归因。

指标按用途报告，避免合成一个无法解释的“准确率”：

| 问题 | 指标 |
| --- | --- |
| 所需材料是否在候选池 | 必需事实候选召回；独立于最终选材召回 |
| 最终材料是否足够且适用 | 全需求覆盖任务数/总任务数、事实覆盖、错误纳入、规则/例外共同保留、重复占位 |
| 是否错误宣称可以回答 | 错误充分数、错误接受数；另列未确定和预算不可用，不能删掉失败再报高准确率 |
| 是否不必要地询问 | 错误澄清率、确实缺项时具体问题命中率；保留来源不可访问这一原因 |
| 自动判断是否可靠 | 自动接受比例、接受中的错误比例；足量时再报告可靠性分箱、Brier/NLL，不把 0 次错误当 100% 可靠 |
| 全链条成本 | 准备/推理/重试/升级总耗时、冷启动、热运行、峰值 RAM/VRAM、输入/输出 token、实际费用、最终请求字节 |

先比较质量和成本的支配关系：质量更差且更贵的候选移除；差异受样本不足影响时保留最多两个同层候选。若不同错误类型各有胜负，按可观察输入条件提出路由，再用独立留出验证；不能在看完测试答案后替每个案例选赢家。固定四条表现好也不转成全项目固定四条。

模型尚未获安装/调用授权的部分保持待测，不用 mock 分数冒充真实模型效果。本轮可独立完成算法实现、留存预测重放、格式/局部检查和评审；无须为这些可逆研究步骤重复请求许可。外部推理和安装如需开展，届时提供具体候选、数据范围和预算再按既有项目边界处理。

### 根据结果保留与暂缓什么

- **保留支持组选择。** 它能在已有映射可靠时修正窗口遗漏；下一步重点是区分必需项与可选背景、改善缺口判断。未形成完整支持映射时保留原因和现有选材能力，不将新策略设为所有任务的强制前置。
- **保留强排序对照。** 本批语义固定四条已经覆盖全批 39/39；这既反对盲目多取材料，也反对为了停止判断增加没有净收益的模型调用。不能由此把生产统一改成四条。
- **“支持组加前四条”暂不作为首选。** 本批没有增加事实覆盖，MMR 还引入 7 条不适用材料；在未见任务上是否更稳健仍未排除，保留为对照，不默认叠加。
- **保留 BGE/Qwen 两种本地重排器、Jev 与一次通用语义判断的比较位置。** 它们尚未在本机实际推理，不能定出最终模型赢家；RRF、embedding 和持久索引待具体失败/规模证据触发。近期先完善任务必要性与支持组选材，再测模型增益。
