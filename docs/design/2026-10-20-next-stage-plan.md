### 3.1 DATA N1：先验证存储，再考虑产品接线

**责任与路径：** 一名实现者负责测试专用单模块，独立评审者核对数据与遗忘边界。优先评估拟新增 `crates/soul-store/tests/local_ciphertext_repair.rs`；若现有私有连接不可见，则改为在 store 内明确认领的 `#[cfg(test)]` 模块。两种落位只选一种，不为测试暴露公共恢复 API。只读依据为 `crates/soul-store/src/store.rs`、`crates/soul-store/src/forget.rs`、`crates/soul-memory/src/service.rs`、`crates/soul-memory/src/selection.rs` 和 DATA 第 6.9 节。

**输入与产出：** 输入是一条合成、Active、无来源/证据关联的 Memory，以及同一正常读取快照中私有保有的 summary 原字节和完整依赖。先验不持久化、不出 IPC、不写日志或审计，不另保留明文或裸 CK；取消、失效或结束持有期时释放原字节，CK 比较使用既有包装状态。产出仅是测试专用采集/复验/回填流程及其执行证据，不提供生产接口、旧文件导入或持久备份。

- [x] 明确认领测试落位和失败注入点，确认没有生产 API/schema/权限扩展；测试使用临时 SQLCipher 和合成凭据。
- [x] 在同一真实快照正常读取后保有原 ciphertext、nonce、全指针、归属、CK/删除状态及完整 Memory。只保有一个显式目标；不把普通 `BlobStore::open` 的解密成功等同于已有原子采集器。
- [x] 实际构造 ciphertext 单独损坏的正例：复验后只条件 UPDATE 目标 ciphertext，受影响恰为一行，再通过真实 `MemoryStore` / `BlobStore` 读取验证（本片未调用 `soul_memory::read`）。原样和仍可认证的当前载荷均不写。
- [x] 覆盖错误/旧密文、指针/nonce/归属/CK 不符、删除记录矛盾、字段限额和文本约束失败；分别验证非空 `source_event_ids`、非空 `evidence_ids` 在采集及提交阶段都拒绝。读取错误不能伪装为空集合。
- [x] 复用真实 `BEGIN IMMEDIATE` 边界，在复验、UPDATE、提交前注入失败，核对零残留；不导入 CK，不重建指针、不 upsert。
- [x] 用两条真实连接与可控屏障交错编辑、关联集合变化、遗忘和回填，记录实际锁竞争与提交顺序。遗忘先提交则拒绝修复；修复先提交后仍可正常遗忘；重开后已忘 CK/blob 仍缺失。不能用两段顺序 SQL 冒充并发验证。
- [x] 加入无关写入正控制：另一 Memory、独立 profile 或审计追加，不因全库计数/全局 draft revision 变化而误拒目标。本片采用独立 Memory 与其审计追加；比较完整 Memory、原 nonce、归属、CK 和原审计记录均保持，不宣称实测了独立 profile 变化。
- [x] 独立只读评审核对测试确实执行存储/事务行为，随后验证修复，把命令、退出码、实际结果和未覆盖项写回原 DATA 设计。

**本片退出条件：** 上述正反例有真实运行证据，失败传播和最终存储状态一致，独立评审发现已处理；没有生产恢复能力变更。任何关键前提无法由当前边界表达时，记录具体失败及最小下一选择，不通过放宽拒绝条件或加入通用框架完成任务。

**仍不证明：** 未知真实故障能被自动分类、Session 已安全消费确认、进程崩溃窗口、WAL 物理清理、任意历史 ABA、防管理员回滚或跨机恢复。N1 成功不等于 DATA-01 全部成立。

## 4. 平台收尾与正式阶段如何衔接

ACT 文件执行、整库备份/跨机迁移、更多数据入口、行为预测、Android/同步、项目方云和商业付费系统继续按 ROADMAP 排队。本阶段不同时展开这些方向。
