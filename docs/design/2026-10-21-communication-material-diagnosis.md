- 使用真实 Session、临时 SQLCipher 库、固定合成记忆和导入 fixture；端点仅使用现有 loopback `MockLlm`。不读取真实聊天或用户库，不开启采集、不联系参与者，不调用生产模型。
- 只新增 `crates/soulcore/tests/communication_material_probe.rs` 及同名目录下的诊断模块。保留已有 dirty 修改，不改生产逻辑、冻结算法、schema、依赖、锁文件或授权语义，不提交。
- 复用既有 `prepare → begin → execute → complete`、准确计划单次批准和来源复验；本地阅读、本人片段选择、统计纳入及原文豁免分别处理。
- 观察“记录是否被选中、是否进入实际请求”，不把固定 mock 回复或确定性模板当成消息理解、意图服从、人格准确性或沟通效果证据。
- 正常输出仅有固定标签、计数、布尔值和阶段耗时；正文、查询、UUID、库路径、端点及完整请求仅在测试内存中参与断言，不打印。失败断言也不用内容值作 Debug 输出。

## 任务与独立真值

每类任务包括正常匹配、同义改写、反证或事实更新、特定时间请求、真实材料缺失五种变体，共 15 张合成材料卡。每张卡独立写明必要记录、反证/更新记录、无关记录、不可用事实、用户意图及禁止承诺。标签是实验作者的已知条件，不冒充生产程序的语义判断。

| 场景 | 本次目的 | 必须保留的约束 | 不能由统计或缺失推出 |
| --- | --- | --- | --- |
| 协调安排 | 根据已知条件准备安排回复 | 时间更新、尚未确认的条件和既有承诺 | 未找到改期不等于原时间仍有效；不能新增承诺 |
| 边界婉拒 | 温和拒绝且保留明确边界 | 不披露私人原因、不承诺下次；本次明确意图优先 | 历史热情或互动频繁不等于本次愿意参加 |
| 关系跟进 | 核对往来背景并准备合适开场 | 用户明确的联系意愿、相关事实和未知项 | 往来次数不证明好恶、信任或对方愿意继续联系 |

每卡比较三种条件，使用相同已授权材料来源、相同生产选择预算：

1. 人工完整选择：只从同一候选池选出必要记录，无 query；不补答案或额外背景，只作材料诊断参考。
2. 完整候选无 query：保留整个候选池，用于隔离关键词过滤的影响。
3. 完整候选有 query：与第 2 项保持候选一致，调用现有词面筛选。

特定时间卡的三个条件均传相同 `time_specific`，不能给人工条件绕开能力限制。这三卡只测现有能力拒绝，不含具体查询时点，不测事实时间解析；不可用事实数量为 `null`。材料缺失卡则各有一项明确任务要求：准确引用已确认开始时刻、已约定取消截止日、先前项目名。三项事实均未提供，只需核对该事实，已确定的沟通意图和其他部分可继续。

不存在的事实不纳入可召回记录分母；必要记录分母为零时覆盖率及已找数量为 `null`，不得记 100%。任务要求和真值标签仅为诊断注释，没有传给生产选择器。选择 `Context` 不等于回答有充分依据；`Clarify` 只说明实际 API 的结果，不证明程序识别了具体缺失问题。

## 材料传递与本地模板诊断

对每个具有 context 的选择条件，显式允许该次选中的本人材料 ID，再调用真实 `prepare_draft_with_memory`。核对 retained ID、许可 ID 和预览 memory 数据段的完整摘要；没有 context 时 preparation 为 `null`。这些调用只准备、不批准、不执行，loopback 请求数必须为零。它们隔离“未选中”与“选中后丢失”，不验证大材料预算边界。

三类场景各用同一目标和相同 paste、voice，对比未绑定观察与绑定已有合成人物观察，共 3 对、6 个准确批准的 loopback 请求。只改变目标的观察绑定和相应现有材料通道，记录本人目标片段选择与统计许可的差异，不将不同许可形态当成效用优劣。

断言实际捕获的请求：批准前为零、批准后恰一次；固定 system 指令不变，用户材料仍在数据围栏内；目标哨兵是否存在于预期数据段；批准重放不得新增请求。目标记录未进入某个通道，只支持“该通道没有自动携带目标记录”，不能推导用户一定没有通过 paste 提供意图，也不能推导模型一定答错。

另对三类任务分别比较普通本地起草与带记忆的本地起草，核对材料和输出边界。它们是现有本地模板 API 的观察，不扩大为后台自动准备、真实模型或 UI 验证。

## 实际结果（2026-10-21）

最终 `probe-20261021-154751.log`：1 项显式诊断通过，15 张卡 × 3 条件 = 45 个选择观察，分别为 33 Context、9 Clarify、3 Abstain。以下数字是手工构造反例的覆盖计数，不是用户任务准确率或独立统计样本。

| 变体（各含三场景） | 人工必要选择 | 全池无 query | 全池有 query | 本批可支持的结论 |
| --- | --- | --- | --- | --- |
| 正常词面匹配 | 必要 6/6，无关 0 | 必要 6/6，无关 3 | 必要 6/6，无关 0 | 基础匹配与手写真值一致 |
| 同义改写及词面干扰 | 必要 6/6，无关 0 | 必要 6/6，无关 3 | 必要 0/6，无关 3 | 关键词可选中无关记录而漏掉改写材料 |
| 更新／反证 | 必要 6/6，更新 3/3 | 必要 6/6，更新 3/3，无关 3 | 必要 3/6，更新 0/3 | 旧记录命中关键词，更新记录被筛掉 |
| 特定事实时间能力请求 | 3 Clarify | 3 Clarify | 3 Clarify | 现有能力拒绝生效；未测时间理解 |
| 明确事实缺失 | 3 Abstain | 3 Context | 3 Context | 可返回背景材料，不能据此认定任务资料齐全；覆盖率为 null |

33 个 Context 条件都进行了真实准备，累计保留 69 个引用实例，ID 与显式许可集合一致，所有已选摘要完整位于 memory 数据段，未观察到截断；批准、执行及这些准备的请求数均为 0。69 是跨条件累计引用，不是 69 条独立记忆。其余 12 个条件没有准备。材料均很小，不能外推预算上限附近的行为。

三对目标关联诊断的实际请求一致显示：未绑定观察时，明确选择的本人目标及约束进入 memory 数据段；绑定人物观察后走 insight 通道，选中的派生陈述完整进入请求，但目标及约束未随该通道进入，目标仍保存在本地。共 6 次准确批准的 loopback 请求；批准前零请求，重放批准不增加请求，固定指令与材料围栏检查通过。两条通道分别使用本人片段许可和派生统计许可，不能将这个差异直接定性为授权 bug，也不能自动把目标附加到现有统计许可中。

普通本地起草与带记忆本地起草的 3 对输出相同；同一 voice 下三个不同目标的本地模板也相同。这说明这些本地模板调用没有展示目标定制效果，不说明真实模型不能利用材料，也不覆盖后台自动准备或桌面交互。

## 根据证据确定下一批顺序

以下是本批产出的实施建议，尚未实施、未变更产品决定或授权语义。

1. **先打通任务意图与已授权证据的共同准备。** 最小目标是让“用户当前想做什么、禁止承诺什么、选用了哪些证据、还有什么未知”在预览中各自可见，适用于协调、婉拒和跟进。绑定观察不应让用户难以同时表达目标与引用证据；但新增片段必须重新展示并获得相应明确许可，不能借用统计勾选自动放行。先考虑在现有 Session／prepare 路径组合材料，复用现有来源复验和单次批准，不先造通用插件框架、改 schema 或重写评分。验收重点是相同目标在两种绑定状态下都能被用户明确纳入，并且拒绝某类材料时实际请求没有该类材料。
2. **再改材料检索，先保护更新和反证，再比较召回方案。** 现有硬词面筛选已有三类跨场景反例；全池无 query 是可用的诊断参考，但会混入无关材料，不能直接扩成无限全量上下文。下一步先比较有界同源／同事项邻近材料、显式更新关联和词面排序，必要时再比较语义召回加重排。事实新旧、反证和当前用户意图分别保留，不能仅按向量相似度或“最新一条”覆盖。缺少某个必需事实时只标出该事实，允许确定部分继续。下一批使用不同改写、无关干扰、更新措辞及规模，不把本批 15 卡调到通过就宣称泛化成功。
3. **在材料正确的完整链路上做性能与成本取舍。** 延续已有优化的负例，测候选获取／选择／准备／人物展示分段，并补总延迟与内存；随机或交错执行、重复测量，按相同材料完整度比较。优先修复此前独有证据／小规模路径的回退，再考虑缓存、索引或语义模型。若相同证据质量下增加检索步骤，只在实际耗时与收益支持时保留；本轮没有生产模型费用、真人节时或自然 p95 结论。

这个顺序优先修复三个场景共享的材料组织和选择机制，避免各建一套场景流程。短期可保留明确的人工材料选择作为对照和可控路径，但不把人工找到答案的能力归功于自动检索。更换大模型、增加多 agent、全量图谱或持久向量库暂不优先：本轮已定位到模型之前的缺口，它们各自能否改善净效果仍需单独测量。

第一项的静态落点已定向核对：[assistance 分流](../../crates/soulcore/src/commands/session_assistance.rs)、[insight 生命周期](../../crates/soulcore/src/commands/session_insight.rs)、[请求组合与预算](../../crates/soulcore/src/commands/draft.rs)、[桌面调用接口](../../apps/desktop/src/core.ts)。最小候选是将“本次明确提供的沟通意图”作为独立有界输入，与 insight 进入同一个准备快照；不能简单串调现有 memory/insight 准备，因为两路 pending 会互相清除。优先验证当次输入，若预填保存的目标，则必须增加明确纳入选择并保持精确来源复验。意图里的第三人内容仍需分类脱敏，不因字段名称而当作本人内容；paste 原文豁免不扩展到意图。修改意图后旧准备失效、取消拒绝、统计关闭、超限拒绝及预览／实际请求一致是这片改动的必要回归。以上可行性来自静态代码分析，未实现或运行候选。
