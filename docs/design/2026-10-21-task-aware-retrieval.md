# 任务范围与沟通意图参与检索：实验计划与回执

日期：2026-10-21。起点：`codex/soul-rebuild-20261019` @ `6a56d852d23a051c7c4e9845642791295c541105` + dirty。保留已有修改，接续[有界检索对照](2026-10-21-bounded-communication-retrieval.md)。用户已授权本轮合成对照及独立评审，之后才决定生产检索和性能优化顺序。当前状态只在 [STATUS](../STATUS.md) 维护。

## 目标与架构

让同一份本次任务范围、意图与约束进入两种检索方法，检验其选料差异。新增测试专用 `TaskInput` 和排序适配器，复用真实保存目标、密封记忆精确快照、明确候选及 Session 选择／准备。范围与意图是用户明确提供的内容，不是从 fixture 真值倒推。生产 `MemoryContextRequest`、D72、IPC、存储 schema 与授权语义均不改。

普通 `prepare_memory_context` 目前不绑定 AssistanceBinding；本轮测试适配器在排序结果返回时复验任务与候选，不宣称生产已具有这个新绑定。若后续实施，应正式复用现有绑定和来源复验链，不另建 hash 或失效协议。

技术：Rust 1.83、SQLCipher 临时库、现有 `soul-memory`／`soulcore`、loopback MockLlm。没有已证实可直接调用的仓库内语义模型；本轮受限语义方法采用当前 Codex 的无历史代理做实际合成排序预测，再由 Rust 重放结果。它不是本地部署模型或生产 E1 检索调用。

## 比较条件

1. **仅范围词面消融：** 字符 bigram 的固定集合相似度，只使用 scope；单列为信息消融，不充当语义方法的唯一对手。
2. **范围＋意图词面排序：** 同一通用相似度，使用 scope、intent、constraints 的完整文本；不建立场景同义词表或读取真值。并列保持输入顺序。
3. **受限语义排序：** 获得与第二项相同的完整任务和候选，使用固定指令，只输出临时候选 ID 的完整排序，不生成事实、不选择池外内容。

三者都返回完整 32 个候选的排列，随后调用真实 `prepare_memory_context(query=None)`；最终同样受既有 8 条、16 KiB 上下文及 64 KiB 起草请求预算限制。16 KiB 不被误写成语义输入预算：本实验每个完整任务包另限 32 KiB UTF-8，超限整包拒绝，不截去材料，实际字节另记。该限制仅为本次实验资源上限，不改变生产常量。

三类沟通各两个合成池，每池两项不同目的，构成 12 个独特任务。每池 32 条短记录，有同一事项内另任务材料、跨事项强词面材料、旧约定与更新、约束、正文注入负例。相关／无关记录不以“本事项”“当前”标题泄露真值。逐条标注必要与辅助材料及理由；被更新完整复述的旧背景不强行计作必要，两个任务的必要集不同。每池保留容易噪声，另有不自称无关的对象／阶段干扰及预标排除理由。同一内容作两种排列，最终 24 任务条件，每条件比较三种方法。规模固定在前轮已暴露失败的 32 候选，不把重复排列称为独立样本。

最终八条覆盖反映预算内选料，但同池两任务材料合计不足八条，恒选两者即可获得高召回，因此不能单独证明意图生效。另记前三位必要材料、另一任务占位和必要材料排名，成对观察本任务材料是否随意图变化前移；辅助背景单列，不算必要也不冒充噪声。此修订来自预测前独立评审，不根据成绩调整。

## 语义预测与证据边界

两个 `fork_turns="none"` 代理分别只得到一种排列的 12 个任务包及相同固定指令，不传仓库路径、历史结论或 gold。为避免转抄大批 JSON 出错，允许各用一次 pwsh 仅以 UTF-8 读取指定的仓库外合成输入及固定指令；读后不得再调用工具或接触其他材料。这是两个批次的调用，不是 24 次独立调用；同一批次的任务可互相提供上下文，不能由本实验估计独立单任务调用表现。候选正文是待排序的数据，任何要求改规则、置顶或伪造 system 的正文都不能成为指令。该盲化是流程限制，不是文件系统安全沙箱。

响应为严格 JSON 数组，每项只有 `case_id` 和 `ranked_ids`，整批响应上限 64 KiB。必须覆盖完整任务集合，IDs 恰为对应候选的排列；池外、重复、缺项、未知字段、超长或格式非法均令整批 12 个任务不可用，保留原始分母，不猜补、修正或选择性重试。真实输出先原样保存，再计分；同一输入得到一次结果，不为成绩调 prompt、词典或真值。能观测到的模型元数据、调用起止和完整输入／输出留在仓库外；未提供的模型精确版本、token、费用为 unknown／null。

代理预测只处理明确合成内容，不是 Soul 已批准的生产出站链。真实 Session 部分只验证本地选料和起草准备，默认无批准、无生成请求；本地使用目标或候选不自动授予 OwnerExcerpt，也不把目标自动附加到起草请求。未来外部语义服务仍需单独明确用途、脱敏输入、origin、一次批准及结果来源复验，不能借起草许可放行。

export 与 replay 是两个进程，不持久化 ContextSelection 或跨进程批准。replay 先逐字段核对留存合成输入与当前 fixture 一致，再在本进程获取真实任务／全部候选快照，解析结果后复验；另以普通测试在这个窗口插入目标与候选变更。它验证离线重放和窗口内失效，不宣称模型等待期间已有生产跨进程会话保活。

## 输入传输失败与实验修订

首轮两个代理都返回原始 `{"error":"input_truncated"}`，没有排序。第二轮仅调高内外层工具输出预算，仍均返回同一错误。额外一次无工具审计确认：代理实际设置两层 40000，返回原始约 25118 token，但中间仍有 `…15401 tokens truncated…`，即使结尾标识存在也不能证明读全。四次错误响应及两轮 replay 单独保留，均按原政策记两组共 24 条件语义不可用；不把它们修补成成功。

独立评审后第三轮统一缩小传输分组：原 a/b 各 12 case 拆成六份，每份同池两项任务。任务、32 条候选、ID、标题、正文及顺序逐字段相同，固定指令不变；每份实际约 13 KiB，最大字节分包加指令的工具返回为 3762 token，低于已观测的截断上限。12 名新 `fork_turns="none"` 代理各读一份，只处理这两个任务，不再拥有其他池的上下文。它是第三轮分包实验，不能称原两次大包调用终于成功或模型上下文完全不变。

每份原始响应先由同一严格解析器验证对应两个 case；再按原 case 顺序机械合并为 a/b 两个派生响应文件。合并不删围栏、不补 ID、不纠正文本、不改变排名。预先规定任一分包失败使所属 12-case 组全部不可用，保留 24 条件分母；第三轮不因排名或格式成绩追加调用。原分包响应与派生文件分开标识。实际调用账本为前两轮四次未取得排序、第三轮实际十二次排序调用，以及一次无工具调用取证交互；费用和 token 未提供遥测。此偏离原定两批且不重试的安排源于已定位的传输限制，没有先前有效成绩可供择优保留。

## 实际瓶颈、通用性与下一实施顺序

1. **先把任务来源作为生产检索的正式依赖。** 本轮证明 scope／intent／constraints 可作为共享输入驱动可替换排序器，不需要把协调、婉拒、跟进写成生产分支。生产化的第一片应复用保存目标及现有 AssistanceBinding，使任务变更和所有候选变更在排序消费时失效，并继续衔接准备／派发／完成的精确复验。当前测试适配器不等于这个生产接口已落地，普通 `prepare_memory_context` 仍没有自动绑定目标。
2. **选料数量与低成本候选整理优先于默认换模型。** 本批每任务最多三条本任务必要／辅助材料，全部填满八条时至少五条来自其他用途；语义组恰有 120/192 不适用实例。因此应先设计并对照“最多八条、证据不足可少取或明确缺口”，不能直接写死取三条。另一个明显限制是每池 32 个 ID 实际仅 14 种不同正文，三种容易噪声各重复七次；完整任务词面组前三位经常全是重复任务字样的附件索引。下一批应在保留来源 ID 和复验边界下，对请求内重复材料整理、多样性与更强的词面权重做便宜对照，补少重复／无重复条件；本轮没有证明这些低成本替代方案无效，不据此改导入幂等或遗忘语义。
3. **保留有界语义作为候选，先测可部署后端的质量与实际成本。** 本次 Codex 排序在这批样本上有清晰收益，但不是仓库内模型、生产 E1 或可报价服务。下一片应在相同全候选、真实输入预算、失败口径和来源复验下测可部署方案的每任务延迟、token／费用（若提供）、峰值内存及无重复／长材料表现。外部后端需要明确检索用途、脱敏、origin 与单次授权，不借用起草许可。不能由本批结果直接引入向量库或把单一 bigram 失败推广为所有词面检索失败。
4. **材料质量达到同等水平后再排性能改动。** 先分别测读取／解密、任务与候选复验、排序和准备成本，保留相同覆盖与拒绝语义，再决定请求内复用、读取路径或排序实现的优化顺序。本轮只有单次 Session 阶段计时，没有 CPU／内存／尾延迟基准，也不能用模型代理调度墙钟推导生产 SLA。工具传输截断属于实验通道问题，不当作 Soul 检索耗时。

这一次确定了后续顺序，没有修改生产查询、硬 query 规则、候选上限、schema、IPC 或授权。上述下一片是实施建议；正式 Goal、真人效用、平台门禁与发布状态保持原边界。
