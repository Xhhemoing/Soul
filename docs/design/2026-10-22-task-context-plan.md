## 4 任务输入及处理语义

H，候选设计：请求内任务描述需要表达任务目的、收件主体的稳定引用、明确约束、任务时间语义、用户本次选择的候选，以及可用的已确认分组。它不新增权限。来源快照、当前修订与许可由受信 Session 取得，不能接受模型或导入 JSON 自报的 granted、authority 或版本作为授权依据。

处理顺序为：受信入口绑定本次任务与候选；执行既有隐私及来源资格检查；在合格材料内排序；保留已知规则与例外的完整组；用最终实际请求计算预算；判断本次可回答范围；生成有界诊断或澄清提案。派发和回复接收继续复验任务及来源，旧结果不能写回新任务。

| 诊断类别 | 可支持的事实 | 允许的下一步 |
| --- | --- | --- |
| 当前窗口遗漏 | 已检查的获准池中有必要材料，但未保留 | 在本次授权范围内补取并重新准备 |
| 池内缺失 | 在已检查范围未找到会改变回复的必要信息 | 提出针对该缺口的问题；不声称全库不存在 |
| 冲突或过期 | 有具体来源支持冲突或时间不适用 | 显示最少必要差异，等待确认或保守起草 |
| 权限或来源不可用 | 许可不足、撤销、遗忘、快照失效 | 中止相关准备；不以换算法或退回 W2 绕过 |
| 机器要求过细 | 原要求不足以证明本次回复需要该细节 | 撤掉机器附加要求，或明确判断未知 |
| 结构或执行失败 | 解析、模式或执行不可用 | 保留失败；按预先规定选择无越权的回退 |

类别是诊断解释，不强制一任务只能有一种；冲突、权限和结构失败可能同时出现。不能仅因预算耗尽、groups 为空或没有命中，就宣称真实事实缺失。系统无法可靠区分时返回“未确定”，不能伪造精确类别。

现有 Context 表示选出了材料，不证明足以完成任务。候选设计应分开表达“选择结果”“材料充分程度”“建议动作”；不急于把全部含义塞进既有三值枚举。

确认也分层：用户确认记录内容、确认机器解释、确认本次适用、批准某次出网是不同动作。无需机械增加四个弹窗，但一个界面的文字必须准确说明正在确认哪件事，不能以较窄确认推导更宽许可。

## 5 下一项合成研究的可执行规格

H，建议第一项工作：在新的未见任务中比较缺口诊断、范围内补取和澄清。先只改测试与相关设计回执；使用合成 fixtures、临时加密库、现有 Harness 和真实 prepare 路径；不批准生成请求，不修改生产默认、schema 或冻结算法。

样本设计提案为六类诊断各四个独立任务，共 24 个基础任务；每类两个开发任务、两个留出任务。每任务保留原始、重排、干扰项三个条件，共 72 条件；所有变体跟随基础任务留在同一分区。24 是初始工程预算，不是效能保证或产品门槛。先登记分区与规则，再读留出结果；不能根据结果重写题目或选择性补样本。类别标签和答案不能编码在运行可见 ID 中。

研究分两层，分别报告。第一层是机制单测，用用户明确提供的结构化任务约束和分组验证规则、预算与生命周期；这些内容在实际用户流程也必须可见，不能把人工答案伪装成输入。第二层才是上述 24 任务矩阵，输入原始合成自然语言，测试候选规则能否识别必要缺口；不支持的判断允许未知。单测数量不计入任务数，第一层的正确率不能宣传成第二层的自然语言理解能力。

运行输入仅含本次任务、获准候选文本、合法可见元数据和显式确认。人工必要事实、接受答案、诊断真值、正确操作及预设澄清答案只在评分侧，不能作为排序器或诊断器输入。未知支持关系不能由 gold 补齐。

比较四种策略：固定四条 K4、固定八条 K8、四条加诊断 D4、四条加诊断及一次动作 D4A。初始本地排序保留 BM25 加精确重复分组加 MMR；四策略初始任务、候选池和准备上限相同。精确重复分组只去除相同正文占位，不等于规则与例外的语义分组。本地矩阵为 72 条件乘四策略共 288 行，其中留出 144 行；开发与留出分开报告。

D4 与 D4A 都从同一排序的前四条开始，诊断器可查看完整的本次获准有界候选池，因而必须计入全池读取与判断成本，不能声称只看前四条。两策略共用同一份原始诊断输出，D4 只报告诊断、不补取也不释放答复；D4A 才执行一次动作。诊断结果必须包含状态、理由、支持来源或未确定原因；判断条件不支持、解析失败或无法说明必要性时输出未知，不把未知转换成澄清。

执行切片先在开发半集完成候选诊断器 D0 的规则表、伪代码和失败例，再把它与普通机制测试一起提交独立只读检查，随后原样运行留出半集。D0 不在本报告里被宣称已经存在：若只能识别结构化约束或输出未知，这就是本地能力限制，必须如实记入结果；不能由评分器替它补齐语义。不得在看留出成绩后换规则而继续使用原留出名义。

D4A 的补取只消费诊断器预测的必要支持组，不读取评分真值。对合法组按组内最早原始排名、再按排序后 ID 序列确定顺序；选第一个能整体满足真实请求预算的组，先保留该完整组，再按原始排名补入原前四条中剩余材料，不从其他组继续补选，最终不超过既有八条与字节上限。不截断组，全部组都不适配时记预算不足，不自动改为提问。预测组含池外、不可读或失效来源时拒绝本次动作。此处的重排与整体组提交是拟扩展 adapter 的行为，现有前缀 helper 不能直接冒充已经支持。

受限语义排序保留为第二排序对手，但新任务不能冒用旧任务排名；需要另有获准的预测来源后才运行。未获准时该分支写 NOT RUN，研究结论仅覆盖本地方法，不声称已经完成双排序比较。不为凑对照自行调用外部模型。

任务类型、排序和候选数固定后，真实 prepare 记录实际 retained IDs 和 encoded_bytes，评分在实际保留材料上进行。接口或序列化结构失败必须作为不可用保留，不能换成空结果算成功。诊断阶段的来源/权限失败与语义失败分别记录，不因回退而抹掉原失败。

D4A 若选择澄清，只生成一条问题，本次不再补取。澄清前结果参加四策略同输入比较；澄清后单列额外信息实验，只使用题目预先登记的合成答复。由独立评分侧核对问题是否问中了该事实后释放对应答复，未匹配不能注入通用完美答案。记录释放与实际消费是否发生，输入增量、总准备次数和成本；不能把新增事实收益记作纯排序收益。后续准备最多使用原四条和该答复，仍遵守相同最终预算。它只能验证后续准备与内容约束，不证明用户愿意回答或最终生成回复更好。

复用路径：`crates/soulcore/tests/task_retrieval_probe/adapter.rs` 的 Harness、`retrieval_controls_probe` 的词面排序、`evidence_stopping_probe` 的前缀准备与严格输入检查。拟新增单独 `task_gap_probe` 测试目标；不得把测试评分类型引用到生产模块。精确修改路径由执行时认领，一个写者维护共用 adapter。

本切片完成条件是：四策略在同一已登记输入上有完整成功或失败记录；gold 与运行输入隔离可检查；反例覆盖、来源复验与拒绝时零出站有实际证据；独立评审能从原始结果复算指标。算法未胜出也可以完成实验；是否推进生产另由证据决定。

## 6 指标和实验决策

| 指标 | 分母及解释 | 不能替代什么 |
| --- | --- | --- |
| 必要事实覆盖 | 各策略实际保留的必要事实数除以该条件可评分必要事实总数；按基础任务配对 | 最终回复正确率 |
| 错误充分声明 | 宣称充分且漏必要事实的任务数除以全部宣称充分的任务数；另报总任务数 | 未宣称充分不等于任务成功 |
| 必要缺口漏报 | 未报告的真实必要缺口任务数除以含必要缺口的任务数 | 不与普通召回率混算 |
| 不必要澄清 | 评分认为无需问却发出问题的任务数；同时报占全部任务和全部澄清的比例 | 少问不等于问得对 |
| 补取收益 | 新增必要事实与新增无关材料、请求字节、准备次数同时报告 | 只报新增条数 |
| 不可用与失败 | 所有分配条件均入流程分母；未知、失败、拒绝、降级分别计数 | 不填零、不只统计成功记录 |
| 总成本 | 排序、诊断、补取、重试、生成分段耗时与调用数；可得时加 token、缓存及费用 | 最终 prompt 字节不等于总成本 |

同一任务的重排和重复变体单列鲁棒性，不冒充新增独立任务。历史固定四条表现好属于看结果后发现，必须在新留出任务验证。不给小样本设一个漂亮但无依据的总体通过率。

建议继续投入的依据是：新增机制在留出任务有可解释的缺口识别或补取收益，且把额外澄清、失败和总成本一起报告。收益不清或数据不足则写不确定，保留简单对手；不切换默认。越权、失效来源继续使用或正文进入审计属于既有正确性要求，不能被平均效用抵消。

真实使用按 ROADMAP 与 VAL-01 的实际允许范围另行安排。原 A 为 neutral，B 为 from_view，C 为预先固定手工语气；三者进行成对盲评。若研究“完整档案、仅语气、语气加相关偏好”，采用新的比较名称，保持现状对照和主要比较清晰，不套用原 AB 的 60%。

编辑负担与事实错误分别比较，不能写成“二者之一不劣即可”。保留未完成、破盲、缺测、失败及不可比较样本；编辑时间只在双方完成且计时有效的配对计算。20 条作者任务可用于发现流程和成本问题，不足以仅凭数量证明非劣。真实观察不自动写入当前研究留存 ZIP，也不扩大 D107 的窄字段许可。

## 7 请求内编译与观测的最小落点

H：只有第 5 节给出足够的语义依据后，才细化生产候选。首版先不改数据库。规则与例外必须来自用户可见的显式分组或已有可信结构；模型推断只能提出分组，不能静默作为事实依赖。预算以真实脱敏和序列化后的请求复核，组过大时整组不进入，不截断否定、例外或出处。

任务目标与候选来源绑定沿用 Session 的 held、pending、preparation 和完成复验模式。新 task input 改变、分组改变或来源变化，都必须使对应旧准备不可再用。用途许可独立于 confirmed；本人目标的选择不从统计或起草许可自动推导。

缓存字段按供应商和 API 类型归一化。Chat Completions 的 `prompt_tokens_details.cached_tokens` 与 DeepSeek 的 `prompt_cache_hit_tokens` 若同时出现，作为别名处理，不能相加；冲突记数据异常。明确支持范围，不顺手增加 Responses、流式或新出口协议。模型版本、输入输出 token、缓存、分段耗时、失败和重试未知则记未知；不要为命中缓存故意填充提示词。

## 8 适用条件持久化的候选语义

H：仅考虑 Preference 与 Commitment，其他类型维持现状。首先通过第 5 至 7 节确认哪些结构确实被任务消费，再决定 JSON 数据契约、密封内容或关系表的具体落点。下面是应能表达的语义，不是冻结 schema 或新增数据库契约。

| 语义 | 首版需要回答的问题 |
| --- | --- |
| 主体与范围 | 主体是哪个稳定对象；同名不能合并；条件范围由用户如何确认 |
| 条件与例外 | 条件是可判断结构还是自然语言说明；未知条件不得当作满足；例外与主规则是否必须共同使用 |
| 有效时间 | 区分未知开始、未知结束、明确无结束；不把 null 同时当未知和无限 |
| 记录与获知时间 | 记录创建、事实发生、用户确认是不同时间；不得由 UUID 或导入日期推导事实时间 |
| 改口与冲突 | supersedes 只表示明确替代；不同范围不自动互相替代；冲突键的主体、属性、范围由谁确定 |
| 确认状态 | 机器候选、人工确认及其版本是什么；确认不是用途许可，内容修改后旧确认不得静默沿用 |
| 来源与依赖 | 引用是否可解引用、可读、同用途；依赖变化如何使本次准备失效 |

首版可明确不支持“在过去某时刻已知的信息下如何回答”的历史重放；如要支持，必须另定义知识截止和双时间行为，不能只靠 valid_from/valid_to 宣称完整算法三。条件语言暂不做通用逻辑引擎；无法判断时保留未知或请求确认。

依赖处理建议：拒绝自引用和环；限制在本次获准、可解析的有界依赖范围；禁止因被遗忘的替代条目消失而静默复活旧规则。新增依赖需要覆盖准备、派发、完成三个时点。跨主体、候选引用已确认条目、来源撤权和例外不可读应有显式结果。具体限制值和存储布局在实施设计中依据现有上限与真实成本确定，不在本文另造算法常量。

老记录缺少 applicability 时保持其原有读取语义，不能批量标记为已确认，也不能伪造时间或引用。新编译路径无法获得必要条件时给出未确定或使用原有明确手工选择；不会把老记录假装成满足新语义的完整对象。需在实施前决定如何向用户区分这两类能力。

内容与适用条件按实际存储落点纳入既有 CK 生命周期，审计只存必要元数据。事务失败回滚、禁用新功能、旧程序打开新版库必须分别说明；不承诺恢复旧备份或数据库降级，因为它们可能破坏遗忘与审计状态。生产迁移和失效语义须形成明确决定后才实施。

## 9 后续提案与用户操作

H：FollowUpProposal 首版只保留两类：从当前草稿提出“建立事项”的建议；从必要缺口提出一条确认问题。默认不生效，不自动发送、不自动改变事实或开启提醒。

采用或复制草稿只构成提案触发信号，不证明已经发送、承诺成立或条件满足。用户需确认主体、内容、条件和可选截止时间。例：“如果经理批准，我明天发”应保留条件；“我不能保证周五交付”不能直接变成周五截止；“他说下周给你”不能生成本人的承诺。

截止时间允许为空。只有用户明确给定时间时才解析并确认绝对时间与偏移，不从旧语料推断。“明天”一类相对表达应在实际确认时显示解析结果，避免跨日歧义。提醒仍复用现有独立入口和明确未来时间规则，建立事项不自动提醒。

待确认提案绑定来源及对象版本，来源变化使其过期，用户须重新检查。已经确认建立的独立目标按 D97 处理：来源失效不自动删除独立承诺正文；不得把提案的临时生命周期覆盖到已创建对象上。

澄清回答默认只服务当前任务。用户另行选择保存时，明确是改口、增加例外、补录历史还是仅本次适用，并核对原对象版本；不默认覆盖整条记忆。重复点击确认复用现有主键、唯一性及事务/CAS机制防止重复创建，不新增自制授权凭证。
