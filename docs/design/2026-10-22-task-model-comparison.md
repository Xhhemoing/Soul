## 实现与验收口径

- [合成材料](../../fixtures/synthetic-task-context/README.md)：24 个 family，各有 complete/missing/conflict/unavailable 四变体，共 96 case；开发、校准、留出各 8 family/32 case。同 family 不跨 split。每 case 4 个预先给定信息选项、12 条候选。此次验证的是候选选项中的必要性识别，不是无约束生成所有需求。
- [Rust probe](../../crates/soulcore/tests/task_requirements_probe.rs)：严格验证模型判断，区别 supported/missing/conflict/unknown；必要项全部获支持才复用既有 AND/OR 组选材。可选项缺失不阻断任务。固定四/八条只作排序与证据覆盖对照，不算诊断模型。
- [实际模型 runner](../../scripts/task-model-probe.py)：模型只读 input，不读 family/split/variant/gold；原始响应、失败、用量和延迟全部留存。无自动重试，不修复模型 JSON。Jev 状态与支持选择不一致仍由严格校验拒绝，不能因其多发生在 optional 项就删除失败。
- `all_options` 使用同次模型实际评估的四项 assessment，`predicted_required` 仅使用其选定必需项。两者可比较动作、过度澄清和材料成本；`all_options` 按定义把四项都当必需，其必要性精确匹配分数不是模型能力比较。
- 诊断正确要求必要项集合、各项状态及充分证据都正确；冲突证据也使用组内 AND/组间 OR。实际准备后的完整证据覆盖另行计分。诊断可用不等于创建了 context。

评分器仅在运行结果形成后读取 gold。不可读变体是显式可读性占位信息，不能称为真实文件或数据库损坏复现；普通测试另覆盖真实来源遗忘后拒绝与 16 KiB 准备预算丢失。四变体相关，不能把 96 case 说成 96 个独立任务或真人效果。

## 项目采用建议与交付边界

本轮支持继续沿用“**本地筛候选 → 一次受限语义判断必需项、缺口和证据 → 程序校验 → 完整支持组选材 → 来源与字节预算复验**”。先识别会影响任务的必需信息，再保留足以支撑它的来源组；缺失、冲突和不可用进入具体澄清，不把相关性分数直接当成事实成立概率。

在此次服务与合成任务上，Sol 更适合作为下一阶段准确率优先的候选：没有错误充分，全部下一动作正确，观察延迟没有更高；其正式请求费用约为 Luna 的 19.36 倍，平均约 $0.005775/任务。Luna 保留为低成本对照，平均约 $0.000298/任务。这个结果不足以定生产最优模型或设计自动双模型路由，尤其留出差异含有标注边界。用户指定后续只用 GPT-6，Jev 仅保留已完成对照及失败，不继续追加其他模型测试。

此次新增的是合成材料、研究 runner、校验/重放测试与结果文档。复用既有 Session、BM25/分组/MMR 和支持组选择，不新增生产向量库、索引、schema、哈希或常驻模型服务。原有加密存储、来源引用和内容密钥边界沿用；本次结构化判断在请求内使用。此前已交付的显式字段轻量能力保持，本轮通用语义判断 **尚未接入产品交互或生产默认**，不宣称各类数据处理已经全面完善。

本轮可交作者验收的是研究切片及其可复查证据；无剩余实验运行阻塞。后续若推进产品，应先在新一批合成材料中补足“不可读来源与具体需求”的可见关联，并把有效替代证据纳入标注，再验证来源绑定与交互。此次按授权范围收口，不继续扩模型、调参或运行完整平台门禁。

## 各类算法的职责、适用场景与成本

这些方法处于不同阶段，不能拿同一“准确率”直接替代彼此。检索找到候选，重排改变候选顺序，语义判断解释必要性和证据，支持组选材把判断落实为上下文，程序核对维护结构、来源及预算。RAG 是检索与生成的组合流程，既可用词面召回也可用向量召回，不是一种单独评分算法；原始研究使用参数模型与非参数检索记忆相结合。[RAG 原论文](https://arxiv.org/abs/2005.11401)

| 方法 | 在 Soul 中适合负责什么 | 本机速度与测量状态 | 成本与限制 |
| --- | --- | --- | --- |
| 规则、类型、集合与结构校验 | 明确字段、ID、日期数字、授权、预算、来源快照的精确核对；结构明确时直接计算 | 此次 input_validation 暖均值中位 **0.0214 ms**；不是全部产品规则的耗时 | 无新增模型 API 费，有 CPU/内存成本；不能自动解释任意自然语言指代与适用条件 |
| 字符 bigram BM25 | 按任务与标题/摘要的字面相关程度排序，适合精确名称、编号及词面有重合的候选 | 每池 12 候选，**0.1835 ms** | 无新增 API 费；同义改写可能漏召回，不判断冲突或信息是否足够 |
| 精确分组 | 标题和摘要完全相同的候选先排代表，将重复项移到完整排列后部，减少重复占位 | 分组本身 **0.00148 ms**；BM25+分组整体 **0.1823 ms** | 无新增 API 费；不删除来源，不等于语义去重，也不证明适用对象相同；两次排名时间的小差异不是确定加速 |
| MMR | 结合相关性和相似度惩罚，防止相似材料占满候选名额 | BM25+分组+MMR 整体 **1.2955 ms** | 无新增 API 费；可能压低“规则+例外”中的必要条目，不能靠多样性保证事实完整 |
| 完整支持组选材 | 每个必需信息保留一个完整 AND 证据组，OR 组是替代路径，尽量复用共享来源 | 含输入/预测/排序校验 **0.0749 ms**；只测既有 Sol 判断 ready 的 24 case | 无新增 API 费；依赖正确语义映射；当前是顺序贪心，不保证全局最少字节或来源 |
| embedding / 向量召回 | 大库中从大量材料找到同义、跨措辞候选，适合词面召回不足时研究 | 本轮未推理，无本机延迟、显存或索引规模实测 | 本地计算或托管 embedding 费、索引存储和更新/遗忘维护成本；召回分数不代表事实成立 |
| BGE / Qwen reranker | 对已召回的小批候选重新评估任务相关性 | 本轮未推理，不提供推测毫秒数；作者指定只测 GPT 后已停止下载 | 本地 CPU/GPU/内存成本或服务费；不能替代任务必要性、冲突和来源合法性判断 |
| Jev | 把必要性、支持/冲突等拆成受限语义问题；适合研究快速原子判断 | 已完成两版各 96 请求，中位约 **1.00–1.01 s**；1.14 最慢样本 30.22 s 保留 | 本批每任务约 **$0.000571**，按 usage×公开单价；错误充分仍有 6/96、8/96，不能仅凭速度自动继续 |
| 通用 LLM（GPT） | 一次输出必需项、缺口、跨条证据和冲突；用于自由文本的受限语义判断 | 各候选真实 API 延迟/费用见模型表；生产默认尚未接入 | 当前中转按单请求消费增量统计；仍可能解释错，程序校验合法引用也不能证明语义正确 |
| RAG 组合流程 | 将上述召回、选材与依据材料的生成接起来 | 没有独立固定耗时；取决于各阶段及串并行方式 | 总成本取决于召回、重排、判断和生成，不能把“用了 RAG”理解为无需 LLM 或天然更准 |

BGE 官方说明其 reranker 读取 query 与 passage 并输出相关分数；Qwen3-Reranker-0.6B 模型卡也将其定义为 Text Reranking。两者的公开基准不作为 Soul 本机性能或事实正确性证据。[BGE 模型卡](https://huggingface.co/BAAI/bge-reranker-v2-m3)、[Qwen 模型卡](https://huggingface.co/Qwen/Qwen3-Reranker-0.6B)于此次通过 agent-reach 的网页读取路径核对。

此次本地阶段测量入口为 [timing.rs](../../crates/soulcore/tests/task_requirements_probe/timing.rs)，原始数据 `gpt-6-sol/local-stage-timings.jsonl` 共 504 行、汇总 `local-stage-summary.json`。每个 case/阶段记录首次调用与后续 10 次均值，表中是这些 **case 均值的中位数**；前五阶段各 96 case，支持组选材 24 case。Rust 使用现有 test profile（opt-level=1），不是 release 或进程冷启动。模式顺序按 case 轮换，文件读取、建库、网络、模型与 gold 评分均在计时外。BM25 调用内部本就计算分组，各排名模式是完整路径，不能把表中耗时相加当端到端时间。

已有 Sol 重放的真实 Session 局部运行中位数另为：支持组选材后准备 3.684 ms（24 case），固定四条准备 4.240 ms、固定八条准备 5.258 ms（各 96 case）。此处包含来源检查、Session 准备和探针断言，排除候选排序、临时库创建、预测文件读取和模型调用；这些不同准备分母不用于证明性能优劣，只说明测量层次。CPU、电耗、冷启动及大库扩展成本尚未量化，“无新增 API 费”不等于免费。

当前最小组合仍为：**资格/来源检查 → 显式候选池 → 必要时 BM25/分组/MMR → 一次受限语义判断 → 程序校验 → 完整支持组选材 → 最终来源与字节复验**。已明确字段优先直接计算；面对当前 12 条候选且模型已经看过全池的场景，额外 embedding 或 reranker 必须先证明新增收益。若今后大库词面召回明显漏掉同义材料，再比较混合召回与单一重排器，不预先叠加所有方法。
