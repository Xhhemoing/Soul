# 来源元数据与全新合成任务复测

本轮承接[任务与模型比较](2026-10-22-task-model-comparison.md)的两个标注限制：不可读来源未明确关联任务需求，以及 gold 漏列有效替代证据。作者授权补足材料、用全新合成任务复测 GPT-6 Sol、GPT-6.1 Sol、Luna，费用继续计入累计 $5 上限；不新增生产默认、向量库或模型路由。

起点为 `codex/soul-rebuild-20261019` @ `6a56d852d23a051c7c4e9845642791295c541105` 的 dirty 工作区。此前实验累计 $1.375498928，旧原始输入、预测、失败、评分和费用记录保留。只使用人工合成输入、临时加密测试库；凭据仅用于指定服务的调用进程，不写入仓库或实验结果。

## 本轮范围与预定评价

- 新材料：[synthetic-task-context-v2](../../fixtures/synthetic-task-context-v2/README.md)，12 个新场景，每场景六变体，共 72 case；每例 8 候选、4 预设信息选项。整批 `split=fresh`，不使用模型结果调提示词或改 gold，不将同场景六变体当六个独立场景。
- 六变体为 complete、missing、conflict、unavailable、resolved、unrelated_unavailable。前者与 resolved 应能继续准备；missing 与 unrelated_unavailable 应明确缺项；conflict 为未解决的当前矛盾；unavailable 为必需来源不可读。resolved 有明确的同事项更正，不依时间戳自行推断；无关不可读不把真实 missing 变成 unknown。
- 增加可见 `source_metadata`：来源 ID、主体、事项范围、适用时间、涉及主题、明确替代来源 ID。它说明来源归属和覆盖范围，不包含被遮蔽正文或预期状态。每条元数据与对应候选绑定，随正文进入检索、支持组选材与实际 Session 准备，避免模型看见但最终上下文丢失。
- 支持证据组内 AND、替代组间 OR；冲突也标注可替代的充分组。独立评审在首次模型调用前检查可见材料与全部最小路径，特别检查元数据已建立关联时的单来源充分性。
- 复用原研究 parser、selector、评分与 Session。旧材料省略元数据时保持序列化及候选内容不变；`SOUL_TASK_REQUIREMENTS_SET=metadata-v2` 显式选择新集合，默认仍是旧集合。

主比较先报告 72-case 完整诊断、下一动作、错误充分与失败分母，再按六变体报告，单列必需信息状态混淆、无关不可读误判 unknown、已更正误判 conflict，以及继续准备时的完整证据覆盖。模型必须评估全部四个选项，主 `predicted_required` 只采用其必要项；`all_options` 继续作为过度要求的对照，不将其按定义的必要项集合差异解释成模型能力差异。固定四/八条仅比较材料覆盖与准备，不作为语义诊断模型。

## 执行与费用边界

实验产物位于 `E:/SoulSyntheticLab/task-context-v2-20261022/`。三个模型按 case 交错串行调用，首位按 case 轮换；各 72 次，无自动模型重试。使用相同更新后的元数据说明、相同 768 输出 token 上限、low reasoning、同一中转接口。仅模型名不同；原始响应、异常、usage、预测、返回型号和每次延迟均保存。

沿用 `E:/SoulSyntheticLab/task-context-20261022/gpt-costs.jsonl` 累计费用账本，每次请求前后读取服务计费差值，只保存本次增量；单请求计数不为 1、计费未知或余额预算控制触发即停止，不以失败为理由重发。当前控制是观测消费停止点和单次余量，不是服务端硬限额；最终是否低于 $5 以完整记录核对。时延为模型 HTTP 请求往返，不含计费查询；新增轮换顺序只能减小而不能消除时段波动。

所有新集结果形成前，不根据任何部分正确率调参或修改标注。失败案例与慢样本保留；若发现标注歧义，单列限制，不回改主分数。整批新任务用于比较此轮候选，旧批与新批难度/元数据不同，不把分数差直接归因于元数据优化。

## 与现有算法和存储的分工

本轮沿用[既有算法职责、速度与成本比较](2026-10-22-task-model-comparison.md#各类算法的职责适用场景与成本)：明确字段、来源 ID、可读状态和引用结构由程序核对；自然语言中的任务必要性、适用条件、未解决矛盾与明确更正由候选模型判断；完整 AND/OR 支持组选材把判断落实为有限上下文，随后继续检查来源与字节预算。BM25、分组、MMR 负责候选排序，不把相关性分数解释成证据充分。

来源元数据在本轮研究输入及临时 Session 中流转，没有新增生产 schema、向量库、常驻缓存或自动多模型路由。加密存储、精确来源引用、授权和遗忘语义继续复用原实现。此次也不重新测量 Jev、embedding 或 reranker；它们的旧批结果及限制保留在原报告，不与新 72-case 分数拼成同批排名。

## 实施和验证记录

本轮改动限于研究测试、fixtures、调用脚本和文档：

- `task_requirements_probe/data.rs` 增加可选来源元数据，并按来源 ID 绑定到实际候选摘要；旧输入省略此字段时序列化和摘要不变。

## 费用核对、结论与验收边界

新批实际消费合计 **$1.3589698**；加上此前 **$1.375498928**，累计为 **$2.734468728**，低于累计 $5 上限，余量约 $2.265531272。共享 ledger 为 506 条、未知结算 0；本批 216 笔均能与 measurement 逐请求对应，单笔服务请求计数增量均为 1。累计实验模型调用数为 697（此前 481 + 本次 216），不把计费 GET、费用聚合行或独立评审会话当作模型请求。

GPT 费用是指定中转接口报告的消费增量；此前 Jev 费用仍为其 usage × 公开单价，不是本轮重新取得的供应商账单。模型名和返回型号按该接口别名记录，没有独立验证底层权重身份；时延是本次服务、网络与参数下的样本描述，非生产 SLA。

**当前建议仍以 6 Sol 作为准确率优先候选，6.1 Sol 保留为同质量替换候选，Luna 保留为低成本候选。** 两款 Sol 本批质量相同，6 Sol 的中位与 p95 较低；6.1 的消费仅低约 0.70%，中位延迟高约 33.86%，不足以据此强制替换，最大延迟则是 6.1 更低。Luna 平均任务费约为 6 Sol 的 1/17.79，成本优势明确，但仍有一次错误充分和一次不可读范围误判，不适合仅凭本轮把“可以继续”完全交给它自动决定。暂不新增双模型常驻流程或置信阈值。

本批说明来源元数据和明确证据标注能使这些边界可检验，两款 Sol 也在新材料上正确处理了它们；**没有同一批去掉元数据的随机对照，不能量化元数据本身带来多少准确率提升**。12 个合成场景各有六个相关变体，数量有限、构造模板相近，任务要求是从四个预设选项识别必需项；不是任意自然语言需求抽取、真实用户效用或各类数据全覆盖。下一阶段若继续，宜先保留这些失败，扩展自然表述和来源关系的合成难例，不因这次满分直接改生产默认。
