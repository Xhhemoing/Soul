  • “销毁已提交”与“后续失败”分开核心回执保留清理和审计确认，清理失败不再丢掉已提交结果。

PATH TO COMPLETION

距离可信交付，还缺四步

以下是按当前风险与依赖排列的工程接续顺序，不是新的冻结合同，也不擅自豁免现有验收。

01
P0 · 数据控制

把影响面校验放到销毁之前

在同一存储锁下重新计算并比较用户读过的范围；范围变了就拒绝，不等到回执才报告不一致。配套事务、并发和回滚测试。

02
P0 · 撤权及时性

拆分长任务，独立处理撤权

准备 → 锁外慢执行 → 带状态验证的提交。取消、授权过期或来源变化后的结果不得成为有效提交；不把页面忽略响应当核心取消。

03
验证 · 当前源码

补原生、组件与跨层回归

按锁定依赖运行 Rust / SQLCipher、完整 React/Vitest、lint/build 和独立桌面 IPC；检查旧调用者、旧回执与恢复路径，再进行独立评审。

04
交付 · 需要相应许可与环境

补齐平台证据，再收敛到 main

尊重 G-L 暂缓与 NSIS / G-M 跳过指示。条件具备后取得同源码平台门禁、真实人工观察并完成评审合入，才关闭 Goal 1。

长期方向，仍按既有路线推进

不因本轮接线完成，就提前开放文件写入、新采集或云分析。
