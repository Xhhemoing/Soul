# Soul Wave 1 Implementation Plan

日期：2026-09-27
基线：f2fa8e56d73928c609bb7e0d9c53c31115fa9b7c

## 目标

围绕“控制及时、数据可信、结果可解释”完成第一波改进，不扩大产品权限边界。

## Wave 1

### P0 控制链路
- Session 长任务拆分为准备、锁外执行、提交三个阶段。
- 撤权拥有独立优先路径。
- 过期授权、取消任务、来源变化后的结果必须拒绝提交。

验收：
- 慢模型请求期间撤权不等待请求结束。
- 已取消任务不能产生有效提交。
- 真实端到端行为与现有停止承诺一致。

### P0 遗忘结果语义
- 区分逻辑删除、清理状态、审计状态。
- checkpoint 检查完整返回状态。
- 支持清理恢复，而非重复执行销毁。

验收：
- 提交前失败不会产生部分销毁。
- 提交后清理失败能准确显示状态。
- 审计失败不会阻止遗忘。

### P1 输入与网络
- 导入增加字节预算、记录预算和单条长度边界。
- IPv6 origin 规范化。
- 出网前保持脱敏失败即拒绝策略。

验收：
- UI 和核心均拒绝超限输入。
- 畸形 origin、IPv6、redirect 有测试。

## 后续 Wave

Wave2：消息幂等、证据抽屉、情境偏好、获准记忆参与起草。

Wave3：任务接续、恢复包、受控文件动作。

Wave4：平台密钥、设备协同、研究扩展。

## 规则

- 不修改冻结算法。
- 不扩大出网能力。
- 不增加未经批准的采集。
- 所有功能改动必须配套测试和状态记录。
