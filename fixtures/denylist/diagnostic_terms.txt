# Soul 诊断词与量表词 denylist —— 单一事实来源
#
# 由 `cargo run -p xtask -- denylist-audit` 扫描 crates/**/src 的字符串字面量
# 与公共 API 标识符。命中即失败。
#
# 为什么存在：PRODUCT_LOCK 写明 Soul 不是临床医学产品，不给出精神疾病诊断；
# DECISIONS D22 写明心理模型是方向轴加弱/中/强证据档，不是量表、不是分数。
# 这两条只靠人自觉守不住，所以做成 CI 断言。
#
# 匹配规则（见 crates/xtask/src/denylist.rs）：
#   * ASCII 词按词边界匹配，标识符先按 `_` 与驼峰拆词再比对，
#     所以 `underscore` 不会被 `score` 命中；
#   * 非 ASCII 词按子串匹配；
#   * 大小写不敏感。
#
# 豁免：本文件自身、`crates/xtask/**`（实现与自测需要引用这些词）、
# `fixtures/**`、任何 `tests/` 目录。
#
# 故意不在名单里：
#   * `clinical`、`clinical_claim` —— 那是 schema 里的护栏字段，不是声称；
#   * `diagnostics` —— 那是 privacy.purposes 的合法取值（本机诊断日志用途），
#     与 `diagnosis`/`diagnose` 不同词，不要混为一谈。
