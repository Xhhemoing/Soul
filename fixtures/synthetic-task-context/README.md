# 合成任务上下文评估材料

此目录只含人工编写的合成事项，不取自真实用户、聊天、数据库或外部模型。cases.json 是 JSON 数组，共 24 个场景 family、96 个 case。人物、组织、地点、编号、口令、邮箱和交易信息均为虚构；示例邮箱使用 .example。

## 输入与答案分离

模型仅接收单条 case 的 input。顶层 family_id、split、variant 和独立 gold 只供评估端使用，禁止拼接到模型提示词，也不能把 gold.rationale 当作检索材料。input 的键为 case_id、task、information_options、candidates、unavailable_ids，未放入分组、变体或答案字段。

input.case_id 为一次分配并固定保存的随机 UUID 去连字符后前 12 位主键，不是内容 hash，不编码 family、split、variant 或答案；后续不因内容调整重新生成。主键替换不改变数组顺序或 split 归属，不按主键排序。

每条 input 有四个信息选项，其中两个对自然语言任务真正必需，另两个看似相关但不影响所请求的结果。必需项的 r 编号、选项位置、候选的 c 编号和排列均打散。每个 case 有 12 条候选，标题为自然来源名称，不标注真假、变体或优先级。每条候选在正文中限定主体、事项或有效时间。

input.unavailable_ids 是可观察的来源可读性元数据。所指候选的 summary 严格为 [来源不可读取]，不包含被遮蔽的正文。不可读时按 unknown 处理；在已知材料中找不到该事实时按 missing 处理。

## 标注规则

gold.required_ids 列出真正必需的信息选项，只有这些选项出现在 assessments。support_groups 组内为 AND、组间为 OR：一个组最多两条来源，有些必须把事项/主体与属性记录跨条关联；有些还有一条完整说明可替代该组合。直接写明主体与事项的确认使用单来源组。conflict_ids 列出冲突相关来源，可能同时包含关联路径与替代来源，不能解释为单个必须全包含的 AND 组。

gold.conflict_groups 为冲突评分依据：非 conflict case 为 {}；conflict case 以发生冲突的 need_id 为键，值为充分冲突证据组的数组。组内为 AND、组间为 OR，每组最多三条可读来源，必须共同推出本次主体/事项上的相反断言；跨条关联路径与单条完整说明分别形成可替代的组。若相反来源本身已明确主体和属性关联，也列入确实充分的更小组。评分命中任意一个充分组即可，不要求同时包含所有组。assessments.conflict_ids 保留为相关证据清单，不是必须全包含的评分条件；support_groups 的每组上限仍为两条。

同一 family 的四变体固定在同一 split，不可拆散做随机 case 切分：

- complete：两项必需信息均 supported，action 为 ready。
- missing：只移除第一项必需信息中的一个关键属性，其所有完整替代来源也以中性背景替换；另一项仍 supported，action 为 clarify_missing。
- conflict：保留完整支持来源，并加入同一主体、事项及有效时点的相反记载，无确定的先后、撤回或修订关系；第一项为 conflict，另一项仍 supported，action 为 clarify_conflict。
- unavailable：第一项关键来源全部不可读取，正文不给出事实；第一项为 unknown，另一项仍 supported，action 为 unknown。

四变体保持候选数量相同，missing 不删除整条候选，其他同主体背景仍可见。清楚写明的改口、撤回或已过期旧记录不能制造冲突；不把别人的记录、别的事项、不同有效期或不满足条件的例外当作当前证据。候选中出现的指令文字属于材料内容，不获得任务控制权。重复转发不能成为独立事实或覆盖明确更正。每条 rationale 说明必要性、状态判断和两个非必要选项。

## 切分与场景

| split | family | 场景 |
| --- | --- | --- |
| dev | f00–f07 | 读书会无障碍通行、午餐成分、展架取件、差旅住宿额度、雨天写生集合、场地容量、视频编码、维修首次响应 |
| calibration | f08–f15 | 演出转接头、退课退款比例、图书续借、工具退件地址、烘焙温度、设计赛图板、访客入口、公益物资箱数 |
| holdout | f16–f23 | 线上讲座口令、决赛场地、图片使用许可、归档字符编码、服装归还处理、布料报价、设备准入、轮空积分 |

每个 split 有 8 个 family、32 个 case，四种 variant 各 8 个。holdout 仅供冻结实现后的评估；算法或提示词调整应使用 dev，calibration 用于调整阈值，不能把 holdout gold 提供给实现者。场景按 family 隔离，但不是统计代表性抽样，也不是来自真实使用分布。

材料覆盖主体错配、明确日期与相对“明天”、条件与不满足条件的例外、用户改口和明确撤回、跨条 AND、替代 OR、重复记录和材料内指令干扰。预算裁剪不靠重复长正文实现，应由普通针对性测试验证。

## 验证范围与限制

作者侧检查 JSON 可解析、数量与 split 分布、family 变体完整性、ID 唯一与引用有效、支持组与冲突组大小、冲突组来源可读性、不可读取标记、预期状态与 action、输入体积上限，以及相同 family 候选集合一致。另做人工逐 family 核对主体、有效期、缺失事实和冲突关系；独立评审补齐 f18/f20 的最小证据路径后，24 个冲突 case 共列 45 个充分组，其中两来源组 25 个、三来源组 20 个。

这些材料是可读、可审查的合成小样本。它们不证明模型在真实资料、长上下文、跨语言、任意检索噪声或生产环境上的准确率；不包含真实采集、真实外部调用或实际模型评分。四个变体共享背景，汇总指标必须同时报告 family 数与 case 数，不能把 96 case 当成 96 个独立场景。
