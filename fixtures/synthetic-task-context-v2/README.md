# 新合成任务上下文材料 v2

本目录是一次新编的 12 个场景 family、72 个 case。所有人物、团队、编号、日期和制度均为虚构；规则仅为测试设定，不表示任何真实行业操作要求。没有读取真实聊天、数据库、凭据或外部服务。旧目录 `../synthetic-task-context/` 的 24 个场景和 96 个 case 保留不动。

整批 `split` 均为 `fresh`，每个 family 含六个变体。材料和 gold 在本批模型运行之前编写；这批用于新任务复测，不作为调参集。12 个 family 是独立题材，六变体共享各自背景，统计时应同时给出 12 个 family 与 72 个 case，不能当作 72 个独立场景。

## 输入与来源元数据

顶层保留 `family_id`、`split`、`variant`、`input`、`gold`。评估端只能把 `input` 作为模型输入，不能传入分组、变体、gold 或本 README。`input` 保留 `case_id`、`task`、`information_options`、`candidates`、`unavailable_ids`，新增 `source_metadata`。每 case 有八个候选、四个选项和两个必需项。候选 ID、候选排列、选项 ID、选项排列与必需项排列均打散，不用位置编码答案。

`case_id` 是一次随机分配并保存的 12 位 UUID 片段，不是 hash，不编码分组、变体或答案；后续编辑应保留它。它与旧材料的 ID 没有重合。

每条候选恰好对应一条公开元数据：

```json
{
  "source_id": "c123",
  "subject": "来源所述主体或对象",
  "scope": "来源适用范围",
  "valid_time": "2027-03-04",
  "topics": ["来源涉及的自然语言主题"],
  "supersedes": []
}
```

元数据是模型可见证据，不能忽略其主体绑定，也不能把它扩充为没有写出的事实。所有字段简短，`topics` 为一至四项；元数据不放答案值、need ID、状态、变体或 gold 标签。`supersedes` 仅引用同池来源，明确表达更正的替代关系。

不可读来源的 `summary` 严格是 `[来源不可读取]`，不透露被遮蔽的答案。`subject`、`scope`、`valid_time` 和 `topics` 仍然公开，帮助判断它是否可能补足本次所缺的信息。与缺失项有关的来源不可读时标记 `unknown`；仅别的主体、日期、主题的来源不可读，不妨碍将真正缺项标记为 `missing`。

## 六种变体

| variant | 第一必需项 | 第二必需项 | action | 证据设置 |
| --- | --- | --- | --- | --- |
| `complete` | `supported` | `supported` | `ready` | 对象条款和事项确认提供替代路径 |
| `missing` | `missing` | `supported` | `clarify_missing` | 两条可能记载第一项的可读来源均不含该事实 |
| `conflict` | `conflict` | `supported` | `clarify_conflict` | 同主体、条件、日期的相反记载，没有先后或修订关系 |
| `unavailable` | `unknown` | `supported` | `unknown` | 第一项的条款和事项确认均不可读，公开元数据表明关联 |
| `resolved` | `supported` | `supported` | `ready` | 正式更正明确撤回原条款与原确认，正文和 `supersedes` 一致 |
| `unrelated_unavailable` | `missing` | `supported` | `clarify_missing` | 第一项确实缺失；不可读项仅属于别组旧日期的文档存放索引 |

这里的“第一/第二”只用于解释编写方法，不对应任何固定 r 编号或选项位置。第二必需项始终有一条执行安排和一条明确转抄；二者各自写出完整事实，所以分别列为单来源支持组。转抄不是独立事实的交叉证实。

八个 n01–n08 的原条款只在元数据绑定一个对象，没有声称本次选了该对象，故需要“分配记录 AND 对象条款”。独立的事项确认同时写出本次对象、条件和完整规定，形成单来源 OR 替代路径。n09–n12 的对象条款已通过元数据绑定完整事项，正文也明确适用条件，所以它自身就是充分来源；不能再强制附加分配记录。所有 family 的明确事项确认都可单独支持第一项。

`resolved` 仅保留更正来源作为第一项的最小支持组。更正正文声明撤回原对象条款及原事项确认在本事项上的旧说法，`supersedes` 引用对应两条候选；旧来源不再制造当前冲突。全部 family 的 `conflict` 最小充分组都是“对象条款 + 相反记录”或“事项确认 + 相反记录”：相反记录自身也写出本次对象分配与条件，故能为对象条款提供归属关系。n01–n08 另保留有效的“分配 + 条款 + 相反记录”三条超集，但命中最小两条组已经足够。共 32 个充分冲突组，其中 24 个最小组、8 个有效超集。

每个 case 还含另一个主体及日期的旧批次记载、无规则制定权限的指令式引用，以及两个任务不需要的布置信息。它们不能覆盖当前来源，不能把非必要选项升级成必需项。编写时逐 family 检查了主体、条件、日期及更正范围，避免从这些干扰项推出当前答案。

## Gold 与验证范围

`gold` 沿用 `required_ids`、`assessments`、`action`、`rationale`、`conflict_groups`。`support_groups` 组内 AND、组间 OR，列出从正文和公开元数据可成立的所有最小充分组。`conflict_groups` 也是组内 AND、组间 OR，列全最小组并保留上述有效超集；`conflict_ids` 是相关证据的并集，不表示所有来源必须一起保留。非冲突 case 的 `conflict_groups` 为空。

作者结构检查覆盖 72 个 ID 唯一且不与旧批次重合、12×6 变体完整、全批 fresh、八候选与四选项、两个必需项、元数据逐来源一一对应、字段与主题长度、所有引用存在、支持/冲突来源可读、不可读标记、替代关系无自指，以及各变体状态和 action。另按上表核对语义与最小来源路径。当前检查只验证材料，不代表已经跑过模型、真实 Session、生产回归或独立评审；后续运行与审查以各自实际证据为准。

局限：这是短上下文、中文、人工设计的有限题材样本，不是随机抽取的真实使用分布；六变体有相关性，重复转抄也不是独立证据。它不证明长上下文、复杂来源链、多跳撤回、多语言、真实采集、出网授权或生产准确率。随机化 ID 和排列只是避免固定位置提示，没有新增 hash、冻结 contract、baseline 或 gate。
