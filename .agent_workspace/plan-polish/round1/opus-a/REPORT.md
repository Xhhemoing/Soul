## 1. PRODUCT_LOCK.md

### 变了什么

1. **抬头多一句**：算法口径（判档规则、常量、话术）的唯一权威是 `docs/algorithms/DECISION.md`，本锁只写产品承诺、不复抄常量数值。
2. **「自主拍板」表加一行「灵魂层算法」**，只做指针（T4D / A0 / A2），不承载细节。
3. **新增「灵魂层算法（v0.1）」小节**，放在「自主拍板」与「出网分级」之间：四行表格交代 T4D（人脉档位唯一权威）、A0（问卷 + 纠正锁）、A1（A0 内部升档规则，v0.1 空转是预期行为）、A2（纯渲染器）；三条产品面承诺（档位不是分数、时间口径来自数据不来自墙钟、降档与「最近半年没有往来」共用同一阈值）；三条已知代价（仅群聊落弱、F04c、任一场地时钟的不对称面）。
4. **不可协商约束加第 13 条**：口径以 `ALGO_FROZEN` 为准，产品面不得另立第二套阈值，不得为 F04c 加第三道门。

### 为什么

- **P3 冻结吸收。** 原锁完全没提 T4D / A0。冻结只活在 `docs/algorithms/` 里，产品面读者不会去翻，于是「人脉图 = 互动强度」这种模糊表述会被后来的实现者按自己的理解填空——G1 的 T0 遗留判档正是这么来的。
- **A1 空转必须写进产品面。** 只写在 `DECISION.md` §2 的话，任何 reviewer 看到「升档规则从不触发」都会当缺陷开工单。写进锁里，它就是已拍板的预期行为。
- **锁只指不抄。** 常量表在 `DECISION.md` §3 声明「全仓库禁止第二处出现数字字面量」。所以新小节里没有 3 / 10 / 180 / 360 中的任何一个：需要说降档时写「半年」「一年」并注明各自对应常量表里的一个常量。「自愈路径」同理写成「补够常量表规定的一对一次数」。
- **不膨胀（P5）。** 新小节末尾一句写死：本节不新增切片项，只是给切片第 3、6 两条钉算法口径。十三片、砍/留表、后期路线、假设全部一字未动；OAuth / 云端 / 文件写执行没有被拉回 v0.1。
- **不提 T0。** 全文没有 T0 字样；遗留判档的事实属于 STATUS 与 BLOCKERS，不属于产品锁。

### 明确没做

没有开第二份 `PRODUCT.md`；没有改「一句话」「作者原意」「不是什么」「不可协商约束」1–12；没有动切片编号（下游 `FORMAL_WORK_PROMPT` 与 `BLOCKERS.md` 都按编号引用切片，改编号会连带失效）。

## 3. STATUS.md

### 变了什么

原稿六行，核心断言三条：`PLAN_FROZEN`、「尚未写应用代码」、「v0.1 实现：未开始」。后两条在本分支上是假的。改写后：

1. 里程碑改为 `PLAN_FROZEN` + `ALGO_FROZEN`，并写明这两个冻结管计划与算法选型，不管实现，也不管合入。
2. 新增分支现状表（`main` / 本分支 / PR #2 / PR #6 / PR #7 / PR #4），每行带尖端提交号与「核于」日期。
3. **杀掉「尚未写应用代码」的全局说法**，换成可核的版本：`main` 上没有应用代码；应用代码在 `cursor/soul-goal1-7b1c` 上，未合入也未关闭。
4. 进度表：「v0.1 实现 未开始」→「Goal 1 实现 进行中，在另一分支，未合入未关闭」；另加「Goal 1 关闭门 未过」「Goal 2 未启动」两行。
5. 阻塞：保留「计划面无阻塞」，但立刻限定它只覆盖本树；随后一张核于本日的阻碍项状态表，指向 `docs/BLOCKERS.md` 而不复抄全表。
6. 下一步：本分支只负责计划那一半，其余按 `BLOCKERS.md` 第 5 节走，且都在 Goal 1 线上做。
7. 末节写死写法纪律（D48），含「PR #2 合入时两份 STATUS 合成一份」。

### 事实是怎么核的

| 断言 | 证据 |
|---|---|
| `main` 只有算法 crate | 本树 `Cargo.toml` 成员表只有两个 `soul-algo-*`；`crates/` 下也只有这两个 |
| Goal 1 尖端是 `3161e02` | `git rev-parse origin/cursor/soul-goal1-7b1c` |
| M2 未做 | `git show origin/cursor/soul-goal1-7b1c:Cargo.toml`：16 个成员，没有任何算法 crate |
| G1 未接 T4D | `crates/soul-graph/Cargo.toml` 不依赖 `soul-algo-tie`；`crates/soul-graph/src/build.rs` 仍自带 `fn band()` |
| WP 完成面 | 引自 `origin/cursor/soul-goal1-7b1c:docs/STATUS.md`，并在表里注明「按该分支自己的 STATUS」 |
| `BLOCKERS_FROZEN` 核于 `2e72ddf` | `BLOCKERS.md` 抬头自述 |

M1 / M3 / G2 / G3 / G5 我没有逐一在尖端复核，所以写的是「未见关闭」「需按尖端复核」，不写「仍未修」。G5 特别标注了 `BLOCKERS.md` 冻结点之后主干自称已接上导入与采集入口，需要复核——冻结的阻碍项清单不会自己跟着主干走。

### 为什么这样写而不是抄 Goal 1 那份

`origin/cursor/soul-goal1-7b1c:docs/STATUS.md` 有 805 行，是实现面的流水账。把它拷到计划线会立刻制造双源，而且会让 `main` 上的 STATUS 描述一堆 `main` 上不存在的代码。所以计划线这份保持短，只回答「哪条线到哪了、谁是权威」，并写明合入时两份合一。
