## 0. 本轮的一句话结论（先说，后证；其中两句推翻我上一轮）

1. **R1 的 `FN2-1` 是一条坏杀线，本轮作废。** 它写的是「学习候选打不赢 `n2` ≥5 点 ⇒ 全体出局」。
   但在 `n2` 弃权的场合（自由选择点），赢它是白送；在 `n2` 开火的场合，`n2` 近乎满分，谁也赢不了。
   于是这条线的红绿**由机会集的构成决定，不由模型质量决定**——它测的是语料，不是候选。
2. **「N2 是否杀死学习」这个问题，主要不是命中率问题，是一个可以今天数出来的整数问题**：
   基线（`n2` 开火时用 `n2`，弃权时退 `n0`）在整个机会集上**错了多少次**。
   错得少于 5%，任何学习候选都拿不到 5 点提升——**不必实现就能处决**。这条叫上界处决（§4.2）。
3. **本轮把这个普查在三类使用剖面上手算了一遍（§4.4），结果推翻了我 R1 的预判**：
   R1 说「`n2` 吃掉全部可预测量的概率过半」。**普查说不是**：稳态下 `n2` 只有两行能开火，
   在均衡剖面上它只覆盖机会集的 **20%**，在离线（无 E1 端点）用户上覆盖 **0%**——
   一条恒不开火的对照等于没有对照。上界处决在三类剖面上**一条都没打响**。
4. **所以杀死学习候选的不会是 N2，而是饥饿**（§4.6）：动作轴一天个位数事件，`n ≥ 200` 大概率永远不到。
   本轮把饥饿写成一条会真正落槌的条款（含死代码清除），而不是让候选永远挂在 `inconclusive` 上。
5. 还有一条今天就成立的硬事实（§2.1）：**在 HITL 动作面上，`n2` 与 `n1`（MRU）逐点相同**，
   因为 E1 路径的 `prepare` 与 `generate` 各发一次 `egress.generate`，两个事件同名。
   `n2` 要成为一条**可分**的对照，必须换到命令面（面 B），而换面要先冻结一张今天不存在的清单。

## 1. 待决状态的数据面（源码逐条；本节推翻 R1 §3.3 的三处）

R1 §3.3 用一句话描述 N2 的输入：「有没有已展示未确认的整理预览、有没有 `prepared` 未生成的起草、
有没有已展示未执行的遗忘影响预览」。查过源码之后，这句话**三条里错一条、另两条不可读**。

### 1.1 今天真实存在的待决槽（两个，都是 `Option`）

| 槽 | 字段 | 置位 | 清位 | 坐标 |
|---|---|---|---|---|
| 已准备未生成的 E1 起草 | `DraftSession.pending: Option<Pending>` | `prepare()` | `generate()` 取走 / `discard()` / `set_identifiers()` | `soulcore/src/commands/draft.rs:104-118, 189-224, 242-250, 147, 159-161` |
| 已报价未确认的遗忘 | `Session.held_forget: Option<HeldForget>` | `preview_forget()` | `forget_memory()` 取走（`take().filter(...)`） | `soulcore/src/commands/session.rs:384-391, 1097-1111, 1125-1135` |

两个槽都**只有一格**：第二次 `prepare` 顶掉第一次（`draft.rs:204-212` 的注释说明这是故意的），
第二次 `preview_forget` 顶掉第一次（`session.rs:1094-1096`）。**所以待决状态是 O(1) 布尔，不是队列**——
这是 N2 能自称「零状态」的唯一理由，值得钉住：**若日后任一槽变成 `Vec`，N2 的规范作废，须重写。**

### 1.2 R1 错的那一条：整理预览**没有**待决槽

`FilePlanSession` 的**全部**字段是 `authorization: Authorization`（`soulcore/src/commands/fileplan.rs:50-53`）。
`preview()` 是 `&self`，返回 `Preview` 就结束，什么也不留（`fileplan.rs:97-106`；`session.rs:609-627` 只把它写进审计并渲染）。
**「用户看了一个整理预览还没决定」这个状态在进程里不存在。**

这不是疏忽而是 v0.1 的形状：计划不可执行（`executable_in_this_version: false`），
没有「确认」这一步，所以没有东西要等。**后果**：N2 在文件面上一行也写不出来，
而文件面恰恰是 Cycle 2 的主题。R1 把它当成 N2 的三分之一，是错的。

### 1.3 两个槽今天都读不出来（这是 N2 的前置件，不是细节）

| 想读的 | 今天有什么 | 问题 |
|---|---|---|
| 有没有准备好的起草 | `DraftSession::pending_plan_hash() -> Option<&PlanHash>`（`draft.rs:151-153`），全仓只有测试调用（`soulcore/tests/draft_commands.rs:257,277,374`） | **它返回的正是 D3 禁止 N2 消费的值**。N2 需要的是布尔 |
| 有没有待确认的遗忘 | 无。`held_forget` 私有，无访问器 | 读不到 |
| 有没有未花的能力令牌 | `TokenIssuer::issued_count()`（`hitl.rs:340-342`）是**含已花的总数**；`is_spent(id)` 要先知道 id | 数不出「活着的」 |

→ 新缺口 **G21**（§7）。补法是三个只读访问器，且**必须返回布尔/计数，不得返回 hash 或 id**：
`has_prepared_draft() -> bool`、`has_held_forget() -> bool`、`live_token_count(as_of_ms) -> usize`。
这条缺口小到可以在 v0.2 之前补掉，但**它是 §4 全部五步的前置件**：数不出待决状态，机会集就分不了桶。

### 1.4 待决槽会被**无关命令**静默清空

`Session::sync_identifiers()` 调用 `self.draft.set_identifiers(...)`，而后者 `self.pending = None`（`draft.rs:144-148`）。
它的调用点有三个：`session.rs:486`（开会话）、`:718`（`prepare_draft` 自己，紧接着重建，无害）、
**`:959`（`commit_telegram` 提交导入之后）**。

所以「准备一封回信 → 导入一个 Telegram 文件 → 点生成」这条路径上，生成会以 `NothingPrepared` 被拒，
**而界面在此之前没有任何地方能告诉用户那封信已经没了**（`SessionStatus` 只有向导/库/配置三件事，`session.rs:517-530`）。

两个后果：
(a) **N2 必须在每个机会现读，不许缓存、不许由事件流回放重建**——回放会漏掉这次静默清空。这条写成门 `S4`（§5）。
(b) 顺带的产品面观察（本文件不裁，只登记）：这是一处「状态变了而用户读不到」的地方，
   N2 若上屏，它会是第一个撞上它的东西。

### 1.5 令牌活性需要时钟，所以 N2 不是「无时钟」的

`DEFAULT_TOKEN_TTL_MS = 120_000`（`soul-policy/src/hitl.rs:248-251`），过期由 `is_expired_at(now_ms)` 判定
（`hitl.rs:318-324`）。「有一个还能用的令牌」这个待决状态**随时间自己消失**。

裁决：**N2 v1.1 不收令牌活性行。** 理由是它与已有的起草槽重复（E1 令牌只在 `generate()` 里现铸现花，
`draft.rs:262-270`，根本没有「拿着令牌等」的窗口），而收它就要引入 `as_of_ms`，
把一条规则表变成一条有时钟的规则表，`FN2-2` 的「≤6 行且逐行一句话」立刻名存实亡。
**若日后 v0.1.1 的可逆移动引入了「令牌已发未花」的真实窗口，这条裁决要重开，并同时补 `as_of` 纪律。**

### 1.6 待决槽与 predictand 的字母表**不对齐**

C2R1 §1.2 已经证明动作面的可观测字母表是 **5**（`draft.reply` / `analyse.people` / `scan.directory` /
`plan.files` / `egress.generate`），`forget.*` 与 `research.preview` 无生产者。

把 §1.1 的两个槽放上去对：

| 待决槽 | 它预示的下一步 | 该下一步在动作面上是什么 |
|---|---|---|
| `DraftSession.pending` | `generate_draft` | `egress.generate`（`policy.rs:190-204` 的第二次 `check_action`） |
| `Session.held_forget` | `forget_memory` | **什么也不是**。`soul-memory` 全 crate 不过 HITL（C2R1 §1.2，G19） |

**后果**：N2 的两行里，**有一行预测的 token 在今天的事件流里永远不会出现**。
它不是「预测错」，是「预测了一个不存在的字母」——恒错，且不可能被修正。
在动作面上它必须被删掉，N2 就只剩一行。这是 §2.1 那个结论的来源。

## 2. N2 的两个形态：先声明面，再谈杀线

**纪律（本轮新增，最重要的一条形式要求）**：
`n2` 的任何数字必须带一个面标记 `S ∈ {A, B}`。**两个面的数字不得出现在同一张比较表里。**
R1 的 `FN2-1` 没有面标记，这是它不可执行的第一层原因。

### 2.1 `n2A.pending_state_rule.v1`（HITL 动作面，字母表 5）——**今天不可分于 `n1`**

删掉 §1.6 那条恒错行之后，规则表只剩：

| 行 | 条件 | 输出 |
|---|---|---|
| A1 | `has_prepared_draft()` | `next_action(egress.generate)` |
| A2 | 其余 | `abstain.no_pending` |

**它与 `n1`（重复上一个动作）在 A1 上逐点相同，证明如下**：
`has_prepared_draft()` 为真，当且仅当 `prepare()` 成功过而 `generate()/discard()` 还没跑
（`draft.rs:206`、`:248`、`:160`）。而 `prepare()` 自己发出的动作事件就是
`allow(policy, ActionKind::GenerateWithUserEndpoint, ...)`（`draft.rs:197`）。
所以**只要 A1 的条件成立，事件流里紧邻的上一个事件必定是 `egress.generate`**，
而 `n1` 的输出恰是「上一个事件」。两者在 A1 上给出同一个 token；在 A2 上 `n2A` 弃权，`n1` 仍答。

→ **在面 A 上，`n2A` 是 `n1` 的一个更弱的子集，不是一条独立对照。**
R1 把 `n2` 称作「真对手」，在面 A 上不成立。**判别机会数 = 0**（§4.3 的 `K3` 当场变红）。

状态：`COMPARATOR`（名义）+ `TESTABLE-NOW`，但**不得单独进阶梯**——用 `n1` 更便宜且严格更强。

### 2.2 `n2B.pending_state_rule.v1`（命令面）——`n2` 有意义的唯一形态

面 B 的 predictand 是「下一条用户命令」，即 `Session` 上那批由一次用户手势触发的 `pub fn`
（`session.rs` 里约 32 个：`status` / `files` / `authorize` / `preview` / `people` / `person_summary` /
`draft_pasted` / `prepare_draft` / `generate_draft` / `discard_draft` / `preview_forget` / `forget_memory` /
`memories` / `write_memory` / `edit_memory` / `research` / `audit` / 采集三件 / 档案四件 / 导入两件 / 端点两件 / 向导一件）。

**规则表 v1.1（首匹配即出，行序即优先级；每行附一句用户能读的话）**：

| 行 | 条件（只读布尔，无参数，无时钟） | 输出 | 一句话 |
|---|---|---|---|
| B1 | `!status().wizard_completed`（`session.rs:519`） | `complete_wizard` | 「你还没走完第一次设置。」 |
| B2 | `has_prepared_draft()`（G21） | `generate_draft` | 「你准备好了一封回信，还没生成。」 |
| B3 | `has_held_forget()`（G21） | `forget_memory` | 「你看过忘掉那条记忆要付的代价，还没确认。」 |
| B4 | `!unavailable_roots.is_empty()`（`session.rs:380`） | `authorize` | 「有一个你授权过的目录，现在打不开。」 |
| B5 | `roots().is_empty()`（`fileplan.rs:84-86`） | `authorize` | 「你还没有授权任何目录。」 |
| B6 | 其余 | `abstain.no_pending` | —（不出声） |

**5 条实义行 + 1 条弃权行 = 6，正好顶满 `FN2-2` 的上限。登记一条禁令**：
不许加第 7 行。要加就先走 `DECISIONS`，并重新论证它还算不算「零状态规则」——
因为一张会长大的规则表就是一个没人登记的模型，而且它会**从内部**把 §4 的上界推高（`n2` 覆盖越多，学习的天花板越低），
即它可以靠加行把对手挤死。**这条禁令是整篇杀线可信的前提。**

**稳态只有两行**：B1/B4/B5 是一次性/设置类事件（§3.4 会把它们隔离出判定），
所以稳定使用中 `n2B` 实际只有 B2 与 B3 会开火。**「N2 是一张两行表」这句话应当写进任何引用它的地方。**

**面 B 的代价（诚实登记，不许默认掉）**：
命令面**不是闭集**——它没有 `ActionKind` 那样的枚举，加一个 `pub fn` 不会让任何编译失败。
C2R1 的门 `D1`（词表同步，禁 `_ =>` 通配）**在面 B 上失效**。→ 缺口 **G22**（§7）。
换面不是免费的：面 A 的字母表由类型系统守着，面 B 的字母表由人记得守着。

## 3. 机会集：杀线的地基（不先切开，任何比较都是在比语料）

### 3.1 规范化（本轮把 R1 §9 争点 1 裁掉）

**裁决：合并，不排除。** 同一次 `preview()` 调用内背靠背产生的 `(scan.directory, plan.files)`
（`soul-fileplan/src/preview.rs:88-96` 与 `:101-103`）在规范化阶段合并为**一个** `plan.files` 事件。
理由：排除 `scan.directory` 会让「授权后第一次扫描、计划为空」这类机会整个消失，而那是真实的用户动作。

**实现代价必须一并登记**：判定「同一次调用」今天没有依据——动作事件没有 call id，
`ActionRequest` 里也没有关联字段。只能用「相邻 + 顺序为 scan→plan」的启发式，
而这个启发式在两次 `preview()` 交错时会错。→ **补 G17/G18 时必须同时给动作事件一个 `call_id`**（并入 §7）。

### 3.2 机会的定义

设规范化后的事件序列 `e₁ … e_N`（面 S 上）。**机会 `i`（1 ≤ i ≤ N）= 预测 `eᵢ`**，可用的信息恰为：
前缀 `e₁ … e_{i−1}`，以及 **`eᵢ` 发生之前一刻由会话现读的待决状态快照**。

- `i = 1` **算机会**（`n0`/`n1` 在此弃权、按未命中；`n2` 若有待决则可答）。
- 待决状态必须**现读**（§1.4），不许回放重建。
- 弃权计入分母、按未命中处理（继承 C1）。

### 3.3 三分桶

| 桶 | 定义 | 处置 |
|---|---|---|
| **M**（机械） | 后继由同一函数调用产生，用户没有插手的机会 | 规范化后不存在（§3.1）。若某天出现新的同调用二连，**先扩规范化，再谈判定** |
| **C**（受约束） | `n2` 在该机会上命中某条实义行（非弃权） | `n2` 的地盘 |
| **F**（自由） | `n2` 落到弃权行 | 学习的地盘 |

`|O| = |C| + |F|`。**所有比较必须逐桶报数，禁止只报总数**——总数是两个不同问题的加权平均，
而权重（`|C|/|O|`）是语料属性，不是模型属性。

### 3.4 一次性行的隔离（`FN2-4`）

B1（向导）、B4/B5（授权面不完整）预测的是一生一两次的事件。它们必须：
(a) 在语料里单列计数；(b) **不计入 §4 的任何主判据分子分母**；(c) 若某份普查里它们占 `|C|` 的 ≥20%，
整份普查作废重采——那说明语料几乎全是首启噪声。
不隔离的后果很具体：`n2` 会靠「猜对了一次开箱流程」把自己的覆盖率抬上去，从而压低学习候选的天花板。

### 3.5 记账约定

- 每个候选在每个机会输出 top-1 或弃权；只记 top-1（动作轴事件太少，top-3 在 5 字母上近乎平凡）。
- 比较用交叉相乘，`i128`，判定步无浮点。
- 空虚保护：任一分母 `< 200` 或分子 `< 20` ⇒ `inconclusive` ⇒ 按不过。
- 并列：按 token 的 `as_str()` 字典序升序。
- 确定性：同输入 1000 次逐字节同输出。

### 3.6 基线候选（被杀之后 v0.2 要发的那个东西，必须先有名字）

`b0.pending_then_marginal.v1` = 阶梯：`C` 上用 `n2`，`F` 上退 `n0`，两者都弃权则弃权。
状态：`COMPARATOR + TESTABLE-NOW`（面 B 阻塞于 G21）。
**§4 的全部上界都是相对 `b0` 算的。** 没有 `b0` 这个名字，「杀死学习候选」就没有下文——
杀了之后要发什么？答案必须在杀之前写下来。

## 4. 杀线：五步判定程序（`FN2-K1 … K6`）

**总纪律：这五条只能向下杀，不能向上抬。** 上界不处决 ≠ 学习有价值；上界处决 = 学习一定没价值。
任何人拿 `K1/K2` 没打响来主张「所以该建 G17 那张表」，是把单向判据当双向用。

### 4.0 判定前必须先登记的东西（看结果之前）

面 `S`、规范化管道版本、使用剖面权重（§4.4）、一次性行清单、常量 `{5 点, 10 点, 200, 20}`、随机种子。
**事后倒填 = 该次判定作废**（继承 C1 A8）。

### 4.1 `K1` 粗上界处决（最便宜；不需要实现任何模型）

任何候选在 `C` 上至多全对、在 `F` 上至多全对，所以它相对 `b0` 的命中提升上界是

```
U₁ = (|C| − hits_n2_C) + |F|
```

**若 `20·U₁ < |O|`（上界不足 5 点）⇒ 学习类候选在该剖面上全体处决。**
需要的输入只有三样：机会集、真值标签、待决状态标注。**连 `n0` 都不用跑。**

### 4.2 `K2` 细上界处决（加跑 `n0`，严格更强）

```
U₂ = (|C| − hits_n2_C) + (|F| − hits_n0_F)  =  |O| − hits_b0     （即 b0 的错误数）
```

`U₂ ≤ U₁` 恒成立。**若 `20·U₂ < |O|` ⇒ 处决。**

一句话说清它：**「基线一共才错这么几次，任何模型至多把这几次全改对。改对了也不到 5 点，那就别做。」**
这是本文件对「N2 是否杀死学习候选」给出的可执行答案的主体，而且它**不依赖 G17/G18**——
它要的是一份机会集普查，不是一张持久化的历史表。

**它的适用边界（诚实标注，两条）**：
(a) 它只管 top-1 命中这一个价值口径。`x1` 的「门」形态（只决定**何时**建议，不决定建议什么，C2R1 §3.9 采纳的形状 (i)）
**不受本上界约束**，它的判据仍是 `FX1-2` 对 `c0_never` 的那条成对线。
(b) 上界是相对**这一份剖面**算的。换剖面要重算。所以 §4.4 的权重必须预注册。

### 4.3 `K3` 可分性检查（`n2` 有没有资格当基线）

判别机会 `D = { i ∈ C : n2(i) ≠ n1(i) }`。要求 `|D| ≥ 20` **且** `20·|D| ≥ |C|`。
不满足 ⇒ **`n2` 在该面上不可分于 `n1`，退位**：基线里的 `C` 段改用 `n1`，`K1/K2` 重算，
且**该面上不许再出现「打赢 `n2`」这种说法**。

**面 A 上这条今天当场变红**（§2.1 的证明：`|D| = 0`）。
这就是 R1 `FN2-1` 不可执行的第二层原因，也是「要谈 N2 就必须换到面 B」这个结论的来源。

### 4.4 `K1/K2` 的手算普查（本轮实做；三类预注册剖面，面 A）

规则：每类给出「每 100 次流程实例」的构成；流程的事件展开取自源码
（离线起草 = 1×`draft.reply`；E1 起草 = 2×`egress.generate`，即 `prepare` 一次 + `generate` 一次；
整理 = 1×`plan.files`（已合并）；人事 = 1×`analyse.people`；遗忘 = **0 个动作事件**）。
`n2A` 只有 A1 行，`hits_n2_C` 按「准备之后一定生成」的**最有利于 `n2` 的假设**取满分。
`n0` 输出全局众数 token。

| 剖面（预注册） | 流程构成 | \|O\| | \|C\| | \|F\| | hits_n2_C | hits_n0_F | U₂ | `20·U₂` vs `\|O\|` | 判定 |
|---|---|---|---|---|---|---|---|---|---|
| **E1 重度** | E1 90 / 整理 5 / 人事 5 | 190 | 90 | 100 | 90 | 90 | 10 | 200 ≥ 190 | **不处决**（天花板 5.3 点，擦线） |
| **均衡** | 离线 20 / E1 20 / 整理 20 / 人事 20 / 遗忘 20 | 100 | 20 | 80 | 20 | 20 | 60 | 1200 ≥ 100 | 不处决（天花板 60 点） |
| **离线用户**（无端点） | 离线 40 / 整理 30 / 人事 30 | 100 | **0** | 100 | — | 40 | 60 | 1200 ≥ 100 | 不处决；且 **`n2` 一次也没开火** |

**三条读数**：

1. **上界处决一条也没打响。** 我 R1 的预判（「`n2` 吃掉全部可预测量，概率过半」）**被自己的普查推翻**。
   稳态下 `n2A` 覆盖率是 90/190、20/100、0/100——最好的情况也不到一半。
2. **E1 重度那一栏是擦线过的**（5.3 点 > 5 点）。它对假设极敏感：只要用户有 10% 的准备后改主意（`discard`），
   `hits_n2_C` 掉到 81，`U₂` 升到 19，天花板翻倍;反过来把整理/人事去掉，`U₂` 归零，**当场处决**。
   **一个由单一用户习惯就能翻面的判决，本身就是「该等真实语料」的证据**，不是可以拿去下结论的东西。
3. **离线用户那一栏最要命**：`|C| = 0`。**`n2` 在这类用户身上从不发言。**
   一条恒弃权的对照不是对照——对这类用户，R1 那句「没有 `n2`，`a1` 打赢 `n0` 就会被误当成学到了习惯」
   根本没有防护作用。**对照的存在性本身是分剖面的**，这一点上一轮完全没考虑到。

**因此处置规则（预注册）**：三类**全部**处决 ⇒ 学习分支墓碑；**两类**处决 ⇒ 不晋级并冻结实现；
**≤1 类**处决 ⇒ 学习分支继续存活，但仍受 `K4/K5/K6` 约束。
按本轮普查：**0 类处决 ⇒ 学习分支在这一关活下来。**

**这份普查怎么被推翻**：它假设流程原子、不交错，且权重是我编的。
真实权重只能从使用剖面来，而使用剖面今天只能从**有损的审计链**取（C2R1 §1.3：`file.plan` 二义、
`analyse.people` 时隐时现）→ 缺口 **G23**（§7）。**在 G23 补上之前，§4.4 是一份形状检查，不是一份判决。**

### 4.5 `K4` 优待夹具处决（今天能跑，且是唯一今天能真正落槌的一条）

夹具 `ACT-PEND-BIASED`：在**自由选择点**上注入一个稳定的、与待决状态无关的用户偏好
（例：无待决时，70% 接 `analyse.people`，其余均分），机会数造到 ≥200（合成语料没有理由造不够）。

**判据**：学习候选须在 `F` 上对 `n0` 成对胜出 ≥10 点：`10·(w_a − w_b) ≥ N_paired`，`N_paired ≥ 200`。
**不过 ⇒ 该候选当场墓碑**（不是不晋级）。

**它证明什么、不证明什么（必须写在报告里）**：偏好是我们注入的，所以赢只证明
**实现正确 + 该形状能表达这种规律**。它是**必要条件，不是价值证据**。
但它落槌的资格是硬的：**在为你量身定做的世界里都赢不了，就没有理由去真实世界里试。**

### 4.6 `K5` 真实语料线 + `K6` 饥饿条款

`K5`（阻塞 G17 + G18 + G21，🚫）三条同时满足才算过：

| # | 式 | 意思 |
|---|---|---|
| K5-a | `20·(w_a − w_b) ≥ N_paired`（`F` 上对 `n0` 成对） | 在自由选择点上真的赢了 ≥5 点 |
| K5-b | `100·(hits_n2_C − hits_a_C) ≤ \|C\|` | **不许在 `n2` 的地盘上倒退超过 1 点**去换 `F` 上的收益 |
| K5-c | `20·(hits_a − hits_b0) ≥ \|O\|` | 整体相对 `b0` ≥5 点 |

`K6` **饥饿条款（本轮新增，且这是真正会落槌的那一条）**：
若到 v0.2 冻结点，真实语料上 `|O| < 200` 或 `|F| < 200`，则 `K5` 恒 `inconclusive` ⇒ 按不过 ⇒
**学习分支不得进入产品，且实现必须删除，不许留在一个默认关的开关后面**（死代码条款）。
复活条件：语料达标后重跑 `K5`。

**为什么这不算 C1 §0.5 意义上的「坏杀线」**：C1 的元规则是「在全部可得夹具上恒 `inconclusive` 的判据要换判据，
不许放宽 `n ≥ 200`」。换判据的义务本文件**已经履行**——`K1/K2/K4` 三条今天就能跑，且不需要 200 条真实事件。
`K5` 恒 `inconclusive` 是**关于世界的事实**（动作轴一天个位数事件），不是判据设计失误。
把它写成「不过」而不是「待定」，是为了堵死 C1 点名的那条捷径：**没数据 ⇒ 没失败 ⇒ 可以上。**

## 5. 反向：`n2` 自己怎么死（对照必须可被杀，否则它是教条）

| # | 门/线 | 判据 | 不过 ⇒ |
|---|---|---|---|
| `S1` | 地盘准确率 | `10·hits_n2_C ≥ 9·\|C\|`（在自己开火的地方 ≥90%） | `n2` 降为探针，不得进基线；`K1/K2` 的上界随之升高（**学习候选可能因此复活**） |
| `S2` | 表长 | 实义行 ≤5 + 弃权行 1；逐行一句话可陈述；加行走 `DECISIONS` | 它成了一个没登记的模型，出局 |
| `S3` | 无时钟 | 规则表不读时间；若日后收令牌活性行，必须显式收 `as_of_ms` 并过 1000 次确定性 | 破确定性纪律 |
| `S4` | 现读 | 待决状态由会话现读，禁缓存、禁回放重建（§1.4） | 会漏掉 `commit_telegram` 那次静默清空，数字全错 |
| `S5` | 内容无关（D3） | 源码级：`n2` 不得调用 `pending_plan_hash()`，不得读 `preparation_id` / `memory_id` / `plan_hash` / 路径；`rg` 命中恒 0 | 待决状态里混进内容派生值，踩「文件名是数据」 |
| `S6` | 泄漏负对照 | `ACT-PEND-LEAK`：把真值标签整体打乱后重跑，`n2` 在 `C` 上的命中必须掉到 `n0` 在 `C` 上的水平（差 ≤2 点） | 待决状态是由目标事件本身派生的 ⇒ 管道泄漏未来 ⇒ **全部数字作废，先修 harness** |
| `S7` | 存在性 | 若某剖面上 `\|C\| = 0`（§4.4 的离线用户），该剖面上**不得声称有对照** | 「有对照」变成一句空话 |

**`S1` 与 §4 的耦合是故意的，也是本文件最想让人看见的结构**：
`n2` 越准，学习的天花板越低，学习越容易被处决；`n2` 不准，天花板抬高，学习复活。
**对照与被照者的命运用同一个整数绑在一起**——这才叫对照，而不是一个陪跑的地板。

### 5.8 `n2` 上屏时的可数性豁免（本轮的一条小裁决）

C1 要求每个上屏结论配一句「N 次里有 M 次」。`n2` 是规则，没有计数，配不出这种句子。
**裁：状态陈述不受可数性约束，但必须满足两条**——
(a) 它只复述**当前状态**（「你准备好了一封回信，还没生成。」），不含任何比例、频次或预测措辞；
(b) 它不得与任何统计句拼在同一张卡片上（拼了，用户会把状态的确定性转移给统计的不确定性）。
凡越过这两条的句子，走 COPY 冻结流程，并适用 C2R1 门 `D6` 的禁词面。

### 6.1 被杀名单（精确列举，不许扩大也不许缩小）

### 6.2 三级处置

| 级 | 触发 | 后果 |
|---|---|---|
| **墓碑** | `K1/K2` 三剖面全处决；或 `K4` 不过 | 写入 `REJECTED` 台账（格式照 `docs/algorithms/REJECTED.md`：候选 ID、触发夹具/判定、当时的普查整数、复活条件）；实现删除 |

### 6.3 三条纪律

1. **改名禁令**：新候选提交时必须声明「它与墓碑上哪一条的差别在哪」，**差别不能只是超参**。
   （C1 对 `APPM-lite` 的处置是先例。）
2. **面分离**：动作轴的学习被杀，**不影响** Cycle 1 的 next-app 轴与何时轴，反之亦然。
   任何跨面援引杀线的说法，先证明两个面的机会集是同一个（它们不是）。
3. **顺序**：**普查在建表之前。** R1 §9 争点 2 由此裁掉——
   `K1/K2` 不需要 G17 那张持久化历史表就能算，所以**先跑普查，再决定要不要建表**；
   反过来做就是先建表再找用途，而那张表是一张「你都干了什么」的新表，举证责任在提议建表的人身上。
