# Cycle 2 Round 1 fable-b — 下一动作 / RPA 算法：非法清单与 HITL 建议器可为边界

定位：Cycle 2 代理层调研的「下一动作建议」子轨。本文件是套在该子轨全部候选之前的**否决筛**（第一节）加 **HITL 建议器 MAY 白名单**（第二节）。依据：`docs/PRODUCT_LOCK.md`（不可协商 #1/#4/#8/#9/#10、「不是无人值守 AutoGPT，也不是可永久允许一切的系统管理员」、v0.1 明确不做清单）、`docs/SECURITY.md`（HITL 与注入节）、`docs/STATUS.md` AC-19 已落地事实、`cycle2/CONSTRAINTS.md`。

**类型区分，先立后破**：Cycle 1 的 next-app（P0–P8，已冻结）预测的是**用户**接下来开哪个 exe，本轮不重开、只读消费。本子轨的「下一动作」是从 **Soul 自己的已知动作枚举**（起草、预览、重扫、提醒、v0.1.1 的可逆移动执行）里选一张建议卡。RPA 文献里的「next action」几乎全是前者的超采集版（键鼠/屏幕粒度）加后者的无人值守版——所以这张筛比 Cycle 1 的更严：大半个 RPA 算法空间在 Soul 里是整族非法。

## 一、整族非法的下一动作 / RPA 做法（一票否决，无论效果）

每条给出：做法（含文献/工具对应物）、违反的锁、审查/CI 怎么抓。

### X1 无人值守代理循环（unattended agent loop）

**非法做法**：AutoGPT / BabyAGI / computer-use 式的 plan→act→observe→replan 循环；UiPath「unattended robot」形态；「批准一次目标，然后自己跑一小时」；失败后自动重规划并在**同一份批准**下继续执行。
**违反**：PRODUCT_LOCK「不是无人值守 AutoGPT」；v0.1 明确不做「无人值守」；不可协商 #4（不可逆操作人在回路）、#9（能力令牌一次性）；D24。
**怎么抓**：计划类型是**有限动作列表、整体哈希**——没有循环原语，运行时追加一步就改变 `plan_hash`，AC-19 现有测试直接拒。CI 断言配置面不存在 `auto_approve` / `always_allow` 键。任何候选文档里出现「重试后继续」「批准有效期内自动执行后续」字样即墓碑。

### X2 任意 shell / 生成脚本再执行

**非法做法**：动作词表里有自由字符串命令（`run_shell`、`powershell -c …`、eval）；让 LLM 写脚本然后跑；把「打开终端替用户输入命令」包装成建议。
**违反**：v0.1 明确不做「任意 shell」；D24 未知动作拒绝——自由字符串命令是**未知动作洗钱**：一次批准走私无界动作空间，令牌的「限作用域」失去意义；不可协商 #1（日常不提权）。
**怎么抓**：动作枚举里没有 spawn 类型；产品 crate（policy/agent/core，xtask 与测试除外）源码断言无 `std::process::Command`，与零 E0 审计同法。候选的「输出」栏含任何自由文本可执行体即墓碑。

### X3 键鼠粒度采集与合成（task mining 采集侧 + 宏回放执行侧）

**非法做法**：采集侧——用按键/点击/剪贴板事件流学「用户下一步」（RPA task-mining 的标准输入，本质是键盘记录器）；执行侧——`SendInput`/`keybd_event` 合成键鼠、AutoHotkey 宏回放、SikuliX 式视觉找按钮再点。
**违反**：采集锁「无键盘记录、无密码框」「仅前台 exe+时长」；v0.1 明确不做「键鼠接管」；数据面白名单没有也**永远不会有**键鼠事件流——这不是推迟，是采集面本身被锁。
**怎么抓**：候选输入栏对表四个数据面（前台会话、T4D 边字段、A0 轴、derived 计数）加授权根内文件**元数据**；产品 crate 符号审计禁 `SetWindowsHookEx` / `GetAsyncKeyState` / `SendInput`。训练数据写着「用户操作轨迹（键/点击粒度）」的候选直接墓碑。

### X4 屏幕与 UI 树采集（screen/task mining 变体）

**非法做法**：常驻截屏、accessibility 树抓取、窗口标题 n-gram、OCR 屏幕内容当上下文——商业 RPA 的 process discovery 全家桶。
**违反**：「窗口标题永不采集」（cycle2 CONSTRAINTS 原文）；v0.1 明确不做「常驻截屏」；S3（超采集面）在代理层的同族。
**怎么抓**：同 X3 输入对表；任何「需要知道用户此刻在屏幕上看什么」的候选墓碑。前台 `AppIdentity` + 时长是唯一合法的「用户在干什么」信号。

### X5 外部内容变成建议（注入通道）

**非法做法**：从文件名、导入聊天正文、粘贴文本里的祈使句派生下一动作——「邮件说付款 → 建议付款」「文件名叫 `请删除我.txt` → 建议删除」。LLM 读文件正文做分类/建议在 fileplan 轨道默认禁（读正文 + 默认出网与第三人锁冲突），在下一动作轨道同样默认禁。
**违反**：不可协商 #8（外部内容不能变成指令或授权）；SECURITY.md 注入节（导入/粘贴/文件名只进数据通道）；AC-25 红线。
**怎么抓**：AC-25 用例族扩到建议器——fixture 里埋祈使句文件名/正文，断言**任何**建议卡的动作与参数都不回显该祈使内容。建议的触发因子只能是白名单数据面上的计数与事实，不能是内容语义。

### X6 置信度放行 / 学习型风险分 / 永久允许

**非法做法**：「模型置信度 > 0.9 免批准」「低风险分动作自动执行」「本类动作永远允许」开关；用学习到的连续标量当执行门。
**违反**：#9 能力令牌一次性（永久允许 = 令牌无限重放）；#10 不可纠正黑盒（门槛标量无证据句可渲染）；#4；PRODUCT_LOCK「不是可永久允许一切的系统管理员」。
**怎么抓**：执行门必须是表驱动可枚举策略（`hitl.rs` 现状），不存在任何 float 阈值参与放行决策；`refuse_execution` 与 `soul_policy::hitl::check_action` 的理由码一致性测试已在（STATUS.md）。若日后想给「可逆小动作」减摩擦，唯一通道是父代理 DECISIONS 改锁，不是本调研发明第二套门。

### X7 批准后计划可变（TOCTOU 族）

**非法做法**：批准计划模板、运行时回填参数；批准后目录变了继续按旧计划执行；用旧批准跑「等价改写」后的新计划。
**违反**：#9 计划哈希变化拒绝；这正是 AC-19 三条已测路径（改目的地/改计数/批准后目录里多了文件再重扫 → `PLAN_HASH_MISMATCH`）防的东西。
**怎么抓**：已有机器——批准必须原样 echo `preparation_id` + `plan_hash` 两样（计数型计划会哈希撞车，光哈希不够，这是 WP 实测撞出来的）；`preview_id` 只活在 session 内存，重启即失效；v0.1 写文件令牌「即使完美也拒绝」。候选只要复用这条链就安全，试图绕开任何一环即墓碑。

**继承项不再重开**：自动发送消息（Cycle 1 S7/N5，v0.1 只起草不发送）、预测驱动预启动应用（R2 已裁预取出局）、把建议当 A0/T4D 证据落库（Cycle 1 S8/N8 单向玻璃）。

## 二、HITL 下一动作建议器 MAY do（白名单，逐条给证伪法）

**卡片形态五条**（共同约束，先于一切候选）：

1. 输出类型是「建议卡」，值域 = 已知动作枚举 × 可枚举参数（exe 名、联系人、授权根、扩展名桶）。无自由字符串动作。
2. 每张卡渲染一句 A2 式证据句，只含已算好的计数/事实。
3. **建议 ≠ 授权**：卡上的「去做」按钮只是既有 HITL 链的入口（预览 → echo `preparation_id`+`plan_hash` → 一次性限域限 TTL 令牌），建议卡不缩短这条链的任何一环。
4. 纠正是锁：单卡类型可关闭，关闭后不再出现，后续不覆盖。
5. 全本机：接受/忽略信号只落本机计数，零 E0，永不回传。

### A1 触发式建议卡（trigger→card 规则表）

- **形态**：可枚举触发事实 → 卡的静态映射表。例：T4D 降档已发生 → 「起草问候」卡（即 Cycle 1 M3 在代理层的落点）；授权根自上次扫描新增 ≥N 文件 → 「重新预览整理计划」卡。
- **证据句**：「{根} 自上次预览新增 14 个文件」——纯计数。
- **证伪**：模板绑定测试（COPY_ZH 同法）+ 同屏一致性断言「卡出现 iff 触发事实成立」+ X5 注入红线回放。

### A2 fileplan 下一步（该看哪个授权根）

- **形态**：多个授权根之间按**单一可审计事实**排序（新增文件数降序，或距上次预览天数降序）——按事实排合法，合成加权分即触 Cycle 1 S2。执行类建议必须携带所指计划的 `plan_hash`；目录一变，卡自动降级为「重新预览」，绝不携带旧哈希去撞执行面。
- **证伪**：哈希失效测试——fixture 目录批准后写入一个文件，断言执行建议消失、重预览建议出现（复用「哈希稳定直到目录变」的既有测试形状）。

### A3 未竟事务提醒

- **形态**：「你有一份 {n} 天前的未发送草稿」「有一份已批准未执行的整理计划（v0.1.1）」。纯本地存储事实复述，零推断。
- **证伪**：平凡——存在性断言加模板绑定。

### A4 参数预填不预批

- **形态**：卡可以预选参数（问候对象从沉寂天数最大的 T4D 边预选；移动目标桶从扩展名映射预选），用户在批准屏上仍看到并可改全部参数。
- **界线**：预填改变默认值，不改变批准链长度；预填值必须与批准屏渲染值逐字段一致。
- **证伪**：预填/批准屏一致性断言；改预填参数后 `plan_hash` 必变的属性测试。

### 学习规则（建议器唯一允许的「学习」）

按卡类型累计整数接受/忽略计数：忽略 ≥k 次可压制该类卡，接受计数可参与重排——排序仲裁继承 Cycle 1 P7 纪律（单一事实排序、并列字典序、弃权合法），禁止除法合成率值上屏。关闭是锁，压制是可逆偏好，两者不混。**证伪**：属性测试（压制阈值行为、锁优先于计数）；本机 accept/dismiss 计数是唯一验收信号，开发期用离线 fixture replay，发布后无任何回传通道。

## 四、十问速筛（本子轨候选先答，任一不合即墓碑或降为离线陪跑）

1. 动作值域是否为已知动作枚举，零自由字符串？
2. 输入是否 ⊆ 四数据面 + 授权根内元数据，零键鼠/屏幕/标题/正文？
3. 是否存在任何无人值守的多步执行路径？
4. 每次执行是否走完整既有 HITL 链（preparation_id + plan_hash echo + 一次性令牌）？
5. 是否存在 float 阈值或「永久允许」参与放行？
6. 计划批准后任何变化是否必然导致拒绝？
7. 外部内容祈使句是否有红线用例证明不回显为动作？
8. 每张卡是否有纯计数证据句、可单类关闭且关闭是锁？
9. 接受/忽略信号是否只落本机，零 E0？
10. 是否有离线 fixture replay 或属性测试可证伪？
