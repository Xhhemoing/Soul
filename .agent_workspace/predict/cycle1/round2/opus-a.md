## 0. 三句话

1. **P4 降为对照（comparator），v0.2 不作默认打扰门。** 不是因为它弱，是因为它的主杀线在真实日志上**不可判定**：它测的是会话起始的速率，而本机日志里速率的第一驱动力是采集器在不在线、同意有没有被撤销（G3）。在「采集在线」这件事本身可观测之前，P4 的 `REAL-*` 数字不可采信，一个数字不可采信的候选不配当默认。
2. **「P4 打过 P1」在 SYN Markov 源上是良置的，但结论方向与 R1-SYNTHESIS 那句话相反。** 一阶 Markov 应用序列 + 齐次 Poisson 起始的源上，P4 的**正确表现是测不出区分度**；谁在这个夹具上报出「P4 赢了 P1」，报的是 bug 不是战绩。真正的对手不是 P1 的 top-1，是 P1 已经维护的那张转移表上顺手能读出的一个 app 条件时序基线（下称 `C3`）。
3. **不变式 F 保留，并且加固三处。** 现有表述里有一个前提不成立——桶键**不是**单条事件字段的纯函数（规范化会合并/丢弃相邻段），所以 `decrement` 必须重定义为**有界局部重算**；同时 P4 应当靠「不留持久状态」把 F 变成**构造性成立**，而不是测试性成立。

## 1. 语境：三个议题共同的地基（与 opus-b 的数据面差异）

opus-b §0.1 的 S1 假定前台会话可读到 `duration_s` 与**本机时区偏移**。本槽 round1 的盘点结论是这两样今天都没有：

| opus-b 假定 | 盘上实况（round1/opus-a §1.1、G2、G5） | 对本轮三议题的影响 |
|---|---|---|
| `duration_s` 可读 | 在 `SealedSessionBody` 里，`events` 表无此列；**任何时长统计必须持 content key 逐条解封** | P4 的段规范化（`MERGE_GAP_S`/`MIN_SESSION_S`）需要 app 与时长 ⇒ **持钥**；而 P4 的全局起始流只要 `ts` ⇒ **不持钥**。两者是**两个统计量**，见 D3 |
| 本机时区偏移可读 | 全仓没有；`rfc3339_utc` 只产 `Z` | P4 把基线强度 μ 外包给 P3 的方案在 v0.2 **无法落地**（P3 的桶只能是 UTC 小时），见 D6 |
| `app` 可 SQL 聚合 | 密封体内；研究预览的滚桶把所有 exe 合成一个 `app.foreground` 计数 | `p4a`（全局、明文）可 SQL 出，`p4b`（分 app）不可，见 D3 |
| 缺席可解释 | 不可：关机 / 锁屏 / 无焦点 / 采集未开 / **同意被撤销后丢弃在飞会话** 五种同形，`Tally.sessions_discarded` 不落库（G3） | 这是 D1 的全部理由 |

一句话：**P4 是九个候选里唯一一个「输入几乎全在明文、但语义几乎全被缺席污染」的候选。** 它同时是最便宜的和最不可判定的。下面三条决策就是围着这个矛盾走的。

## 2. R2A-D1 —— P4 降为对照，v0.2 不作默认打扰门

**状态**：已定（本调研范围内）。**推翻的上位表述**：R1-SYNTHESIS「P4 …… 须打过 P0/P1 才配做默认」——该句的比较是错位的（见 D2），本条与 D2 合起来替换它。

### 语境

支持 P4 当默认的理由只有两条，都成立但都不够：

- **A1（真资产）**：它是九个里**唯一**只吃 `events.ts` 明文就能算的候选。`SELECT ts FROM events WHERE kind='app.foreground'` 就是它的全部输入（全局流）。别人都得持钥。
- **A2（真资产）**：它对 G4/G8 的采样伪影**免疫**。`ts` 只到秒、同秒并列、`event_id` 的顺序是实现细节不是契约——这些坑 P1/P2 必须踩（它们要按 `(ts, event_id)` 重排才有转移对），而 P4 的桶宽是 300 秒，tick 内事件顺序不影响 `excite`（opus-b F4-4 已经写了这条）。

反对的理由有五条，其中第一条是**判定性**的：

- **B1（判定性）：它测的量与「采集器在线时段」不可分辨。** P1 条件在「上一个 app」上，采集中断只是在断点处少了几个转移对，转移表本身不偏；P4 条件在「最近的事件密度」上，而采集中断**直接就是**密度归零、恢复即密度陡升。更毒的是缺失非随机：`poll_once` 遇 `ConsentWithheld` 会 `discard_open()` 丢弃在飞会话，`finish()` 无同意时也丢弃——这是**由用户行为触发的、成块的**删除。在这种掩码下，任何自激核都会在每个恢复点报 `burst.hot`。
  出路只有三条，今天全堵：(i) 用审计链 `collect.start`/`collect.stop` 当特征——**禁**，那是用一张**永不被遗忘**的表去解释一张**可被遗忘**的表（round1 §3）；(ii) 从数据本身推在线时段——循环论证，事件密度正是待测量；(iii) 持久化 `sessions_discarded` 或加心跳事件——**不在本调研范围**，登记为 G15（§7）。
- **B2：μ 无处安放。** λ = μ + Σα·e^{−β·Δ} 的分解里 μ 由 P3 承担，而 P3 需要本机墙钟小时，G2 说没有。于是 v0.2 的 P4 只能报「相对于最近的突发」，报不了「相对于你这个时段的常态」。见 D6。
- **B3：F4-2 这条反向测试按现写法无效。** 「把每天的会话起始时刻在当天内随机重排」同时**摧毁自激与日内节律形状**，所以它不能把「读到自激」和「读到节律」分开。正确的零假设必须**保节律**，见 D5-K5。在 F4-2 被修好之前，P4 没有一条有效的反向测试——没有有效反向测试的候选不能当默认。
- **B4：半衰期是猜的。** opus-b 自己写了（§2.5 已知缺陷、§6 未决 1）。默认不该压在一个未测常数上；对照可以。
- **B5：第三道门没有账。** P5 有 `COOLDOWN_DAYS`/`MAX_DAILY_REMINDERS`，P8 有停留门，全局打扰预算**不存在**（opus-b §6 未决 6）。在没有总账之前加第三道门，组合行为不可测，只可能更吵。

### 决策

1. **v0.2 的默认打扰时机由 P8 + P5 的频控决定。P4 不进默认路径。**
2. P4 保留为**具名对照**，在「何时」这条任务上与 `C0/C1/C2/C3`（§4.1）并列评测，结果如实登记。
3. P4 **不得**进入 P7 的仲裁输入集（P7 的输入恒为 {P0,P1,P2,P3}），也**不得**改变任何 `next_app` 输出——见 K2 的源码级断言。
4. P4 的 `REAL-*` 数字在 G15 补上之前一律标注 **inadmissible（不可采信）**，可以跑、可以看，不可作为任何晋级依据。

### 后果

- 「何时打扰」这件事 v0.2 **没有**基于时序的信号，只有停留门 + 冷却期。这是有意的降级：**宁可门少一道，不要一道读不懂自己在读什么的门。**
- 省下的不只是 P4 的实现：省下了「P4 与 P8 与 P5 三门组合」这一整块无法归因的评测面。
- A1 那条资产没有浪费——它变成了 D3 里 `p4a` 的存在理由（一个不持钥就能算的、诚实标注为「事件密度」而非「用户突发」的量）。

### 翻案条件（晋级为默认的完整路径，四条全要）

1. **G15 落地**：events 表里有**可被遗忘的**采集在线信号（持久化 `sessions_discarded`，或 `collector.heartbeat` 事件）。审计链不算数。
2. **K6 通过**：在 `ADV-uptime` 掩码夹具上，掩码带来的**表观区分度**低于 K1 的零假设阈值；或存在不读审计链的校正把它压下去。
3. **K3 与 K4 通过**：分别打赢盒核 `C1` 与 app 条件基线 `C3`（§4.2），margin 见表。
4. **全局打扰预算存在**，且「P8 + P5 + P4」三门组合有一条像 F8-3 那样的、直接测打扰质量的杀线。

四条缺一，P4 停在对照位。**四条全过也只是「可作默认候选」，仍要按 §4 的表跑完再定。**

### 钉它的测试

K6（uptime 混淆）、K3、K4；以及一条纪律测试 `D1-guard`：predict 侧的默认打扰路径对 `p4.*` 的引用数为 0（形状同 opus-b F6-3 的源码级断言，测试自身的反向断言处排除）。

## 3. R2A-D2 —— 把「P4 vs P1」重述为良置比较

**状态**：已定。**替换**：R1-SYNTHESIS「P4 …… 须打过 P0/P1 才配做默认」与 opus-b F0-1 对 P4 的适用性。

### 语境

F0-1 写的是「对任一其它候选 `Px`，若 top-1 不高于 P0，`Px` 出局」。这条对 P0–P3、P7 成立，对 P4 **不成立**，因为 P4 的预测量根本不是 `next_app`：

| | 预测量 | 标签 | 命中率的定义域 |
|---|---|---|---|
| P0/P1/P2/P3/P7 | 下一个 app 是谁 | 下一段的 `app_id` | 每次转移一格 |
| P4 | 接下来还会不会很快有动作 | `[t, t+900s)` 内是否出现下一次起始 | 固定 tick 栅格上一格 |
| P8 | 当前这段还会不会继续 | 当前段是否结束于本桶 | 每段一格 |

拿 top-1 命中率去比 P0 和 P4，是在两个不同的样本空间上比两个不同的指标。**它们唯一真正共享的东西是下游决策：「现在该不该打扰」。** 良置的比较必须建在这个决策上，且必须有一个「P1 家族」的对手站在同一条任务上——那个对手不是 P1 的 top-1，是 P1 已经维护的那张行表上顺手能读出的 `C3`。

### 决策

1. **P4 不参加 `next_app` 的排行榜，不适用 F0-1。** P4 的排行榜是「何时」任务，对手是 `C0/C1/C2/C3`。
2. **`SYN-M1P`（一阶 Markov 应用 × 齐次 Poisson 起始）是 P4 的负对照，不是擂台。** 该源的起始过程无记忆，因此：
   - P4 的正确表现：**测不出区分度**（K1）；
   - `C3` 的正确表现：**同样测不出区分度**（起始与当前 app 独立）；
   - P1 的正确表现：逼近该转移矩阵的贝叶斯上界（opus-b F1-3 已有）。
   **在这个夹具上「P4 赢 P1」这句话没有可成立的读法。** 若报告里出现它，先查 §5 的 D4 泄漏（当前 tick 未闭合），再查生成器，最后才怀疑算法。
3. 真正的擂台是 `SYN-M1H`（两者都有信号且独立）与 `SYN-APPTIME`（时序由当前 app 决定，`C3` 的主场）。

### 后果

- 评测报告必须**分两张表**出：`next_app` 一张（P0/P1/P2/P3/P7），`何时` 一张（C0/C1/C2/C3/P4/P8）。混在一张表里出的数字一律退回。
- P4 的「主杀线」从 opus-b F4-1 的单条（hot ≥ 2× cold）扩到 §4.2 的 K1–K8，其中 K1 与 K6 是**负对照**（必须测不出），K3/K4 是**正面擂台**（必须测得出且赢够）。负对照先过，正面成绩才被受理。

### 翻案条件

若后续轮次给出一个把「哪个 app」与「何时」合并成单一可数指标的定义（例如「下一次动作的 (app, 是否 15 分钟内) 联合 top-1」），且该指标在 `SYN-M1P` 上不会退化成 P1 独赢的平凡量，则本条重议。目前想不出这样的定义，所以先分开。

### 钉它的测试

K1（`SYN-M1P` 负对照）、K4（`SYN-APPTIME` 与 `SYN-M1H` 上对 `C3` 的擂台）、以及报告格式的纪律检查（两张表分开）。

## 4. 夹具与杀线（D2 的执行细节）

### 4.0 评测时点的定义（先钉这个，否则下面全是废话）

- **时点栅格**：`T = { t : t = m·TICK, t ≥ span_start + W·TICK, t + 900 ≤ span_end }`。**必须是与结果无关的固定栅格**——不许「在每次会话起始时评测」，那等于条件在「刚刚发生了一次事件」上，`hot` 的复发率被结构性抬高。
- **暖机**：跳过前 `W` 个 tick，保证环形量在每个时点都被完整决定。
- **右删失**：`t + 900 > span_end` 的时点丢弃，不计入任何分母。
- **标签**：`Y(t) = 1` iff 在 `[t, t+900)` 内出现至少一次（规范化后的）会话起始。
- **`as_of` 显式传入**，禁读墙钟（沿用 opus-b §0.4.3）。

### 4.1 对照阶梯（「何时」任务）

| ID | 定义 | 状态量 | 存在理由 |
|---|---|---|---|
| `C0` | 常数（取多数类） | 0 | 一切区分度的地板 |
| `C1` | **盒核**：最近 3 个 tick（15 分钟）内起始数 ≥ 1 | 3 个整数 | 若 P4 赢不过它，**指数核这套装置就没有存在理由**——盒核也是 Hawkes，只是核形状最笨 |
| `C2` | UTC 小时桶基率（**诚实标注**：这是 UTC 的小时，不是「用户的上午」，G2） | 24 或 48 个整数 | 节律对照。它自己因 G2 也是残废的，所以只当对照不当默认 |
| `C3` | **app 条件时序基线**：`count(900s 内有下一次起始 \| 当前 app = a)` 对 `count(当前 app = a)` | 每 app 两个整数，**挂在 P1 已有的行上** | **这就是「P1 家族」在何时任务上的形态**；它是 P4 的真对手 |
| `P4` | 量化 Hawkes 环（`p4a`/`p4b` 两变体，见 D3） | W 个整数 × 流数 | 待证 |

`C3` 的关键性质：它**不增加新的状态面**。P1 为了 `trans[a][b]` 已经在按 `a` 分行了；`C3` 只是在同一行上多挂两个整数计数。**所以「P4 输给 C3」等价于「P4 的整个环形缓冲是 P1 一张已有表的两个字段的冗余」**——这是 P4 最现实的死法，比「精度不够」现实得多。

### 4.2 夹具族

| 夹具 | 应用序列 | 起始过程 | 谁该赢 | 谁该测不出 |
|---|---|---|---|---|
| `SYN-M1P` | 一阶 Markov（已知 T） | 齐次 Poisson（严格齐次，无 burn-in、无节律） | P1（`next_app` 表） | **P4、C1、C3 全部** |
| `SYN-M1H` | 一阶 Markov（同 T） | Hawkes（已知分支比） | P1（app 表）+ P4/C1（何时表） | C3（时序与 app 独立） |
| `SYN-I0H` | i.i.d. 边缘分布 π | Hawkes | P4/C1 | P1（退化到 P0）、C3 |
| `SYN-M1D` | 一阶 Markov | 非齐次 Poisson（日节律，**无自激**） | C2 | **P4**（测出来即读到节律，见 K5） |
| `SYN-APPTIME` | 一阶 Markov | 起始间隔由**当前 app** 决定（如 `launcher.exe` 后必有簇） | **C3** | 视核而定；P4 可能赢也可能输，输了要如实登记 |
| `ADV-uptime` | 同 `SYN-M1P` | 同 `SYN-M1P`，外加**成块且自身成簇**的观测掩码（在线 2–6 小时块） | 无人该赢 | **P4 必须仍测不出**（K6）——这是 D1 的判定夹具 |
| `ADV-flood` | 单 app 刷屏 | 5 秒切换 ×1000/天 | — | 钉读时截断与 W 截断（K7） |
| `ADV-adjacency` | `A(10s), B(20s), A(10s)` 及其变形 | — | — | 钉 `decrement` 的局部重算（K8） |

### 4.3 判据用整数比较（沿用 P5 的交叉相乘纪律）

令某状态划分下 `a = Σ Y(t)`（该状态下命中数）、`n = |{t}|`（该状态下时点数）。

- **区分度成立**（形如「hot 复发率 ≥ cold 的 2 倍」）：`a_hot · n_cold ≥ 2 · a_cold · n_hot`。
- **区分度不成立**（零假设，阈值 1.2 倍）：`10 · a_hot · n_cold < 12 · a_cold · n_hot`。
- **甲赢乙 ≥ 25%**：`4 · a_甲 · n_甲' · n_乙 · a_乙' ≥ 5 · a_乙 · n_乙' · n_甲 · a_甲'`（四元乘积，harness 用 `i128` 精确算）。
- **浮点只许出现在自助置信区间里**（内部评测量，opus-b §0.6 已放行），但**通过/不通过的那一步比较必须是精确有理数**——最后一位上翻来覆去的测试比慢测试坏得多。
- **空虚保护**：任一分母 `n < 200` 或任一分子 `a < 20`，该判据返回 `inconclusive`；**`inconclusive` 一律按不通过处理**。没数据 ⇒ 没失败 ⇒ 可以上，是本调研里最需要提前堵死的一条捷径。

### 4.4 杀线 K1–K8

| ID | 夹具 | 断言 | 不过的含义 |
|---|---|---|---|
| **K1** | `SYN-M1P` | P4 的 hot/cold **区分度不成立**（1.2 倍阈值），且自助 CI 覆盖零 | 无记忆源上测出记忆 ⇒ 先查 D4 的当前 tick 泄漏，再查生成器，再查栅格与 tick 边界的相位相关。**这是实现/harness 的红灯，不是算法的战绩** |
| **K2** | 全部 | 接上 P4 前后，所有 `next_app` 输出**逐字节相同**；`p7.*` 源码不引用 `p4.*` | 「何时」的门改了「哪个」的答案 ⇒ 分层被穿透 |
| **K3** | `SYN-M1H`、`SYN-I0H` | P4 的区分度 **≥ 1.25 × `C1`** | 指数核不如盒核 ⇒ 用 `C1`，删掉环形缓冲与半衰期常数 |
| **K4** | `SYN-M1H`、`SYN-APPTIME`（至少一个 conclusive 的） | P4 的区分度 **≥ 1.25 × `C3`** | **P4 被 P1 已有的一张表的两个字段支配** ⇒ P4 出局，时序信号折进 P1 的行里。这是「vs P1」的正解 |
| **K5** | `SYN-M1D` + `REAL-*` 的**保节律重采样** | `SYN-M1D` 上区分度**不成立**；`REAL-*` 上区分度在保节律零假设下**仍成立**且 margin ≥ 1.25 | 读到的是节律不是自激 ⇒ 归 P3/C2，而 P3 因 G2 本身残废，诚实结论是「我们没有节律预测器」，不是「P4 是」。**本条替换 opus-b F4-2** |
| **K6** | `ADV-uptime` | 掩码带来的**表观**区分度低于 K1 的 1.2 倍阈值 | 采集在线时段被当成用户突发 ⇒ `REAL-*` 全部 inadmissible ⇒ **P4 不得为默认**（D1 的判定条） |
| **K7** | `ADV-flood` | `excite` 有**可证明的**上界（见 D5 引理二：读时截断后 ≤ 1440，装得下 u16）；`HOT` 不得恒真 | 恒真的 token = 无用 token（opus-b F4-5 保留） |
| **K8** | `ADV-adjacency` + 随机删除属性测试 | 不变式 F（局部重算版，见 D7） | 见 D7 |

**保节律零假设的构造（K5 用）**：不是 opus-b 的「日内均匀重排」（那把节律也一起摧毁了，于是这条测试什么也分不开），而是**非齐次 Poisson 自助**——按经验的 `(工作日/周末, UTC 小时)` 计数强度重采样起始时刻，保住日内形状，只摧毁形状之外的聚簇。种子固定，重采样 200 次，取区分度的经验分布。

## 5. R2A-D3 / D4 / D5 / D6 —— P4 规范的四处修订

这四条是「即便 P4 只当对照，也必须先改对，否则连对照的数字都不能信」。

### R2A-D3 —— 拆成两个具名变体，禁止串号

| 变体 | 输入 | 持钥? | 数的是什么 | 可 SQL 聚合? |
|---|---|---|---|---|
| `p4a.raw_start_ring.v1` | `events.ts`（`kind='app.foreground'`） | **否** | **原始事件行** | 是 |
| `p4b.segment_start_ring.v1` | 规范化后的段起始 | **是** | 合并去抖后的**段** | 否 |

**语境**：`MERGE_GAP_S`/`MIN_SESSION_S` 的规范化需要 `app` 与时长，两样都在密封体里（G5）。所以「不持钥就能算」这条资产**只属于 `p4a`**，而 `p4a` 数的量在焦点抖动下与 `p4b` 系统性不同（采集侧 `SameApp` 已经合掉一部分，5 秒去抖那部分没合，G8）。
**决策**：两个变体分别登记、分别评测；**任何报告不得把一个变体的数字挂在另一个名下**。默认引用 `p4b`（语义正确的那个），`p4a` 只在明确讨论「不持钥可算性」时出现，且必须诚实命名为**事件密度**而非用户突发。
**翻案条件**：若某天 `duration_ms` 或 app 类别以可聚合形式出现在明文列（那会同时作废 round1 §0 的结论），两变体合并。
**钉它的测试**：同一份 `REAL-*` 上两变体的 hot 时点集合的对称差要如实登记；差 > 10% 而报告只给一个数字，报告退回。

### R2A-D4 —— 修 `excite` 的当前 tick 泄漏（off-by-one）

**语境**：opus-b 写的是 `excite(now) = Σ_k start_count[k] >> ((tick(now) − k) / 12)`，求和含 `k = tick(now)`，即**当前这个尚未走完的 tick**。若 harness 先用全量事件建好计数表再在内部时点求值，`start_count[tick(now)]` 里就已经含有 `now` **之后**、同一 tick 内的起始——而 `TICK = 300s` 正是 900 秒预测窗的三分之一。**这会在任何源上凭空造出区分度，包括无记忆源。** K1 存在的第一目的就是抓它。
**决策**：`excite(as_of)` 只对**已闭合**的 tick 求和：`Σ_{k : (k+1)·TICK ≤ as_of}`。评测时点同时限定在 tick 边界上（双保险）。
**后果**：`excite` 对 `[as_of − TICK, as_of)` 内的事件**看不见**，即最坏 300 秒的反应延迟。对「打扰门」这个用途可接受；如果哪天不可接受，缩 `TICK` 而不是放开当前 tick。
**翻案条件**：无。这是正确性，不是取舍。
**钉它的测试**：K1；外加一条构造性单测——在 tick 内插入一次紧随 `as_of` 的起始，`excite(as_of)` 必须逐字节不变。

### R2A-D5 —— 读时截断 + 窗口收缩（打包，缺一不可）

**引理一（窗口截断，可证明而非实测）**：设半衰期 `h = 12` tick，距离 `d = tick(as_of) − k`，移位 `s = d / 12`（整除），项 `= c[k] >> s`。当 `c[k] < 2^s` 时该项**恰为 0**。若在**读路径**上对每桶取 `min(c[k], CAP)`，`CAP = 63`，则 `s ≥ 6` 时所有项恰为 0，即 `d ≥ 72` 的桶贡献恒 0。故 `W = 72` tick（**6 小时**）与 `W = 288` tick（24 小时）给出**逐位相同**的 `excite`。

**引理二（上界，同样可证明）**：读时截断后 `excite ≤ Σ_{d=0}^{71} 63 >> (d/12) = 12·(63+31+15+7+3+1) = 1440`，装得下 `u16`。opus-b F4-5 担心的 u32 溢出**由构造消除**，不必靠夹具去试。

**为什么必须打包**：不加 `CAP`，刷屏 tick（1000 次起始）在 `d = 72..83` 处仍贡献 `1000 >> 6 = 15`，`W = 288` 就不是死重，引理一不成立。反过来只加 `CAP` 不缩 `W`，白算 4 倍。而且 `CAP` 不只是省钱：**20 小时前的一次刷屏不该被叫做「现在很突发」**，截断在语义上也是对的。

**决策**：`CAP = 63` 施加在**读路径**；`W = 72` tick。
**关键约束（这条是 D7 的一半）**：**截断只许在读路径，绝不许在写路径。** 写时饱和加法（把桶本身钉在 63）会**当场破坏不变式 F**——70 次事件的桶饱和在 63，删一条后重放仍是 63，而 `decrement` 给 62。有损变换一律留在纯函数 `(counts, context, as_of) -> tokens` 里，存下来的状态必须精确可逆。**这条推广到所有候选，不只 P4。**
**后果**：`HOT = 8` / `WARM = 3` 两个阈值**不需要重新登记**——引理一说 `W` 从 288 缩到 72 时 `excite` 逐位不变，这是截断不是调参。只有 `CAP` 是真变化，且只在单 tick 起始数 > 63 时才咬到。
**翻案条件**：若半衰期从 12 tick 改档（`{30min, 1h, 4h}` 三档实测，opus-b §6 未决 1），`W` 必须按 `W = h · (1 + floor(log2 CAP))` 重算并重新登记；4 小时档下 `W = 48·6 = 288` tick（24 小时），死重就回来了——**半衰期选档与窗口大小是同一个决策，不许分开做。**
**钉它的测试**：K7；外加一条等价性单测——`W = 72` 与 `W = 288` 在全部夹具上 `excite` 逐值相等（引理一的可执行形式）。

### R2A-D6 —— v0.2 的 P4 不做 μ 分解，只报相对突发

**语境**：μ 由 P3 承担，P3 需要本机墙钟小时，G2 说没有。硬上就是拿 UTC 小时冒充作息（round1 §G2 已经点名这条不许做）。而且把 P4 的判据挂在 P3 身上，会让 P4 的杀线变成 P3 杀线的条件式，两个都测不干净。
**决策**：v0.2 的 P4 输出只有「相对于最近 6 小时的突发状态」，**不声称高于/低于该时段常态**。节律对照由 `C2` 独立承担（且诚实标注 UTC）。
**后果**：解释句只能是「过去一小时你开了 9 次前台会话，上一小时 6 次」这种纯计数（opus-b 原句就是这个形状，正好）；**不许**出现「比你平时这个点多」。
**翻案条件**：采集侧补上 UTC 偏移字段（round1 §4 第 1 件）之后重议 μ 分解。
**钉它的测试**：渲染层禁语句检查（同 R5 禁词面），比对基线的措辞一律拦截。

## 6. R2A-D7 —— 不变式 F 保留，并加固三处

**状态**：已定。**保留**：opus-b §0.5 的 `replay(events \ {e}) == decrement(replay(events), e)`，逐桶相等。**加固**：下面三条。

### F-1（修正前提）：桶键不是单事件字段的纯函数，`decrement` 必须是**有界局部重算**

**语境**：opus-b §0.5 的论证是「桶键全都是事件字段的纯函数，所以删一条事件时能算出该减哪个桶」，并据此说 F 对 P0–P3、P5、P8 天然成立。**这个前提对 P0–P4、P8 不成立**，因为 `MERGE_GAP_S` 合并与 `MIN_SESSION_S` 丢弃使得一条事件落进哪个段、构成哪个转移对，取决于**它的邻居**。

反例（`ADV-adjacency`）：原始 `A@0(10s), B@10(20s), A@30(10s)`，规范化得 A,B,A ⇒ `count[A]=2, count[B]=1, A→B=1, B→A=1`。删掉 `B@10`：
- `replay(E \ {B})`：`A@0(10s), A@30(10s)`，两段间隔 20s > `MERGE_GAP_S=5` ⇒ 两段 A ⇒ **`A→A = 1`**。
- 单桶 `decrement`：`count[B]=0, A→B=0, B→A=0`，**`A→A = 0`**。

两边不等。同理，把间隔改成 ≤ 5s 时删 B 会让两段 A **合并**，`count[A]` 该从 2 变 1，单桶减法也给不出来。**删除既能拆段也能并段。**

**引理三（删除的局部性）**：删掉一条原始事件 `e`，规范化后的段流的变化被限制在「`e` 所在的合并 run ∪ 紧邻的前一个 run ∪ 紧邻的后一个 run」之内——`e` 的删除只能把自己的 run 拆成至多两段，或让前后两个 run 并成一个；其余 run 的边界间隔未变，故不受影响。**受影响的 run 至多 3 个**，因而 P0/P1/P4 至多触及 O(1) 个桶，P2/P3/P8 同样 O(1)（常数更大）。

**决策**：`decrement(state, e, as_of)` 定义为「在这 ≤3 个 run 上重跑规范化，取桶增量」，**不是单桶减一**。有界局部重算仍是 O(1) 摊销，§0.4 的纪律不破。
**钉它的测试**：`K8` = `ADV-adjacency`（上面那三种形状：拆段、并段、跨 `SESSION_GAP_S` 边界生灭）+ 一条固定种子的属性测试：10⁴ 组随机 `(夹具, 事件)`，`local_decrement(replay(E), e) == replay(E \ {e})` 逐桶相等。
**注意**：opus-b 的 F1-4 / F3-5 / F4-3 / F8-4 若用「单桶减一」实现，会在**从不制造新邻接的夹具上全绿**。所以 F 的测试集**必须**含 `ADV-adjacency`，否则这四条测试是空转的。

### F-2（参数化）：F 必须对每个 `as_of` 成立，且窗口外的删除必须是**有类型的 no-op**

**语境**：P4 的状态是最近 `W` 个 tick 的环，环索引是 `tick mod W`。**一条已被移出窗口的事件，其 tick 仍能取模映射到一个活桶上**——朴素实现会去减一个跟它无关的桶，静默污染状态。这是环形缓冲的经典 bug，而且它只在「遗忘一条较老的事件」时才触发，正是最不容易被随手测到的路径。
**决策**：不变式写成 `∀ as_of: replay(E \ {e}, as_of) == decrement(replay(E, as_of), e, as_of)`；当 `tick(e) < tick(as_of) − W` 时 `decrement` 必须是**有类型的 no-op**（返回「窗口外，无变化」，不是悄悄取模）。
**钉它的测试**：`F4-3b`：遗忘一条早于窗口的事件，环内每个桶逐字节不变；再补一条「恰好在窗口边界上」的事件（`tick(e) == tick(as_of) − W`），两侧行为必须与全量重放一致。
**顺带**：`decrement` 与 `update` 在整数桶上可交换，断一条 `F4-3c`：先删后加 == 先加后删。

### F-3（覆盖面）：F 只管「事件被移出输入集」，不管「遗忘并没有移出输入集」

**语境**：这条是本槽 round1 的 G12 在 P4 上的具体化，也是我认为最需要写进记录的一条。遗忘的实现是**销毁 content key + 派生降 orphan**；`events` 行的明文 `ts` 列**并不因此消失**。而 `p4a` 的输入**恰好只是 `ts`**。于是：

> 用户遗忘了某段采集期之后，`p4a` 的突发统计量仍可从残留的明文 `ts` **精确重建**。不变式 F 对此**一声不响**——因为 F 的前提是「事件被从输入集里删掉了」，而这里没有。

**F 是必要条件，不是充分条件。** 补一条：

> **不变式 F′（遗忘覆盖）**：候选消费的每一个输入字段，都必须在遗忘后**被删除或不可读**。

`p4a` 违反 F′。可选的两条出路：

- **(a) 不持久化。** 环不落库，每次求值从 `events` 的 `[as_of − 6h − LOOKBACK, as_of)` 区间现算。这样 P4 **不比 store 本身多记住任何东西**，泄漏面回落成 store 层的 `ts` 保留策略问题，不是 P4 的问题。
- **(b) 持久化则必须挂 `content_key_id`**，进 forget 预览（G12 的一般要求）。

**决策：取 (a)。P4 不留持久状态。**
理由与代价：
- 引理一把窗口压到 6 小时，现算的成本是**先验有界**的：区间内起始数 `R ≤ 6h / MIN_SESSION_S = 7200`，7200 次整数加移不值一提；`p4b` 还要解封同一区间的 body，几百条，同样不值一提。
- 需要 `LOOKBACK_S = 1800`（`SESSION_GAP_S`）的前置读窗，否则跨窗口起点的合并 run 会被切错。
- **副产物：不变式 F 对 P4 变成构造性成立**——没有增量状态就没有 `decrement` 这条代码路径，F 退化成「纯函数对输入集的单调性」，K8 只需断言 `f(E \ {e}) == f(E)` 在 `e` 落在窗口外时相等、落在窗口内时等于重算。opus-b 为了保 F 而把累加器换成环形桶的那次自觉交换是对的，但**还可以再走一步：不留状态比留可逆状态更强。**
- 代价：`p4a`/`p4b` 从「摊销 O(1) 更新」变成「O(R) 读」。§0.4.1 的意图是禁无界状态与训练，零状态不违背它；但这一步必须写在明处，不能悄悄换。

**翻案条件**：若求值频率高到 O(R) 读成为瓶颈（例如每秒求值），才重议持久化，且必须先解决 F′（挂 `content_key_id` 或进 forget 预览）。
**钉它的测试**：`F′-1`：模拟一次遗忘（销毁 key），断言 P4 的输出与「该段从未采集」的重放**不可区分**；对 `p4a` 这条今天**会红**，红得对——它精确地记录了 F′ 的缺口，不许为了让它绿而改断言。

## 7. 新缺口 G15 / G16（承接 round1 的 G1–G14）

**G15 —— 没有可被遗忘的采集在线信号。** 区分「没用电脑」与「采集没开/同意被撤销」的唯一计数器 `Tally.sessions_discarded` 不落库；能区分的只有审计链，而审计行永不被遗忘，拿它当特征等于造遗忘旁路。**后果**：任何以事件**速率**为统计量的候选（P4 首当其冲，`C1`/`C2` 同样）在真实日志上不可判定。**这是 P4 晋级为默认的第一前置件，也是 D1 的全部理由。** 补法两种：持久化 `sessions_discarded`（进可遗忘的表），或加一条低频 `collector.heartbeat` 事件。两者都是采集侧改动，不在本调研范围，只登记。

**G16 —— 遗忘不移除明文 `ts`，于是 F 有覆盖盲区。** 见 D7 的 F-3。这不是 P4 独有的问题，是「遗忘 = 销毁密钥」这一实现与「派生统计量的输入是明文列」这一事实之间的一般性缺口；P4 只是第一个把它顶到台面上的候选，因为它是唯一一个输入**全在明文列**的候选。

## 8. 考虑过并拒绝的备选

| 备选 | 拒绝理由 |
|---|---|
| 保留 P4 为默认，靠 `ADV-*` 夹具「证明它稳健」 | 夹具证明不了 G15 那种**结构性不可观测**。合成掩码能测出「有多糟」，测不出「真实日志里掩码长什么样」 |
| 用审计链 `collect.start/stop` 校正 uptime 混淆 | 用永不被遗忘的表解释可被遗忘的表（round1 §3）。宁可 P4 不当默认 |
| 直接砍掉 P4 | 过头了。它在 `SYN-I0H` 上有明确的、可测的正面预期，而且是唯一不持钥可算的量。**对照位是它挣得到的**；默认位不是 |
| 把 P4 塞进 P7 仲裁当第五个源 | 预测量不同（何时 vs 哪个），塞进去会让 P7 的 F7-1「≥ 全部单源最大值」失去定义 |

| 老 tick 归并成粗桶以省空间 | 同上，写路径有损 ⇒ 破 F。而且引理一之后省的是 0 |
| 沿用 opus-b 的 F4-2（日内均匀重排）当反向测试 | 它同时摧毁自激与节律，分不开两者。换成保节律的非齐次 Poisson 自助（K5） |
| 把「hot/warm/cold」换成一个整数分数直接给用户 | D22 禁量表/百分位；三档 token 已经是合法呈现的上限（round1 G10） |

- **D1 的判定条**：跑 `ADV-uptime`。若成块掩码下 P4 的表观区分度真的低于 1.2 倍阈值，B1 垮掉，D1 只剩 B2–B5 支撑，应当重议。
- **D2**：给出一个把「哪个 app」与「何时」合成单一可数指标、且在 `SYN-M1P` 上不平凡的定义 ⇒ 分两张表的决定作废。
- **D4**：读 `excite` 的实现；若求和上界已经是 `tick(as_of) − 1`，本条只是把既有做法写进记录，不是修订。
- **D5 引理一**：构造一份夹具使 `W=72` 与 `W=288` 的 `excite` 不等 ⇒ 必然是某桶读时值 > 63，即读时截断没落实。引理本身是算术恒等式，可以在纸上驳倒我。
- **D7 F-1**：给出一个规范化管道，使得删除一条事件**永不**改变段边界 ⇒ 引理三成为多余，单桶减一恢复合法。（`MERGE_GAP_S = 0` 且 `MIN_SESSION_S = 0` 就是这样的管道——但那等于不去抖，opus-b §0.2 的理由仍然站着。）
- **D7 F-3 / G16**：查遗忘实现；若遗忘会**删除** `events` 行而不只是销毁密钥，则 `p4a` 不违反 F′，(a)/(b) 的选择可以重做。
- **§4.3 的空虚保护**：若某条杀线在所有可得夹具上都 `inconclusive`，那条杀线本身就是坏的，应当换判据而不是放宽 `n ≥ 200`。
