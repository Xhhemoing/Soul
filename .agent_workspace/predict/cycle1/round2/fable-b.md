# Cycle 1 Round 2 fable-b — P0/P1/P3/P5 解释句模板（调研草稿，非冻结话术）

定位：回答 R1-SYNTHESIS「Round 2 攻坚」里的「预测解释句如何保持可数且非临床」。**本文件是研究草稿，不是冻结 COPY_ZH**：冻结须走既有流程（先改 `docs/algorithms/COPY_ZH.md` 并留痕），本稿只给可供日后模板绑定测试的候选句式与验收断言草案。依据：`cycle1/R1-SYNTHESIS.md`、`docs/algorithms/COPY_ZH.md` 第 0 节全局规则、`predict/CONSTRAINTS.md`、Round 1 opus-b 规范（P0/P1/P3/P5 的字段与弃权集）、Round 1 fable-b 拒绝筛（S1/S2/S5、M1–M3）。

任务约束「只用次数/日期/app 文件名」落成三条硬规则：

1. 模板中的**数字**只许是整数次数、日期（渲染为「{某某某某} 年 {某} 月 {某} 日」）、整数天数差。无分钟、无比值、无任何评分性数字。
2. 模板中的**实体**只许是 app 文件名（P0/P1/P3）与「这个人 / 你们 / 对方」（P5）。无姓名、无窗口标题、无正文引语。
3. 其余一切修饰词过「基础禁词表（COPY_ZH 0.3）+ 预测面增补禁词表（本稿 §0.4）」。禁词**连否定句都不许出现**（词表是子串匹配，「不是说你冷落了谁」照样挂）。

## 0. 从 COPY_ZH 第 0 节继承什么、修正什么（预测面修正案）

**原样继承**：数字纪律（0.2）、日期格式、禁词基表（0.3：分数/评分/百分比/百分位/排名/指数/权重/系数/衰减/半衰期/算法名/诊断词全表）、第三人称呼（0.4）、band 词单源（强/中等/弱，本稿仅 P5 沾边且刻意绕开）、「怎么算的」透明句制度（0.7）。

**修正案（预测面 scoped，不回写 T 族模板）**：

- **X1 拉丁字母**：COPY_ZH 0.3 禁一切拉丁字母，但预测面的可数对象本身就是可执行文件名（`notepad.exe`）。修正为：**拉丁字母只许出现在 `{app 文件名}` 占位符槽内**，槽外一个都不许（含「%」）。测试法：渲染后把 app 槽内容剥掉，剩余文本断言无 `[A-Za-z%]`。
- **X2 时间词**：时间表述只许两类——**绝对日期**，或**事件序相对词**（「上一个」「下一次」「最近一次」，且「最近一次」必须紧跟绝对日期锚定）。禁一切钟面相对词（今天/现在/此刻/刚才/正在）与钟点语义词（上午/下午/晚上/深夜/凌晨/清晨/半夜/早上）——后者除了继承「不读墙钟」纪律，还因为数据面**没有本机时区**（R1-SYNTHESIS 数据面事实第 2 条），任何「用户的上午」都是编造；「深夜」还额外撞情绪暗示（R1 fable-b N1 的例句就是它）。
- **X3 收尾句（预测版，单源定义在此，各模板不改字）**：
  - next-app 类（P0/P1/P3）：「这只是照次数猜的，你可以屏蔽它。」（屏蔽是锁，后续不覆盖——R1 fable-b M1。）
  - 提醒类（P5）：「这是按日期数出来的提醒，不是对你们关系的评判；你可以关掉对这个人的提醒。」（关掉与纠正同形，永久尊重。）
- **X4 透明句（预测版，单源定义在此）**：
  - P0/P1/P3 首句：「怎么算的：只数你打开过哪些应用、各多少次、在哪些日子，不看窗口里的内容，也不读你的文件。」
  - P5 首句沿用 T4D 原句：「怎么算的：只统计次数和日期，不读聊天内容。」

### 0.4 预测面增补禁词表（草案，日后并入 assert_non_clinical 的预测面词表）

- **心理化动词/状态**：喜欢、偏爱、想念、需要、离不开、依赖、沉迷、上瘾、成瘾、习惯。
- **轴向形容**（对应 P6 亲和表：orderliness、social_energy、accommodation、emotional_steadiness）：规律、条理、自律、专注、拖延、焦躁、烦躁、亢奋、外向、内向、热情、疏远、冷落、怠慢、维系。
- **钟面与钟点词**：见 X2 全列。
- **必然化**：一定、肯定、必然、总是。预测句的合法动词是「猜 / 可能」（语域问题留 Round 3，见 §6.3）。

### 0.5 占位符约定

`{app 文件名}`/`{app 甲}`/`{app 乙}`=规范化可执行文件名；`{次数}`=该候选项的支持计数；`{总次数}`=全部规范化前台段数；`{行总次数}`=P1 某上下文行的总转移数；`{桶内总次数}`=P3 某钟点格的总段数；`{起始日期}`=记录里最早事件的日期；`{截止日期}`=as_of 的日期；`{最后一对一日期}`/`{最后群聊日期}`=T4D 已有列的日期；`{一对一沉寂天数}`=按 `last_direct_contact` 算的整数天数差；`{一对一次数}`/`{一对一天数}`=T4D 分列计数；`{典型间隔天数}`/`{最长间隔天数}`=一对一活跃日序列相邻间隔的中位/最大整数天数。

全部占位符都是**算法 token 随身携带的字段**：渲染层只填空，不得自己从事件表重算（继承 A2 P1b 的「推导即第二意见」禁令）。

## 1. P0（边际频率对照）模板草案

- **主句（top-1）**：「怎么算的：只数你打开过哪些应用、各多少次、在哪些日子，不看窗口里的内容，也不读你的文件。从 {起始日期} 到 {截止日期}，你一共打开应用 {总次数} 次，其中 {app 文件名} 有 {次数} 次，是次数最多的，所以把它放在最前。这只是照次数猜的，你可以屏蔽它。」
- **top-3 续句**（逐条，不用序数词，避免任何名次感）：「其次是 {app 文件名}，{次数} 次；再往后是 {app 文件名}，{次数} 次。」
- **并列**：「{app 甲} 和 {app 乙} 都是 {次数} 次，按文件名的字母顺序排列。」（钉 F0-3 的确定性并列。）
- **无记录弃权**：「还没有打开应用的记录，先不猜。」
- **未开采集弃权**：「前台记录是关着的，没有可数的次数，先不猜。」
- **屏蔽回执（设置页）**：「你已屏蔽 {app 文件名}，它不会再出现在任何猜测里。」

P0 的解释句是全家最平淡的一句，这是特性不是缺陷：它是对照组，句子里除了两个次数什么都不许有。P6 面上的风险点在渲染层给它加戏（「你最常开的是游戏」滑向「你爱玩」），增补禁词表的「喜欢/沉迷/习惯」一列就是给它焊的。

## 2. P1（一阶转移计数）模板草案

- **主句**：「怎么算的：只数「打开一个应用之后紧接着打开了什么」，不看窗口里的内容，也不读你的文件。上一个打开的应用是 {app 甲}。到 {截止日期} 为止，你在 {app 甲} 之后紧接着打开过别的应用 {行总次数} 次，其中 {次数} 次打开的是 {app 乙}，是次数最多的，所以这次先猜 {app 乙}。这只是照次数猜的，你可以屏蔽它。」
- **记录太少弃权**：「你在 {app 甲} 之后紧接着打开别的应用的记录只有 {行总次数} 次，太少，先不猜。」（不降级去猜——降级由 P7 统一做并换 P0/P3 的句子，见 §5 断言 TA-8。）
- **无上下文**：P1 静默，无句。开机后/长间断后的第一格由 P7 选 P3 或 P0 的句子。**一屏永远只出一句、只署一个来源**——这正是阶梯仲裁优于加权融合的话术理由（opus-b P7），也是本稿最重要的结构性断言之一。

**复核附注（进规范附注，不进用户界面）**：「紧接着」的可复核定义引 opus-b §0.2 的三条规范化常量（同名段 5 秒内合并、不足 3 秒丢弃、间隔半小时以上断链不计转移）。这些数值是规则常量，单点定义在规范里；用户界面句子里**不复制**这些数值，用户按附注口径可手数出 {行总次数} 与 {次数} 两个整数，全程无乘法。

## 3. P3（钟点格最频）模板草案——诚实标注是硬约束

数据面事实：只有 UTC 小时可从 `ts` 推，**没有本机时区**。所以 P3 的句子一个钟点语义词都不能出现（不许说「你早上常开它」），也暂不出「工作日/周末」字样——周几的边界同样依赖时区，UTC 周界对远离零时区的用户会把周五晚上算进周六。两个诚实变体并列，留 Round 3 挑：

- **变体 A（点名统一钟点，带免责）**：「怎么算的：只数你在同一钟点段里打开过哪些应用、各多少次。这里的钟点按统一的世界钟（协调世界时）计，可能和你墙上的钟差几个小时。在 {某} 点到 {某} 点这一段，你打开过应用 {桶内总次数} 次，其中 {次数} 次是 {app 文件名}，是次数最多的。这只是照次数猜的，你可以屏蔽它。」
  - 代价：句中出现钟点数字，它既不是次数也不是日期（与任务口径有张力，但用户可拿事件时间戳核对）；「协调世界时」四个字用户未必懂。
- **变体 B（同钟点段指代，不点名任何钟点）**：「怎么算的：只数你在与这一格相同的钟点段里打开过哪些应用、各多少次；钟点段按记录里的时间戳分格，不用你本地的钟。过去落在同一钟点段的打开记录有 {桶内总次数} 次，其中 {次数} 次是 {app 文件名}，是次数最多的。这只是照次数猜的，你可以屏蔽它。」
  - 代价：「这一格」是对 as_of 所在格的指代，抽象；好处是句中数字严格只剩两个次数，完全落在任务口径内。
- **记录太少弃权**（两变体共用）：「这个钟点段的记录只有 {桶内总次数} 次，太少，先不猜。」
- **轴亲和警戒**（orderliness）：P3 的句子只许陈述格内计数，禁「规律/条理/固定」。同一个 30 次里 18 次，说成「你很规律」即越界——增补禁词表已收。

## 4. P5（沉寂提醒，读 `last_direct_contact` 已有列）模板草案

称呼规则：模板体只有「你们 / 这个人 / 对方」。姓名只出现在卡片标题，由本机 `label_ref` 解引用；token 与模板都不含姓名（opus-b P5 的 token 纪律照抄）。**解释句引用的统计量必须与触发条件是同一个统计量**（否则就是 R1 fable-a §6.4 的「展示与依据脱节」），所以两个变体各自绑定一个触发形态，成对提交、成对取舍：

- **主卡 V1（典型间隔版；绑定触发「沉寂 ≥ 典型间隔的两倍」）**：「怎么算的：只统计次数和日期，不读聊天内容。你们上一次一对一往来是 {最后一对一日期}，到 {截止日期} 已经隔了 {一对一沉寂天数} 天；过去你们一对一往来一共 {一对一次数} 次，通常隔 {典型间隔天数} 天就有下一次。要不要写点什么？草稿会先给你看，不会自动发出。这是按日期数出来的提醒，不是对你们关系的评判；你可以关掉对这个人的提醒。」
  - 复核附注（不进界面）：{典型间隔天数} = 相邻一对一活跃日间隔从短到长排开取中间那个，偶数个取靠短的一个（确定性下中位，无除法无小数）。**可数性存疑**：用户复核要先排序再取中位，超出「数一数」的动作面；触发里的「两倍」还含一次乘法，T4D 的复核标准是全程无乘法。两处都记为未决点 §6.1。
- **主卡 V2（最长间隔版；绑定触发「沉寂 > 历史最长间隔」）**：「怎么算的：只统计次数和日期，不读聊天内容。你们上一次一对一往来是 {最后一对一日期}，到 {截止日期} 已经隔了 {一对一沉寂天数} 天；过去你们一对一往来一共 {一对一次数} 次，相邻两次之间最长的一回间隔是 {最长间隔天数} 天，这次已经比以往任何一次都久。要不要写点什么？草稿会先给你看，不会自动发出。这是按日期数出来的提醒，不是对你们关系的评判；你可以关掉对这个人的提醒。」
  - 好处：最大值一眼可核（找出最长的那段空档即可），无排序、无中位、无乘法，完全落在「次数/日期」口径内。代价：触发比 V1 保守（只在破纪录时响），提醒变少——这可能恰是打扰预算想要的方向，交 F5 系测试裁。
- **群聊在场附句**（X2 形状，direct 沉寂但群里同场；接在主卡句后）：「这段时间你们在群里同场说过话，最近一次是 {最后群聊日期}；一对一的上一次还是 {最后一对一日期}。」（钉住「提醒读 direct 时钟、判档读任一场地时钟」的裁决，F5-3 的话术面。）
- **静默态（一律无卡）**：只同过群（`direct_active_day_count = 0`）、档为弱、一对一活跃日不足 3 个、边被用户锁定、冷却期内——全部静默。设置页可见的解释各一句：
  - 用户已关：「你已选择不提醒这个人，这不会被改回来。」
  - 新关系：「你们一对一往来过的日子还不到 3 个，先不提醒。」
  - 边锁：「你已锁定这段关系的档位，这里不提醒。」（刻意不出现档位词，绕开 band 单源纠纷；若 Round 3 认为该句应报档位，则必须从 T4D band 取词。）
- **多人排序的话术后果**：opus-b P5 的频控排序用交叉相乘（`a₁·g₂ > a₂·g₁`），**这个序无法用一句可数的话解释给用户**（含乘法），且逼近 R1 fable-b M3 明令禁止的「合成加权分排序」。本稿的模板假设排序退回单一可审计观测（沉寂天数降序），这样「为什么先提醒这个人」有现成答案：它的 {一对一沉寂天数} 最大。与 opus-b 的冲突记为未决点 §6.4。

## 5. 日后测试怎么钉（模板绑定断言草案，实现期随 predict 侧测试落地）

- **TA-1 词表**：每个模板渲染结果过 assert_non_clinical + §0.4 增补表；剥掉 `{app 文件名}` 槽后断言无拉丁字母与「%」（修正案 X1 的测试面）。
- **TA-2 数字重算**：每个数字占位符都能由输入观测按 §0.5 的定义重数出来；数字只有整数次数、日期、整数天数差三种形态。
- **TA-3 渲染单源**：解释句只填 token 随身字段；渲染层源码不存在从事件表重算计数的路径（镜像 COPY_ZH 断言 7）。
- **TA-4 弃权即沉默或明说**：弃权 token 渲染为空或「先不猜」句；「先不猜」句里不得出现任何 app 文件名（不许一边弃权一边偷渡猜测）。
- **TA-5 时间词**：全部渲染无 X2 禁词（今天/现在/正在/上午/深夜等）；「最近一次」出现处后必须紧跟日期占位符。
- **TA-6 P5 面**：模板体无姓名占位符、无轴向词；如日后引入档位词，只许「强/中等/弱」且取自 T4D band。
- **TA-7 并列确定性**：并列句在计数相同的夹具上跑 1000 次逐字相同（接 F0-3）。
- **TA-8 一屏一句一源**：P7 仲裁后同屏只出一个来源的解释句；P1 弃权时屏上出现的必须是 P3 或 P0 的句式，不得出现拼接句（「综合来看…」类措辞直接进禁词审查）。
- **TA-9 解释与触发同源**（P5）：V1 句只在中位触发形态下渲染、V2 句只在最长间隔触发形态下渲染；换触发不换句、换句不换触发都算失败。

## 6. 留给 Round 3 的话术未决点

1. **中位数可数性**（P5 V1）：排序取中位算不算「用户可自行数出来」？触发里的「两倍」含乘法，违背 T4D 全程无乘法的复核标准吗？若两问皆否，V2（最长间隔）整体接管。
2. **P3 变体 A vs B**：点名协调世界时（可懂性差、多出钟点数字）还是同钟点段指代（抽象但口径最干净）？以及「工作日/周末」字样在拿到本机时区之前是否永久禁用（schema 缺口——本机时区列——只记录不实现，与 R1-SYNTHESIS 口径一致）。
3. **语域**：「猜」字的谦抑是否过头（显得系统不可靠）？备选「可能接下来是」。倾向保留「猜」：它最诚实地传达了这不是承诺、可屏蔽。
4. **P5 多人排序**：交叉相乘序（opus-b）vs 沉寂天数降序（本稿假设）。前者无可数解释句，后者会系统性偏向久疏的边。需要 F5 系夹具加一条「排序解释句存在性」检验。
5. **P0/P1/P3 解释句 v0.2 是否上屏**：模板先备好；只进调试面板还是进用户界面，由后续轮次连同打扰预算一起裁。
6. **app 文件名直显**：`notepad.exe` 直显最诚实，但可读性差；若加用户自定义别名层（用户输入，不是采集面扩张），别名进不进 assert_non_clinical 的检查范围要先裁。
