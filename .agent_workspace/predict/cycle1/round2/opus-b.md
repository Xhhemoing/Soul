# Cycle 1 / Round 2 / opus-b — APPM-lite 与 P2：合并成一个候选，还是两个？

任务：R1-SYNTHESIS「Cycle 1 Round 2 攻坚」第 2 条。输入是 `round1/gpt-sol-b.md` 的 APPM 段（Parate et al. 2013）
与 `round1/opus-b.md` 的 §2.3 P2（二阶 n-gram + 确定性回退）。
**权重一律整数。不实现 Goal 2，不改 T4D/A0，不写产品 crate，不 git。** 本文件只给规范与裁决。

---

## 0. 结论

**都不是。「APPM-lite」不该作为一个候选存在——不是一个，也不是两个。**

问「合并成一个还是两个」预设了 APPM-lite 和 P2 是同一层级的两个模型。它们不是。
APPM 是**一张前缀计数表 + 一条融合规则 + 一个时延分量 + 一个预取动作**四件东西捆在一个论文名字下面。
Soul 这边这四件东西**已经各有归属的槽位**：表是 P2 的，融合是 P7 的，时延是 P4/TTU 那条轴的，预取是产品锁明令禁止的。
把它整体收成一个候选，等于在 P2 旁边再放一张同源的表、在 P7 之外再开一层融合——状态双份、归因双份、
而两层融合叠在一起时任何命中率变化都无法定位到哪一层。

拆开归位：

| APPM 的部件 | 裁决 | 落到哪 | 形态 |
|---|---|---|---|
| 可变阶前缀计数（PPM 主体） | **并入 P2** | `p2.vopm_backoff.v2`，`MAX_ORDER` 升到 3 | 同一张表；depth-2 是它的特例配置 |
| 按历史准确率给「阶」加权 | **移入 P7** | 新具名变体 `p7c.hit_ranked_ladder.v1` | 成对整数胜场排序，无除法无浮点 |
| 加权插值混合多阶预测 | **具名否决** | — | 破可数性；附复活条件，见 §5 |
| TTU（下次使用的时延经验 CDF） | **不并入，单独登记** | 与 P4「何时」同槽评审，本轮不裁 | 目标不同：它答「何时」不答「开哪个」 |
| 预取 / 预加载 | **出局** | — | 预测不得启动或预载任何进程；这是产品面不是算法面 |

对 R1-SYNTHESIS 的具体动作：**删掉「经确认可测」表里的 `APPM-lite` 那一行**，替换为
`p2@2` / `p2@3` 两个配置行 + P7 下的 `p7c` 一个备选行。理由与规范见下。

一句话的判据：**一个候选的边界应当画在「独立杀线」上，不是画在「论文名字」上。**
可变阶的声明是「更长的上下文有用吗」，加权的声明是「按历史准确率选层比按长度选层好吗」。
这是两条互不蕴含的声明，必须能被各自独立证伪；而它们都不需要各自一整套状态。

## 1. 为什么「合并成一个候选」在计数层面是对的

三条，都是可检查的事实而不是偏好：

**1.1 depth-2 的表是 depth-q 的表的前缀截断。** `trans[a][b]` 与 `trans2[(a,b)][c]` 在 R1 §2.3 里就已经共享
（「同时**共享** P1 的 `trans` 表（不重复存）」）。再加一层 `trans3[(a,b,c)][d]` 是同一个数据结构长深一层，
不是第二个模型。若立成两个候选，两份实现会各自决定 tie-break、各自决定 `boundary` 处怎么断、
各自决定重击者怎么裁——**然后 A/B 结果里会混进实现漂移，而不是深度的效果**。

**1.2 一次事件更新所有深度，摊销成本不变。** `update(event)` 对 depth 1..MAX_ORDER 各做一次整数加，
`MAX_ORDER` 是编译期常量，所以仍是摊销 O(1)，仍符合 R1 §0.4「只有在线计数」。两个候选就是两遍遍历同一条流。

**1.3 归因反而更干净，前提是配置必须分行上报。** 合并后「深度有没有用」是**同一实现上单个常量的消融**，
这是 gpt-sol-b 决策规则第 1 条（「必须在为其声明优势设计的夹具族上打赢更简单的前身」）能被干净执行的唯一形式。

**合并的风险，如实记：** 有人跑 `MAX_ORDER=3` 却在报告里只写「P2 赢了」，把多出来的 4 倍状态藏掉。
硬性缓解写进规范：评测输出**必须**逐配置分行，且每行同时登记 `order_used` 分布、条目总数、驱逐次数三列；
少任何一列该行作废。`p2@2` 与 `p2@3` **独立晋级**，不许打包。

## 2. 合并后的规范：`p2.vopm_backoff.v2`

替换 R1 §2.3 的 `p2.ngram2_backoff.v1`。**改的只有深度与预算，回退阶梯的形状一个字不动。**

- **一句话**：数「你前 k 个 app 之后开了几次 X」，k 从 `MAX_ORDER` 往下退，退到有足够计数的那层为止，并把用的是哪层告诉你。
- **输入**：规范化会话流（R1 §0.2 的 `MERGE_GAP_S/MIN_SESSION_S/SESSION_GAP_S` 原样沿用）。
  跨 `boundary` 的 n 元组**一律不计**；因此 boundary 后第 1 段只有 order-0 可用、第 2 段最多 order-1、第 3 段才可能 order-3。
  这不是缺陷，是与 P3 的分工线：**boundary 那一格本来就是 P3 的（R1 §0.2 末句），P2 在那里就该弃权。**
- **`MAX_ORDER = 3`**，不是 5。三条理由：(a) R1 §2.3 已把状态爆炸列为 P2 最大风险，每加一阶前缀数近似再乘一次；
  (b) gpt-sol-b 引的 Parate 结果里，增益在浅阶就趋平（该文连加位置与时段特征都只对 top-5 有边际影响）；
  (c) 评测成本随配置数线性涨，本轮先钉 2 与 3 两档。`p2@4`/`p2@5` 作**具名备选**保留，
  只有 `p2@3` 打赢 `p2@2` 且驱逐率低于 §2.2 的界时才允许开启评测——**不点名到不了，与 R1 对 `p3b`/`p7b` 的处理同形**。

### 2.1 回退阶梯（确定性，无浮点，与 R1 同形只是多一级）

| 层 | 用它的条件 | 常量 | 出处 |
|---|---|---|---|
| order-3 | `trans3[(a,b,c)]` 行总 ≥ `MIN_ROW_SUPPORT_3` | **12（约定，待 F2-6b 扫）** | 本轮新增，来源是猜 |
| order-2 | 行总 ≥ `MIN_ROW_SUPPORT_2` | 8 | R1 §2.3，来源是猜 |
| order-1 | 行总 ≥ `MIN_ROW_SUPPORT_1` | 5 | R1 §2.2，来源是猜 |
| order-0 | 兜底 | — | P0 |

阈值随阶单调递增是有意的：长上下文只有在证据**更多**时才该被选中，否则「长度优先」的阶梯天然过拟合稀疏行。
`MIN_ROW_SUPPORT_3` 的候选集登记为 `{8, 10, 12}`，由 F2-6b 在同一批夹具上扫一次后写死；
**扫完写死，禁止事后把常数改成赢的那个再宣称设计如此**（与 R1 §2.5 对 P4 半衰期的纪律同一条）。

仍然**不做** Katz 折扣、不做插值——折扣量与插值系数都是浮点，会同时毁掉可数性与整数纪律。
诚实代价：理论上比插值差，差多少由 F2-1 实测登记，不许粉饰。

### 2.2 状态预算（深阶用更窄的行，不是更宽的表）

| 深度 | 行数上限 | 行内 `TOPK_ROW` | 条目上限 |
|---|---:|---:|---:|
| 1 | 256（= `TOPK_APPS`） | 32 | 8 192 |
| 2 | 1 024 | 16 | 16 384 |
| 3 | 1 024 | 8 | 8 192 |
| 合计 | | | **32 768 ≈ 4× depth-1** |

深阶行更窄有理由，不是凑数：三元前缀本身已经稀疏，那一行的长尾几乎必然是噪声，留着只会挤掉别的前缀。
这个预算把 R1 F2-1 的杀线（「状态条目数不超过 P1 的 8 倍」）留出一倍余量。
行级驱逐用 Misra-Gries（按行总计数最小者驱逐），**逐深度独立**，防止 depth-3 把 depth-2 饿死。
`evicted_prefixes[depth]` 是必报指标。

### 2.3 输出与可数性（不变）

`next_app` × top-3 + 每个的 `count` + 该层行总 + `order_used ∈ {0,1,2,3}`。
并列一律 `app_id` 字典序升序打破。行总不足且已退到 order-0 仍无数据 → `abstain.no_data`；未同意 → `abstain.consent_off`。

解释句：「你在 {a} 然后 {b} 然后 {c} 之后，14 次里有 9 次开了 {d}。」四个 token 两个整数，全部可手数，无乘法无小数。
**升到三阶不改可数性形状**——这正是「并入 P2」安全的实质理由：多一阶只是句子里多一个 app 名字。

### 2.4 锁冲突（不变）

无轴亲和。禁词面同 P1/P2：转移模式不得被渲染成「注意力涣散 / 拖延 / 自律」。仍须过 P6。

### 2.5 不变式 F（**这里有一处对 R1 的更正，见 §6.2**）

桶键 `(a,b,c) → d` 仍是事件字段的纯函数 → 删事件时逐深度各减一格，**在未发生驱逐的前提下**逐桶等于重放。

### 2.6 证伪测试（改写 R1 的 F2-*）

- **F2-1（主杀线，逐配置）**：`p2@k` 的预顺序 top-1 必须比 P1 高 **≥ 3 点**，**且**条目总数 ≤ P1 的 8 倍。
  两条任一不满足，该配置出局；`p2@2` 出局不蕴含 `p2@3` 出局，反之亦然。
- **F2-2（过拟合探针）**：留出末 20% 时段，`p2@3` 不得比 `p2@2` 差、`p2@2` 不得比 P1 差。差了说明对应阈值太低。
- **F2-3（一阶源上不许自造噪声）**：`SYN-markov1` 上 `p2@2 ≈ p2@3 ≈ P1`（差 ≤ 1 点）。
- **F2-4（冷启动）**：`ADV-new_app` 下 `order_used` 必须在 8 次转移内从 0 爬到 2、在 24 次内爬到 3；爬不上去说明深阶不可用。
- **F2-5（回归钉）**：`p2@2` 在 R1 全部夹具上的输出必须与 `p2.ngram2_backoff.v1` **逐字节相同**。
  这条是合并操作的正确性证明：**合并不得改变现状配置的任何一个 token**，否则合并本身就是一次未登记的算法变更。
- **F2-6a（深度的定义性杀线）**：新增 `SYN-order3` 夹具——两条历史的**后两个** app 相同、第三个不同，且真实后继不同
  （即 `X,C,D→E` 与 `Y,C,D→F`）。`p2@3` 必须在此夹具上比 `p2@2` 高 **≥ 2 点**，同时在其余全部夹具上不低于 `p2@2` 超过 1 点。
  只在自己的夹具上赢不算数，只在别处不输也不算数，两条同时成立才留 depth-3。
- **F2-6b（阈值扫）**：`MIN_ROW_SUPPORT_3 ∈ {8,10,12}` 各跑一遍，登记全部三行结果再写死。
- **F2-7（预算）**：`app 数 > 60` 一档上逐深度报驱逐次数；depth-3 驱逐率 > 20% 时 depth-3 的命中率结论作废
  （驱逐掉的是不同的表，比的就不是同一个模型）。
- **F2-8（泄漏探针，沿用 F1-2 形状）**：`SYN-shuffle` 上 `p2@2/p2@3` 必须退化到 P0 ± 2 点。显著更高 → 先修 harness。
- **F2-9（不变式 F）**：逐深度逐桶，且断言 `evicted_prefixes == 0`（见 §6.2）。

**已知缺陷（新增一条）**：`MAX_ORDER=3` 让 boundary 后的「无上下文窗口」从 2 段变成 3 段，
P2 在这段时间的弃权率必然上升。这把更多格子推给 P3/P0，因此 **F3-1（P3 在无上下文格上比 P0 高 ≥ 8 点）
的重要性随 `MAX_ORDER` 上升而上升**——两者不是独立的，评测报告要把这条耦合写出来。

## 3. 阶加权移入 P7：`p7c.hit_ranked_ladder.v1`

APPM 真正区别于「固定阶梯 n-gram」的地方只有一处：**它不按上下文长度选层，它按各层的历史准确率选层。**
这是一条独立的、值得测的声明。但它是**融合规则**，而 Soul 已经有一个指定的融合层（P7）。
在 P2 内部再放一层加权 = 两层融合叠在一起 = 任何结果都无法归因。所以它进 P7。

### 3.1 P7 的源集合改写

`p7c` 的源集合是 `{p0, p2@1, p2@2, p2@3, p3}`（`p2@1` 就是 P1）。
于是 **R1 的 P7 固定阶梯与 P2 的内部阶梯是同一个操作在两个粒度上的两次书写**。硬规定：
**只许有一份实现**——P2 的内部阶梯即 P7 阶梯在 `p2@*` 上的限制，P2 的 `order_used` 即 P7 的 `source` 在 `p2@*` 上的投影。
（测试见 F7-9。常量单源、话术单源，这里是「决策规则单源」，同一条纪律。）

### 3.2 整数权重：成对胜场，不是准确率

朴素做法是给每阶记一个命中数 `hits[o]`，按 `hits` 降序选层。**这个做法有偏，不能用。**
原因：`hits` 是绝对计数，而低阶几乎每个决策点都有支持、高阶经常无支持，
所以低阶的 `hits` 天然更大 → 永远排前面 → 高阶永不被选中 → 高阶永远攒不到 `hits`。**自我实现的死锁。**
修正它的自然做法是除以「有支持的次数」变成准确率——那是浮点，出局。

整数解法：**只在两层都有支持的决策点上做成对比较。**

- **决策点**：预顺序评测中每次做出一次 `next_app` 预测的时刻。
- **环形记录**：`SCORE_WINDOW = 256` 个决策点，每点每阶存 2 bit（`无支持 / 对 / 错`），4 阶共 1 字节/点，**合计 256 字节**。
- **成对计数**：`wins[o][o']` = 窗口内「两层都有支持、且 o 对 o' 错」的决策点数。4 阶 → 6 对 → 6 个 `u16`。
  进窗时对 6 对增量更新，出窗时反向回退——环形缓冲是精确的，所以增量完全可逆，**没有 P4 那种右移不可逆的问题**。
- **排序**：`o` 优先于 `o'` 当且仅当 `wins[o][o'] > wins[o'][o]`。**只比大小，不算比值**（R1 §0.3）。
  由成对支配取拓扑序得到试探顺序；按此顺序找第一个行总 ≥ 其 `MIN_ROW_SUPPORT_o` 的层，用它，出结果。
- **冷启动**：有效决策点 < `SCORE_WINDOW_MIN = 64` → 用固定阶梯（长上下文优先），输出 `order_rule(fixed)`。
- **成对支配出现环**（Condorcet 环，4 个元素上完全可能）或全平 → **回退固定阶梯**，输出 `order_rule(cycle_fallback)`。
  环不是要处理的意外，是要**上报**的事实：`cycle_fallback` 的出现率是必报指标；如果它常态化，说明各阶准确率无差别，`p7c` 就没意义。
- **可数性**：「最近两层都有数据的 88 次里，三阶对 51 次、二阶对 37 次，所以这次先看三阶；三阶那一格 14 次里有 9 次是 {d}。」
  两句话四个整数，全部可手数，全程无乘法无除法无小数。
  **这是把 APPM 的「按准确率加权」翻译成整数后还能保住可数性的唯一形状**——因为最终解释仍然只来自被选中的那一层。

### 3.3 遗忘：权重窗口不满足不变式 F，只能归零（**新问题，必须写清**）

前缀计数是事件字段的纯函数；**准确率窗口不是**。它是「事件序列 × 模型自身历史输出轨迹」的函数。
删掉一条事件会改变此后每一次预测时的表状态，从而**追溯性地改变此后每一个决策点的对错**。
`replay(events \ {e}) == decrement(...)` 在这里根本不成立——没有哪一格可以减，
因为产生那次命中的模型状态已经不存在了。这与 P4 指数累加器是同一类病，但更深一层（P4 是不可逆算术，这是自指）。

裁决：**任一事件被遗忘 → 整个权重窗口清零，`p7c` 退回固定阶梯，等 256 个决策点重新攒。**

- 记为**不变式 F′**：`forget(e)` 之后，权重状态中不含 `e` 的任何贡献。清零平凡满足（比 F 更强，代价是也丢了别的）。
- 代价如实记：遗忘频繁的用户身上 `p7c` 可能长期处于 `order_rule(fixed)`，等于这个机制不存在。
  **这本身就是一条杀线**：F7-7 要测在真实遗忘率下窗口的可用比例。
- 不接受的替代方案：为权重窗口做 checkpoint + 局部重放。checkpoint 本身也含被删事件，
  要做正确就得从头重放整条流，那就不是 O(1) 更新了，直接违反 R1 §0.4.1。

### 3.4 证伪测试（P7 增补）

- **F7-5（主杀线，与 `p7b` Borda 同一根杆）**：`p7c` 必须比固定阶梯高 **≥ 2 点**，否则永久留在具名备选位。
- **F7-6（自指探针）**：`SYN-random`（纯随机源，各阶都无信息）上，`p7c` 的选层分布必须**接近均匀 / 频繁 `cycle_fallback`**，
  且 top-1 必须 ≈ P0。若它在纯噪声上稳定锁定某一阶，说明它在放大自己的历史，出局。
- **F7-7（遗忘可用性）**：在「每 100 事件遗忘 1 条」的夹具上，`order_rule(fixed)` 的占比 > 80% → 机制形同虚设 → 出局。
- **F7-8（扰动稳定性）**：删除/改动单条事件后，其后 1000 个决策点里 top-1 发生变化的比例，
  `p7c` 不得超过固定阶梯的 **3 倍**。超了说明自指反馈把单点扰动放大成轨迹分叉，
  这直接踩 gpt-sol-b 决策规则第 5 条（小扰动下不稳定即拒绝）。
- **F7-9（决策规则单源）**：P2 独立跑出的 top-1 与 P7 限制在 `p2@*` 源上跑出的 top-1，在全部夹具上逐字节相同。
- **F7-10（确定性）**：同输入 1000 次同输出，含全部并列格与全部 `cycle_fallback` 格。

## 4. 整数化替换表（本轮的「权重一律整数」怎么落）

| 原机制（浮点） | 出现在 | 裁决 | 整数替代 |
|---|---|---|---|
| 按准确率加权各阶 | APPM 核心 | 改造后收编 | `wins[o][o']` 成对整数胜场 + 阶梯排序（§3.2） |
| 多阶加权插值 / 混合分布 | APPM、经典插值 n-gram | **具名否决** | 无（见 §5 的二分论证） |
| Katz 折扣 / Kneser-Ney | 经典 n-gram 平滑 | 已否（R1） | stupid backoff 阶梯 + 逐阶支持阈值 |
| PPM escape 概率 | PPM 家族 | 否 | 「行总 ≥ 阈值」的整数判定即 escape 的整数化 |
| 计数的指数近因衰减 | 通用「让旧数据变轻」 | 否，且**不许开第二个** | R1 §5 已裁：全系统只有 P4 一处衰减，且已换成环形桶 |
| 概率 / 归一化置信度输出 | 全部文献模型 | 否（R1 §0.3） | 整数计数 + 行总，排序用计数降序 + 字典序打破并列 |

一条通则，本轮显式写出来（R1 只是隐含）：
**用于排序的算术 ≠ 出现在解释里的算术。** P5 已经用交叉相乘 `a₁·g₂ > a₂·g₁` 排过序，
而给用户看的仍是「N 天没联系、平时 g 天一次」两个原始整数。
`p7c` 遵守同一条：内部只做整数比大小，**用户复核的那个数字必须是原始事件计数**。
反过来，任何机制若使得「最终答案无法用某一格的原始计数解释」，它就越过了这条线——插值正是这样越过的。

## 5. 为什么加权插值被否（可测的二分论证）

设 `L` = 阶梯选出的 top-1，`B` = 加权插值混合后的 top-1。二者只有两种关系：

1. **`B == L`**：插值没改变答案，那它就是一层纯开销（浮点权重 + 训练 + 不可数），删掉它没有任何损失。
2. **`B != L`**：插值改变了答案。此时 `B` 不是任何单层里计数最高的那个候选——
   **不存在一句「X 次里有 Y 次」能解释它为什么被选中**。用户要复核就得复现一次加权求和。
   这直接违反 R1 §0.3，且违反的方式不是「难看」而是「不可纠正」：用户看不出该改哪个数。

所以插值要么无用，要么不可数。**但这不是拍脑袋，它是可测的**：登记两个指标
`disagree_rate`（`B != L` 的比例）与 `win_rate_on_disagreements`（分歧格上 `B` 的命中率减 `L` 的命中率）。

**复活条件（三条全要，缺一不谈）**：(a) `disagree_rate ≥ 5%`（否则按第 1 种情况删）；
(b) 分歧格上净赢 ≥ 5 点且在两档 app 数分层上都成立；(c) **给出分歧格的可数解释句**——
即一句只含原始整数、不含乘法与小数、用户能手数验证的话。第三条目前没有人给得出，所以它现在是否决。
（与 R1 §5 的「深网 / 联邦」条目同一结构：**否决必须带可执行的复活条件，否则那是偏见不是裁决。**）

## 6. 对 R1 的两处更正

### 6.1 命名：不许叫 APPM

按 gpt-sol-b 自己对 ATPP 的处理纪律（去掉位置分支后就只能叫「temporal-only 消融」，不能叫复现 ATPP），
这里同理：本方案丢掉了 APPM 的加权混合、TTU、预取三件，**只保留了可变阶前缀计数**。
所以叫 `vopm`（variable-order prefix model）/「APPM 启发的前缀计数」，
文档、指标表、算法 id 里**不得出现 `appm` 字样**，避免日后被读成「我们实现并验证了 APPM」。
`p7c` 同理：它是「按成对胜场排序的阶梯」，不是 APPM 的加权。

### 6.2 不变式 F 在重击者驱逐下不成立（R1 §0.5 的原文过强，本轮更正）

R1 §0.5 写「这条对 P0–P3、P5、P8 天然成立」。写这一轮时发现这句**在发生驱逐后是错的**：
Misra-Gries / Space-Saving 的保留集依赖到达顺序，`replay(events \ {e})` 可能保留下与 `decrement(replay(events), e)`
**不同的一组行**，逐桶相等因此不成立。这不是深阶带来的新问题，`TOPK_APPS`/`TOPK_ROW` 一存在它就存在，
R1 漏了。既然本轮把表加深、把驱逐压力显著提高，必须在这里补上而不是留着：

- **不变式 F（强）**：只在 `evictions == 0` 时断言。F 类测试的夹具必须**按容量上限设计**并显式断言 `evicted_prefixes == 0`；
  不加这条前置断言的 F 测试是假绿灯。
- **不变式 F₂（弱，驱逐后仍必须成立）**：被遗忘事件的增量已从**所有存活桶**中减去，且被驱逐的行不含它的任何残留
  （驱逐是整行丢弃，天然不含）。F₂ 保证的是「无残影」，不保证「与重放逐桶相等」。
- **精确性的恢复路径**：R1 §0.4.4 已经允许「计数表是可重建的派生物」。所以规定：
  `evicted_prefixes > 0` 之后，只有一次**从事件表全量重建**能把状态拉回与重放严格相等。
  重建时机不在本轮裁（列入 §7）。
- 这条更正**同样适用于 P1**（`TOPK_ROW=32` 的 `other` 桶），不是 P2 独有。R1 的 F1-4 需要同样加前置断言。

## 7. 留给下一轮

1. **`MIN_ROW_SUPPORT_3` 的三档扫结果**（F2-6b），扫完写死，禁止倒填。
2. **全量重建的触发时机**：按驱逐次数？按时间？按用户显式操作？本轮只确立「重建是恢复精确性的唯一路径」，不裁时机。
3. **`p7c` 与 `p7b`（Borda）的关系**：两者都是 P7 的备选，且都要打赢固定阶梯 ≥ 2 点。
   若两者都过线，谁先谁后没裁；但**不许同时启用**（两层排序叠加又是不可归因）。
4. **TTU 归属**：APPM 的时延分量与 P4 的 burst token、gpt-sol-b 的「经验时延 CDF」在答同一个问题（何时）。
   三者是不是同一个候选的三种写法，本轮不裁——但它**不属于 P2 这条轴**，不许借「合并 APPM-lite」偷偷带进来。
5. **`MAX_ORDER` 与 P3 的耦合**（§2.6 末）：深阶抬高 P2 的 boundary 弃权率，P3 的独立价值随之升权重。
   这意味着「P2 升三阶」与「P3 是否保留」不能分开裁，下一轮要一起看。
