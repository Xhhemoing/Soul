# C1R2：next-app 内部评测契约

## 结论

只保留三项内部指标：top-1、top-3、弃权率。正常评测必须按事件时间做
prequential（先预测、再揭晓、最后更新）；随机打乱只用于负对照，不能代替正常评测。
在保持边际应用频数而破坏相邻关系后，一阶 Markov（P1）应退化到边际频率基线
（P0）附近。所有命中率、差值、置信区间和算法名只存在于本机离线评测产物，不进入
产品 schema、审计正文或 UI。

## 1. 被测对象

### P0：前缀边际频率

- 输入：预测时刻之前已经完成的可执行文件名。
- 输出：至多三个历史中见过的候选；没有历史时弃权。
- 可数性：每个候选只有前缀内的整数出现次数。
- 锁冲突：不需要标题、正文、键鼠、第三人数据或出网。
- 证伪：若频数偏斜夹具上不能选出前缀内最高频项，说明计数、并列或回放实现错误。

### P1：一阶 Markov

- 输入：预测时刻之前已经完成的相邻 `前项 → 后项` 整数计数，以及当前前项。
- 输出：至多三个后继；当前行无支持时使用预先声明的 P0 backoff，P0 也无数据才弃权。
- 可数性：每个候选可还原为某一行的后继次数和该行总次数。
- 锁冲突：同 P0；不得把转移称为心理原因或因果关系。
- 证伪：有一阶结构的夹具上不能超过 P0，或打乱后仍有稳定优势，均阻止把 P1
  作为默认。后者也可能是评测 harness 泄漏，必须先排查，不能直接归罪于模型。

P0 与 P1 必须使用同一候选集、并列规则和 backoff 规则。否则
`shuffle → P1≈P0` 同时混入支持门差异，无法单独检验转移信息。

## 2. Prequential 协议

评测输入先按同意状态、锁屏/来源错误等未知区间切成连续段。不得跨未知区间构造转移。
资格集合在运行任何模型前一次性冻结，所有模型使用完全相同的预测机会：

1. 每段首事件只加入前缀状态，并成为当前前项，不计一个虚构的跨段预测机会。
2. 在揭晓本段下一事件前，用仅含当前时刻及更早事件的状态产生候选列表或弃权。
3. 冻结该输出，再揭晓真实下一可执行文件名并记一次结果。
4. 评分完成后，恰好更新一次边际计数和相邻计数。
5. 重复到段尾；重放从空状态开始，绝不从全量日志预建计数。

等价伪代码：

```text
state := empty
for segment in chronological_segments:
    observe_first_event_without_scoring(state)
    for actual_next in remaining_events(segment):
        prediction := freeze(predict(state))
        record(prediction, actual_next)
        update_once(state, actual_next)
```

约束：

- 真实下一项在此前从未出现，仍是合法评测机会；不得从分母删除。
- warm-up、低支持和未知候选造成的弃权仍进入分母。
- 候选必须来自当时的前缀，不能先从完整日志建立未来词表。
- 调参常量、最小支持和并列规则须在查看该日志结果前冻结。
- 同一输入重放必须逐步产生相同结果。
- 正常结果只来自原始时间顺序；随机切分或随机顺序的“准确率”无效。

当前阶段以 `FakeForegroundSource` 合成序列走真实采集/会话边界来验证协议。没有明确的
本机同意路径时，不得把生产日志解封给研究预览，也不得声称已经测得真实用户效果。

## 3. 唯一三项指标

设共同资格集合大小为 \(N\)，第 \(i\) 次输出是一个去重、有确定顺序、长度为
0–3 的列表 \(L_i\)，真实项为 \(y_i\)。空列表表示弃权；一次输出不得同时包含候选和
弃权 token。

\[
\text{top1}=\frac{\sum_i [L_i\neq\varnothing \land L_i[0]=y_i]}{N}
\]

\[
\text{top3}=\frac{\sum_i [y_i\in L_i]}{N}
\]

\[
\text{abstain}=\frac{\sum_i [L_i=\varnothing]}{N}
\]

弃权在 top-1 和 top-3 中都按未命中处理，而不是从分母移除。因此提高弃权率不能虚增
命中率。每份内部报告必须先给整数分子/分母，再给派生小数，并满足：

```text
0 <= top1_hits <= top3_hits <= N - abstentions
```

报告同时保留逐日志整数和合并整数；P0/P1 比较必须逐同一机会配对。不得只展示最好的
日志、随机种子或后半段。此轮不加入 MRR、人格分、综合分或跨用户排名。

建议的离线记录形状仅用于测试目录或 CI artifact：

```text
protocol_version
trace_fixture_id
model_id
eligible_count
top1_hits
top3_hits
abstention_count
top1_rate
top3_rate
abstention_rate
shuffle_seed_or_none
```

它不是产品事件，也不是 `SoulInference` 证据。

## 4. 泄漏负对照：shuffle → P1≈P0

shuffle 是单独的 leak probe：

1. 先完成且封存原顺序的 prequential 结果。
2. 对每个连续段独立打乱可执行文件身份；保留段边界、事件数、时间戳和时长，从而保留
   每段边际频数但破坏有方向的相邻结构。
3. 每个固定种子都把 P0、P1 状态清空，再从头执行完全相同的 test-then-train 路径。
4. 记录同一机会上的
   `Δ1 = top1(P1)-top1(P0)`、`Δ3 = top3(P1)-top3(P0)` 和弃权率差。
5. 种子列表和等价容差 \(\epsilon\) 必须预注册；不得看完结果后挑种子或放宽容差。

可执行的默认门是至少 32 个固定种子，并取
\(\epsilon=\max(0.01,1/N)\)。P1/P0 共享 backoff 时，三个配对差的 95% 种子区间都应
落在 \([-\epsilon,+\epsilon]\) 内。很短、使 \(1/N\) 过大的夹具只能作诊断，不能作
放行证据。

该门的含义不是“随机顺序也能证明模型有效”，而是：边际频数相同且顺序信号被消除后，
P1 不应仍有可重复优势。失败时依次检查：

- 是否在第一次预测前用完整日志预建了转移表或候选词表；
- 是否在 score 前更新，或同一事件更新了两次；
- 是否按真实结果过滤了机会或候选；
- 各 shuffle 之间是否复用了状态；
- P0/P1 的支持门、backoff 或并列规则是否不一致；
- 打乱是否误跨段，或实际上保留了相邻块。

shuffle 通过也不能单独证明没有泄漏：如果 P0 和 P1 都偷看同一份未来边际频数，两者仍
可能相等。因此另设零容差的前缀因果不变式：任意两条日志只要截至预测点的前缀完全
相同，无论其后缀如何替换，该点的候选、弃权和支持计数必须逐字节相同。此项是协议断言，
不是第四个产品指标。

## 5. 不带 D22 分数的产品呈现

| 内部信息 | 工程用途 | 产品 UI |
|---|---|---|
| top-1 分子/分母与比率 | 候选验收 | 不显示 |
| top-3 分子/分母与比率 | 候选验收 | 不显示，也不据此显示“前三推荐” |
| 弃权分子/分母与比率 | 检查覆盖和门槛 | 不显示比率；弃权时不主动给建议 |
| P1−P0 差值、shuffle 区间 | 泄漏负对照 | 不显示 |
| model/protocol id | 可复现性 | 不显示算法名或质量徽章 |

禁止的 UI 形式包括“准确率 78%”“置信度 82”“表现强/中/弱”“超过多数用户”、星级、
综合指数以及把 top-1/top-3 当作人的能力或习惯分。即使这些数值不是心理量表，也不应
借 D22 的字面范围为产品评分开口子。

产品若最终显示一次 next-app 建议，只显示可纠正的暂定建议和直接证据计数，例如：

> 可能接下来会用 `{候选}`。在本机可核对的记录里，使用 `{当前项}` 后有 `{整数}` 次
> 接着使用了它。

整数事件数是可核对证据，不是归一化评分、概率或百分位。UI 同时提供“这次不对”和
“不再提示此类建议”等纠正入口。低支持时使用不带数字刻度的中性说明
“可核对记录还不够，暂不提示”，或直接静默；不得用低置信分、人格推断或负面标签替代
弃权。

发布门只在工程报告中写“协议通过/未通过”。产品界面不报告模型质量，也不把内部评测
行写入用户档案。这样既保留可证伪的内部数值评测，又不产生 D22 禁止的用户可见分数或
百分位。
