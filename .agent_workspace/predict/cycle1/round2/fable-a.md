## 裁决一：Hawkes/P4 —— 先拆名，再分轨；参数化 Hawkes 在 v0.2 结构性无缘默认

### 1.1 「P4/Hawkes」这个标签下混着两个不同的对象，必须先拆开

R1 综合表里一行「P4 整数环缓冲 Hawkes」掩盖了一个事实：round1 里被叫作 Hawkes 的东西有两个，性质完全不同。

| 代号 | 出处 | 实质 | 参数 | 可数性 |
|---|---|---|---|---|
| **P4-gate**（整数突发门） | opus-b `p4.hawkes_burst_int.v1` | 24h 环形整数桶 + 右移量化衰减的**加权窗口计数**。α=1、半衰期是常量，**没有任何拟合**。它不预测开哪个 app，只输出 hot/warm/cold 供打扰门用 | 0 个拟合参数（半衰期是登记常量） | 展示句是纯计数（「过去一小时 9 次，上一小时 6 次」），排序规则一句话讲得完 |
| **P4-fit**（参数化 Hawkes） | fable-a R1 S6、gpt-sol-b "regularized local Hawkes" | 连续时间点过程，MLE 拟合 μ/α/β，Ogata/时间重标验残差 | 每 app ≤3 个拟合系数 | 强度函数**不可数**；系数不是频次，用户无法核对 |

把两者继续叫同一个 P4，Round 3 的测试就会把 P4-gate 的通过当成 P4-fit 的通行证。**收紧第一刀：R2 综合表把 P4 拆成 P4-gate 与 P4-fit 两行。**

### 1.2 P4-fit：v0.2 对照专用（comparator-only），且这是结构性的，不是准确率问题

即使 P4-fit 日后在时间指标上全胜，v0.2 它也当不了默认，理由有四条，每条都挂在锁上而不是挂在数据上：

1. **无合法渲染面**（opus-a G10 + D22）：拟合强度的自然输出是校准概率/连续标量，而 `Band` 故意无 `Ord`、禁分数百分位。P4-fit 在 UI 上唯一合法的句子是把强度重新折算回经验计数——那句话**不用拟合也能算出来**。也就是说：进 UI 的信息量与纯计数版相同，拟合只贡献了一个用户看不见的排序器。
2. **「展示与依据脱节」质疑成立**（回答我 R1 遗留问题 #4）：展示层是经验频率、排序层是隐藏系数，用户纠正的是句子、模型变的是系数，因果链断开，违反可纠正精神。**P4-gate 不触发此问题**：它的排序规则（窗口计数 + 一小时折半）本身就是那句展示句。裁决线画在这里——**排序器可以不是展示句，但排序规则必须能被展示句完整陈述**。P4-gate 过线，P4-fit 不过。
3. **缺失非随机毒害 MLE**（opus-a G3）：同意撤销/锁屏/`sessions_discarded` 不落库，等于观测窗被用户行为系统性删失而删失标记不存在。点过程 MLE 把「没事件」当「强度低」，拟合出的 μ 会朝采集器在线时间偏，而不是朝人的行为偏。计数展示在同样的缺失下只是「少数几次」，退化是温和且可解释的；拟合强度的退化是静默错误。
4. **遗忘不变式 F**：删单条事件后 MLE 系数不满足「减一等于重放」，只能整段重拟合。可做但贵，且「重拟合后系数漂移多少算干净」没有可测判据。P4-gate 逐桶减一即精确回退。

**处置**：P4-fit 保留为**离线对照工具**——不落库、不进 UI、不进产品 crate，唯一职责是给「何时」类预测标定天花板。其存亡判据沿用 R1 双引：held-out 时间 NLL/MAE 打不过经验 TTU CDF（gpt-sol-b）与 P3 非齐次 Poisson（fable-a S6「打不赢 S5 即整体淘汰」）即整体墓碑；打得过也只证明「时间维还有肉」，届时（≥v0.3）再议是否值得为它设计合法渲染，v0.2 内**不存在提升为默认的路径**。

### 1.3 P4-gate：有条件默认资格，但只作**静默打扰门**，不作用户可见预测

P4-gate 与 P4-fit 不同，它的可数性与遗忘都干净，问题只剩两个：信号是不是真的、越界风险最高（emotional_steadiness 亲和）。裁决：

- **角色收窄**：默认轨里 P4-gate 只允许作为内部打扰门（决定 P5/P8 的提醒此刻发不发），**默认不渲染任何 burst 字样的用户可见 token**。门是控制流不是断言，可数性门槛可以由「规则可陈述」满足；一旦要对用户说「你现在很活跃」，就回到断言面，须重新过全部禁词与轴亲和审查。opus-b 已定的三条硬规定（永不进 emotional_steadiness 证据链、连 proposal 都不许、禁词表）原样继承，不放松。
- **默认资格的前置条件**（两条都过才配默认，测在 REAL 夹具上）：
  - F4-1：hot 态 15 分钟复发率 ≥ cold 态 2 倍，bootstrap 置信区间不重叠;
  - F4-2：日内随机重排后区分度塌到基线。**F4-2 不过等于它读到的是日节律**——那是 P3 已有的信号，P4-gate 直接删除，打扰门改由 P3 桶支持度承担。
- **半衰期纪律**：{30min, 1h, 4h} 三档全跑、登记最优档与登记时间，禁止事后倒填（继承 opus-b 未决 #1，作为默认资格的程序性前提）。

### 1.4 修正 R1 综合表的一处判据错位

R1 综合写「P4 …… 须打过 P0/P1 才配做默认」。**这是量纲错误**：P0/P1 预测「开哪个」（hit@k），P4 预测「何时/是否突发」（复发率、时间 NLL）。让 P4 跟 P0/P1 比 hit@k 既打不了也不该打。正确的杀线按角色分列：

| 对象 | 角色 | 正确的杀线 |
|---|---|---|
| P4-gate | 打扰门 | F4-1 + F4-2；外加下游效用：接门后「不当时机的提醒」显著下降且提醒总量基本不减（与 opus-b F8-3 同型，具体数值 Round 3 与 P8 一起钉，避免两个门各立一套口径） |
| P4-fit | 时间维对照 | 时间 NLL/MAE 对经验 TTU CDF 与 P3-Poisson；时间重标 KS 残差 |

**一句话结论（问题一）**：Hawkes 作为「拟合的点过程」在 v0.2 是 comparator-only 且结构性无缘默认；综合表里那行 P4 真正有默认资格的部分是一个**不含拟合的整数窗口计数门**，它可以默认，但仅以静默门的身份、在 F4-1/F4-2 双过之后。「Hawkes 是否默认」这个问法本身应该从议程上消失。

## 裁决二：APPM-lite × P2 —— 候选保持分立，底座立即合并，「合并」由测试结果执行而不是现在拍板

### 2.1 两者的真实关系：P2 是 APPM-lite 的一个退化配置

- P2（opus-b `p2.ngram2_backoff.v1`）：定长二阶 + 整数阈值阶梯回退（8/5），与 P1 共享转移表，全整数。
- APPM-lite（gpt-sol-b）：有界变阶（≤3），逐阶支持计数，**按各阶历史命中率加权选阶**（这是 Parate et al. APPM 区别于普通 backoff 的真正机制），可选旧计数折扣。

机械上 P2 ≡ APPM-lite 限定 max_order=2、选阶策略=固定阈值、无折扣。既然如此，为什么不直接合并成一个候选？因为**合并会同时毁掉归因与纪律**：

1. **归因**：共享证伪协议要求每个候选的宣称优势有专属夹具。APPM-lite 对 P2 的增量其实是两个正交的 Δ，合并后赢了不知道赢在哪：
   - **Δ1 更长上下文**（阶 2→3）：由「同终点不同路径」高阶歧义夹具检验;
   - **Δ2 自适应选阶**（固定阈值→按各阶历史命中率选阶）：由「不同前缀下最优阶不同」的混合源夹具检验。
2. **纪律**：APPM 原味的命中率加权插值是浮点混合，撞 opus-b §0.3/0.4（禁浮点权重）。但要**诚实记录**：Δ2 可以完全整数化——每阶维护 `hits/attempts` 两个整数计数器，选阶用交叉相乘比较（`h₁·a₂ > h₂·a₁`），与 P5 的频控同法，无除法无浮点。所以浮点不是否决 APPM-lite 的理由，只是否决「原味插值」的理由。Δ3（乘性折扣/老化）则真的与不变式 F 冲突，唯一已获批的时效机制是 P4-gate 那种窗口整数计数；**Δ3 在 v0.2 默认轨停用**，如要近因性，走窗口计数版另立具名变体，本轮不展开。
3. **命名诚实**（沿 gpt-sol-b 对 ATPP 的同款告诫）：整数化 + 去插值之后的东西不该再叫 APPM——测试报告里叫「整数化变阶 backoff（APPM-inspired）」，防止拿论文名给改装机制背书。

### 2.2 裁决：三层处置

1. **底座现在就合并**：P0/P1/P2/APPM-lite 共用一棵后缀计数 trie（阶 0–3，继承 `TOPK_APPS`/`TOPK_ROW` 上限），四者只是同一数据结构上的不同**查询策略**。这使状态量对比诚实（不重复存表）、实现面只有一份、不变式 F 只需证一次。
2. **候选保持分立**：默认轨候选仍是 P2（不动）；APPM-lite 拆成两个具名对照变体挂在对照轨：
   - `p2x.order3_ladder`：阶 3 + P2 同款固定阈值阶梯（只测 Δ1）;
   - `p2x.adaptive_order`：阶 ≤2 + 整数 hits/attempts 选阶（只测 Δ2）。
3. **合并由结果执行（merge-by-outcome）**，Cycle 末按下表收编，保证**默认轨在任何结局下只有一个 n-gram 类幸存者**——绝不并排跑两个会对同一时刻给出两句不同解释的预测器（同屏一致性，沿 T4D「永不同屏矛盾」纪律）：

| 测试结局 | 处置 |
|---|---|
| 仅 Δ1 赢 | P2 升阶为 3（阈值阶梯不变），`p2x.*` 退场 |
| 仅 Δ2 赢 | P2 的固定阈值换成整数自适应选阶（记 `p2.ngram_adaptive.v2`），阶仍 ≤2 |
| Δ1、Δ2 各自独立赢 | 两项都收编入 P2 v2；「APPM-lite」标签寿终 |
| 都不赢 | 墓碑两个 `p2x.*`，P2 原样保留 |

### 2.3 杀线数值（与 R1 已登记数字对齐，不另起炉灶）

- Δ1/Δ2 各自的「赢」= 对 P2 的 prequential hit@3 提升 **≥ 2 点**（沿 fable-a R1 S4 的 2 点线；P2 对 P1 的 3 点线不变），且在 REAL 夹具上不输、仅在合成歧义夹具上赢不算数。
- 状态预算：`p2x.order3_ladder` 的表项数 ≤ P2 的 **8 倍**（平行于 P2≤8×P1 的既有约束；实际约束力来自行内 TOPK 截断，此数是防爆炸的外圈护栏）。
- 冷启动照妖镜：`order_used` 分布必须登记；若 REAL 夹具上三阶被选中的查询占比 < **5%**，则 Δ1 即使命中率过线也判「死重」，不收编（为 <5% 的查询背 8 倍状态不值，且加长的 warm-up 会恶化 gpt-sol-b 要求登记的首条预测前热身事件数）。
- `p2x.adaptive_order` 的选阶计数器本身进可数解释面：「二阶最近 40 次预测中 28 中、一阶 90 次中 41 中，故本条用二阶」——这句话每个数都能手数，比固定阈值 8/5 的「为什么是 8」更可辩护。若 Round 3 实测这句话被评审判为过长/不可渲染，则 Δ2 只作内部选阶、展示句退回被选中那一阶的原始计数（与 P7 的「解释来自被选中的源」同法）。

**一句话结论（问题二）**：不合并候选、立即合并底座；APPM-lite 拆成 Δ1（升阶）与 Δ2（自适应选阶）两个可单独证伪的变体挂对照轨，按 merge-by-outcome 表在 Cycle 末收编或墓碑；乘性折扣（Δ3）v0.2 默认轨停用。
