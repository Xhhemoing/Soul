### 1.3 授权目录写入口

核心侧（`shell.rs`）：

- `authorize_root(&mut Config, requested) -> Result<PathBuf, RootRefused>`：trim → 空拒 → `metadata`（不存在 / 读不到分开）→ 必须是目录 → `canonicalize` → 与已有根去重 → push。**规范化在比较之前**。
- `authorized_roots(&Config) -> Vec<String>`：只读入口（选了「新命令返回列表」这一种，快照仍只带计数）。
- `RootRefused { reason: RootRefusedReason, message: String }`，`#[error("{message}")]`。理由码 `empty` / `not_found` / `not_a_directory` / `unreadable` / `already_authorized`。句子跟着码一起过 IPC，界面不许自己编——`[object Object]` 与「无效路径」两种退化都被堵住。
- `Session { Mutex<SessionState{ config, keys }> }`：`snapshot` / `cloud_toggle` / `complete_wizard` / `authorize_root` / `authorized_roots` / `opened_store_with` / `key_protection`。一把锁盖住配置与密钥事实（两把锁 = 计数与密钥说明描述两个不同时刻）。锁中毒时 `into_inner()` 继续读：锁后面是配置，不是半写坏的不变量。
- `complete_wizard` 拆出 `wizard_config(answers)`，自由函数与 `Session::complete_wizard` 共用同一套拒绝；后者**采纳**返回值（向导承诺「现在什么都没开」，session 若留着旧配置，返回的快照就是在描述不存在的东西）。
- 无参 `config_snapshot()` 保留为「默认关闭快照」，IPC **不再用它**。

壳侧：

- `SessionConfig(pub Session)`；五条命令全部 `session.0.xxx(...)` 一条语句，`the_command_layer_stays_thin` 继续绿。
- `COMMAND_NAMES` / `generate_handler!` / `core.ts COMMANDS` 三处同步加 `authorize_root`、`authorized_roots`；四条 `command_surface.rs` 断言 + `contract.test.ts` 的命令名比对全绿。
- `core.ts` 加 `authorizeRoot(path)`、`authorizedRoots()`、`RootRefused` 类型与 `refusalText(error)`（只取核心写好的 `message`，不做翻译表）。

设置页（`Settings.tsx`）：文本输入 + 按钮，**不加 dialog/fs 插件**，路径原样送出；显示核心给的密钥句子、已授权路径清单、计数徽章（来自核心返回的快照，不是本地数组长度）、以及「本次会话有效，尚无持久化：关掉 Soul 之后这份清单就没了……把它记到哪个文件里是 WP13 的事」。页面改为受控：授权成功后把核心返回的新快照交回 `App`，避免概览页继续显示 0。

## 4. 取舍与已知缺口

| 项 | 说明 |
|---|---|
| 库句柄目前无人消费 | `Arc<Mutex<SqlCipherStore>>` 已 `manage`，但本轮不接任何触库命令（功能视图是 P1）。因此 S-01.2 的运行期「跨命令共享同一句柄」还没有可测面；先落地的是「只开一次」的源码级事实与 session 跨命令可见的运行期事实 |
| 授权不持久化 | 关掉进程清零。UI 逐字写明，`Config::load/save` 归 WP13，本包不做（也没给 `complete_wizard` 加写盘副作用） |
| `KeyProtection::PlatformKeyStore` 无代码路径可达 | 与 `CloudState` 的做法不同：这里保留了一个今天走不到的变体，因为 DPAPI 是「未实现」而不是「产品决定不做」，留着它才让回退看起来是回退。可达性由 `open_store_for_session` 的分支决定，UI 与配置都改不动它 |
| Windows 真机未验 | `app_local_data_dir()` 解析出 `%LOCALAPPDATA%\Soul`、DPAPI 在真 Windows 上仍返回 `Unsupported`、托盘与窗口行为——都只在 Linux mock runtime 与 CI 上跑过。照 WP09 先例列入作者手动清单，交 ST-04 汇总 |
| 库打不开就起不来 | `install_store` 的错误从 `setup` 抛出，应用不会静默地在没有库的情况下运行。这是有意的：无声降级会让「数据存哪了」变成用户要自己猜的问题 |
| 授权错误信息回显用户输入的路径 | 允许：那是用户自己刚敲进去的字符串。WP11 拒绝扫描时的错误信息**不得**复读被拒路径，那条约束在 WP11 侧，不在这里 |
