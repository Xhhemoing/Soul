# KEEP_OR_KILL — T0 与 A0 独立裁决（Round 1 / fable-b）

## T0（Count + Reciprocity + Span）：**KEEP-with-patch**

**保什么**：三档分类学 + 互惠闩 + 跨期门槛这个骨架。它确定性、无时钟、整数可复核、与 Granovetter 的「时间投入 + 互惠」直接对应；「单日 20 条不能 Strong」是正确的产品判断，应当保留并补上测试。rebuild 的幂等结构、evidence 可解引用、local_only 全覆盖也都合格。

**必须打的补丁**（不打则该裁决降为 REPLACE）：

1. venue 分列 + 群聊封顶（DEFECTS P0-2 / INNOVATION #1）——不打这个补丁，T0 在任何有活跃群聊的真实账号上输出的是群成员表，不是关系强度图；
2. 图侧纠正/锁定 + rebuild 尊重 user_verdict（P0-1）——这不是算法参数，是产品锁承诺；
3. 休眠降档（P1-2）与互惠每侧下限（P1-3）；
4. 管道前提：导入去重（P1-4）、时间戳归一化（P1-6）、单向 DM 对端登记（P1-5）。

**为什么不 REPLACE**：

- 对 T1（指数衰减）：衰减和 φ 值用户无法用「数消息」复核，C3 直接掉到 1；其真实收益（旧关系降权）被休眠封顶以阶跃形式拿走，且封顶能用一句中文说清。
- 对 T2（RFM 三分位）：分位数依赖全图分布——同一个人的档位会因为**别人**的数据变化而变，解释性灾难（「你们降档是因为我认识了新朋友」），且分布敏感、测试易碎。
- 对 T3（Granovetter-span）：T3 不是替代品，是 T0 + 补丁 1/3 的名字。打完补丁的 T0 就是 T3。裁决等价于「以 T0 的代码骨架实现 T3 的语义」。

**如果补丁被否**：则 REPLACE 为 T3 重写，因为未打补丁的 T0 在 C1（互动强度失真）与 C3（计数不可复核）上双双不及格，留着它比没有图更有害——错误的 Strong 会喂给 WP10 摘要和未来的起草语气。

## A0（Questionnaire + Correction Lock）：**KEEP-with-patch**

**保什么**：几乎全部。纠正 = Strong + 锁、推断存而不用、无证据不落库的两层拒绝、原子失败、evidence 溯源到具体题目——这组语义正是产品锁「可纠正、可解释、非临床」的正确实现，且测试质量是全仓最高。问卷 Moderate < 纠正 Strong 的排序有据且应保留。v0.1 不做正文行为推断是**特性**：锁机制先行、生产者后置的顺序是对的。

**必须打的补丁**：

1. `intake` 重跑绕锁（DEFECTS P1-1）——一个 `axis_is_locked` 检查加一个测试，这是 A0 唯一的真实缺陷；
2. 两套问卷合并（P2-5）——否则 A0 的问卷半边可能在真实向导流程里根本不执行，AC-03 被 voice 文本空转满足；
3. 建议但不强制：A1 band 推导规则（INNOVATION #5）、解锁路径（P2-4）、锁拒用的审计 ReasonCode（P2-3）。

**为什么不 REPLACE**：

- 对 A1：不是竞争者，是 A0 的 band 计算插件；采纳后 A0+A1 合并为一个候选。
- 对 A2（统计人事摘要）：不同层的东西——A2 说的是「关于别人」的计数，A0 说的是「关于你」的轴；WP10 的 `analysis.rs` 已经是 A2 的雏形且质量不差，两者共存不竞争。
- 对 A3（词典推断）：维持否决。需要正文、临床化、不可解释三连，打不过 A0+A1 的任何一维。

**最终形态建议**（供「只留 1–2 个」的收敛）：一个人脉算法 = **T0+补丁**（即 T3 语义），一个档案算法 = **A0+P1-1 补丁（+A1 可选）**。两者共享三档词汇，但必须按 DEFECTS P1-7 把「tie 的档 = 断言」与「轴的档 = 把握」在文档与 UI 措辞上钉开。
