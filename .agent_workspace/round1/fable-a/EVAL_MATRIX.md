# Round 1 / fable-a — 评价矩阵：C1–C8 操作化 + 对抗夹具

本文件把 SHARED_BRIEF 的 C1–C8 变成可判定的 pass/fail 测试。所有夹具必须是合成数据、UTC 时间戳、固定 UUID，任何候选的判定不得读墙钟（衰减类候选的 `as_of` = 夹具内最大 `occurred_at`）。「候选」指 T0/T1/T2/T3/T3R（合成，见 CANDIDATE_SPEC）与 A0/A1/A2/A3。

## 一、C1–C8 操作化

每维打 1–5 分。下面给出每维的**判定程序**与**及格线**（<3 为不及格；任何一维出现「硬约束违规」直接否决，不进入加权）。

### C1 产品锁契合
- **判定**：候选输出能否直接填充 PRODUCT_LOCK 要求的四元组（互动强度/关系类型/最近接触/证据）与「可纠正」承诺。逐项勾选：band ∈ {weak,moderate,strong}？edge 带 evidence_ids？用户纠正后重算不覆盖（tie 侧对应「用户改写关系后 rebuild 不打回」，trait 侧对应 locked axis）？
- **Pass**：四项全勾。**Fail**：任一项需要新增产品概念（如 T2 需要引入"同侪排名"概念）。

### C2 可测性
- **判定**：(a) 本文件所有适用夹具均可写成确定性单测；(b) 同一夹具、不同墙钟时刻运行两次，输出逐字节一致（F15）；(c) 无浮点不稳定（分桶权重用 1/2/4/8 的有理数，禁用 `exp()` 浮点累加作判档依据——允许实现里用定点/分数）。
- **Pass**：三项全过。**Fail**：任何 flaky 或墙钟依赖。

### C3 可解释性
- **判定**：对每个可能的 band 输出，存在一句中文模板，其中出现的**每个数字都是用户可自行数出来的原始计数或日期**（次数、天数、日期、"按半计"的桶规则）。反例判定：解释中出现「有效分 12.37」「你在前 1/3」「相对其他联系人」即 fail。
- **Pass**:模板存在且数字可复核。**Fail**：需要小数、排名或人群参照。

### C4 隐私
- **判定**：候选的输入签名里**不含正文字段**（编译期可查：入参类型是 `InteractionRef`/`TieStrength`/计数，不是文本）；输出 JSON 序列化后经检查不含姓名、原始 conversation id（只允许 sha256）、正文子串（F11）。第三人输出恒 `local_only`。
- **Pass**：类型层面无正文可达 + F11 过。**Fail**：任何需要开封 `body_ref` 的候选（A3 直接 fail）。

### C5 稳健性
- **判定**：F01–F05、F08、F09、F12、F13、F14 组成的对抗组全过（每个夹具的期望见下表）。
- **Pass**：无一 fail。**Fail**：任何一个对抗夹具产出「常识上错误的档」——错误定义已在每个夹具里钉死，不留争辩空间。

### C6 计算成本
- **判定**：rebuild 复杂度 O(总交互数 + 联系人数)；F14（10 万交互/5 千联系人）在 CI 机器 debug 模式 < 10s，release < 1s；内存与联系人数线性。任何需要两两配对、全量排序分位数以外还要反复重扫的实现 fail。（T2 的一次性排序本身 O(n log n) 可接受，它死于 C2/C3，不死于 C6。）
- **Pass**：达标。**Fail**：超时或超线性内存。

### C7 SOTA 对齐
- **判定**：候选每条规则能指认一个 REPORT.md 里列出的具名理论（Granovetter/Marsden-Campbell/Hawkes-Burt 衰减/RFM/Dunbar 分层/互惠规范/三角验证），且没有「装作发明」的成分。
- **Pass**：逐规则可指认。**Fail**：存在无出处的魔法规则。

### C8 创新必要
- **判定**：仅适用于非基线候选（T1/T2/T3/T3R/A1）。必须存在**至少一个对抗夹具**，新候选给出正确档而基线（T0 或 A0）给出错误档；且不存在反向夹具（基线对、新候选错）。这是消融门：Round 2 用 opus-a/gpt-sol 的夹具跑通。
- **Pass**：净胜 ≥1 且零反向回归。**Fail**：与基线在全部夹具上同分（则按简单者留，即基线）。
