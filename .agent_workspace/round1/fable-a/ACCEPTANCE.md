# Round 1 / fable-a — 「保留 1 或 2 个算法」的验收定义（v0.1）

## 1. 「保留」到底指什么（防止验收时扯皮）

「保留 1 或 2 个算法」= 满足以下全部五条的终态：

1. **单一规范函数**：全仓库只存在一个 tie-band 判定函数（纯函数：观测汇总 → `SupportedBand`），`graph_build` 与 WP10 摘要都调用它。同理，trait/人事侧只存在一个规范聚合路径。禁止两处各写一套阈值。
2. **单源词汇表与阈值表**：weak/moderate/strong 的判定常量全部集中在 `docs/algorithms/` 的一张常量表 + `crates/soul-algo` 的一个模块。A2 的摘要**只消费** T 族胜者产出的 band，自己不定义 band——这是「一个人脉算法 + 一个档案/人事算法」不打架的结构保证。
3. **落选者有墓碑**：T0/T1/T2/T3/A1/A3 中未保留者写入 `docs/algorithms/REJECTED.md`，每条含：候选 ID、否决触发的具体夹具/判定（引用 EVAL_MATRIX 编号）、复活条件（如有）。「不采用」必须可追溯，不许静默消失。
4. **验收测试绿**：保留者通过 EVAL_MATRIX 全部适用夹具 + Goal 1 矩阵相关行（AC-06/AC-08/AC-16/AC-17）在参考实现上等价复现（Linux、无 Windows API、无网络）。
5. **中文解释话术随规范冻结**：每个保留算法的用户可见解释模板（CANDIDATE_SPEC 中的话术）进规范文档，作为验收断言的一部分（渲染输出必须能匹配模板结构且通过 `assert_non_clinical`）。

## 2. 推荐保留对（PROVISIONAL）

**人脉算法：T3R**（Granovetter 门闩 × 分桶半衰计数；H=90，CUTOFF=360，阈值 3/10/3，强档需私聊）
**档案/人事算法：A2**（统计式人事摘要，goal1 分支在位实现，band 纯消费者）

配对理由：

- **数据流是单向的**：T3R 产出 `TieStrength`（含 band 与全部原始计数），A2 把它渲染成带证据的中文句子。A2 不含第二套阈值，所以这一对在结构上**不可能**打架——它们不是两个平级判定器，是「判定器 + 渲染器带证据闭环」。
- **覆盖产品锁的两个门禁面**：T3R 直接满足人脉图 v0（AC-08：边有证据、强度可解释），A2 直接满足人事分析统计降级（AC-16/AC-17：每句有证据、无诊断词、无 key 可跑）。
- **A0 的地位**：问卷 + 纠正锁不参与「1 或 2」的名额竞争。它是产品锁 v0.1 切片第 3/4 条的直接要求（问卷回退、纠正锁定、语气立即改变），属于**产品政策基底**而非可淘汰算法——把它当候选淘汰在产品锁下根本不合法。A1 若过 F16/F16b 生死线，作为 A0 内部的升档规则并入（不占名额）；过不了就归档。
- **对 SHARED_BRIEF「预期形态」的符合**：正是「一个人脉算法 + 一个档案/人事算法」。

## 3. 单算法回退（若配对打架）

「打架」的可判定形式只有一种（因为 A2 无独立阈值，唯一可能的冲突面是词汇表语义）：**A2 渲染出的档位句与图 UI 展示的档位在同一时刻不一致**（例如 rebuild 时序导致摘要引用旧 band，或有人给 A2 私加阈值）。

回退方案：**只保留 T3R 一个算法**，并把 A2 降级为「T3R 输出的视图」——摘要函数改为接收 `TieStrength` 快照并在同一事务内渲染，删除其一切独立判断（方向比阈值 2:1、沉寂 180 天句这两个渲染参数保留，因为它们不产生 band，只产生描述句）。此时 v0.1 的「保留 1 个算法」= T3R，AC-16/17 仍然满足（摘要仍每句带证据、仍无诊断词、仍无 key 可跑），只是它在算法清点上不再计为独立算法。

若 T3R 自身被 C8 消融杀掉（衰减无净胜），回退链为：**T3 + A2**（次优对）→ 仍打架则 **T3 单体**。任何情况下不回退到 T0：F03（群聊重度判强）是 T0 的常识性错档，已有净胜证据。

## 5. 明确不验收的东西（防镀金）

- 不验收任何「预测准确率」类指标——v0.1 没有 ground truth 关系标签，声称准确率就是伪造效度。验收的是**约束满足 + 对抗夹具行为正确**。
- 不验收 Hawkes 参数拟合、社区发现、中心性等图论装饰——超出产品锁需要。
- 不验收 A3 的任何「改良版」——正文推断在 v0.1 是宪法问题，不是调参问题。
